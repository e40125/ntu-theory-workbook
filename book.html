Chapter 0 — Know what kind of thing you are talking about · chap0.pdf, pages 1–15

The whole idea

This deck gives us the grammar for talking precisely about computers. Before proving anything, ask: what objects are involved, and what exactly am I claiming about them? A bunch of notation becomes much less cursed once every symbol has a job. Pages 1–9 introduce objects and logic; pages 10–15 show how definitions become reasons in a proof.

Build the objects from scratch

A set is a collection where membership matters. {0,1} and {1,0,1} name the same set. A sequence preserves order and repetitions: 01 differs from 10, and 11 differs from 1. A tuple is a fixed-length sequence of entries. A machine's five-tuple is therefore a record with five different fields, not five arbitrary decorations.

A function gives exactly one output for every allowed input. Its output may itself be a set. That is how an NFA transition can be a perfectly valid function even though the machine has several possible next states. A relation records which pairs satisfy a condition; it need not select a single partner.

The Cartesian product lists ordered choices from two sets. If A={1,2} and B={x,y}, then A×B contains (1,x), (1,y), (2,x), (2,y). Later, “state × symbol” simply means “give me those two pieces of information together.”

Watch a definition do useful work

Pages 3–4 use “same remainder modulo 7.” Two integers are related when their difference is a multiple of 7. Why is this an equivalence relation—a way of grouping genuinely interchangeable cases?

An integer differs from itself by zero, so it relates to itself (reflexive). If i−j=7a, then j−i=7(−a), so reversing the pair preserves the relation (symmetric). If i−j=7a and j−k=7b, adding gives i−k=7(a+b), so the relationship passes through the middle number (transitive). Each fancy word has just become a checkable property.

How a proof grows out of the picture

Page 11 asks why an undirected graph's total degree is even. A vertex is a node; an edge joins endpoints; a vertex's degree counts incident edge-ends. Look at one edge. It contributes one end at each endpoint, so two contributions overall. Repeat that accounting for every edge: total degree = twice the number of edges. Twice an integer is even. Done. We counted a generic contribution, so the argument covers every finite graph, not just the drawn example. A self-loop, if allowed, contributes two to its vertex's degree.

An implication “P implies Q” says there cannot be a case with P true and Q false. It does not say Q happens only because of P. “Rain implies wet ground” allows wet ground from a sprinkler. To disprove a universal implication, find one case satisfying P but violating Q.

Source wording to separate: page 10 writes the contrapositive ¬Q→¬P under a contradiction heading. Contraposition proves that equivalent implication. Contradiction assumes the original claim fails and derives an impossibility. Pages 13–15 use contradiction: write √2=m/n in lowest terms; its square forces m even, then n even, contradicting lowest terms. Those methods are related but their opening assumptions differ.

Symbols, strings, and languages

An alphabet, written Σ\SigmaΣ (“sigma”), is the finite set of symbols inputs may use. For Σ={0,1}\Sigma=\{0,1\}Σ={0,1}, the symbols are 0 and 1. A string is a finite ordered sequence of these symbols: 101 is one string. Its length is ∣101∣=3|101|=3∣101∣=3. The bars mean length, not membership or absolute value here.

A language is a set of strings. In E={1}E=\{1\}E={1}, the language has exactly one member: the one-symbol string 1. So 1 belongs; 11 does not. The letter E is just the name someone picked. Rename it A and the language stays the same. Braces collect members; they do not mean “repeat.”

2. What a machine remembers

First, build the mental model

DFA 2 — Compress the past without losing the decision · chap1_DFA2.pdf, pages 1–14

The whole idea

The design question is: which differences between input histories can safely be forgotten? If two histories require the same behavior for every possible continuation, one state may represent both. If some continuation must distinguish them, merging them loses information. This is the reason to design state meanings before drawing arrows.

Build the picture from the slide examples

Pages 1–4 recognize nonempty strings whose first and last symbols agree. You need the first symbol permanently, and you update the current last symbol. A separate initial situation handles “nothing read yet.” One symbol such as a already has matching first and last symbols; the empty string needs its own decision.

Pages 6–8 keep the sum since the last reset, modulo 3. Modulo 3 means the remainder after division by 3: 0, 1 or 2. You can throw away the actual sum because adding the next digit affects the final remainder using only the current remainder. A reset overwrites the summary with remainder zero. This is deliberate forgetting, not random loss of memory.

One complete construction: odd many ones

Pages 11–13 ask for binary strings with an odd number of 1s. “Odd” means 1,3,5,…; “even” means 0,2,4,…. You do not need to distinguish one 1 from a thousand and one. Both require the same future toggles.

Let qₑ mean “even many ones so far,” and qₒ mean “odd many.” Start qₑ because the initial count is zero. Accept at qₒ. Reading 0 changes no count, so each state loops on 0. Reading 1 changes parity, so it switches states.

For 010101, the summaries after each symbol are even, odd, odd, even, even, odd. Accept. If you append another 1, the answer flips. That is exactly what the rule demands.

The formal computation page is a run log

On page 9, w=w₁…wₙ names the input symbols. The r₀,…,rₙ names the visited states. w entries are what we read; r entries are what we remember afterward. There are n symbols but n+1 recorded states because r₀ records the situation before reading anything.

r₀=q₀ says start correctly. δ(rᵢ,wᵢ₊₁)=rᵢ₊₁ says each adjacent row follows the update rule. rₙ∈F says the final recorded state belongs to the accepting set. “∈” means membership. It is an acceptance test, not a claim that every run must accept.

A language is regular if some finite automaton recognizes exactly its strings. That is an existence claim about a checker. A language does not become regular because its English description sounds simple.

Why this method generalizes

The odd/even invariant holds at the start and survives each symbol. That gives a proof for arbitrarily long inputs. The “contains 001” machine on page 14 uses another summary: how much of the useful suffix 001 has been matched, or whether it was already found. After 000, the useful suffix is still 00; an extra zero should not erase both zeros from memory.

The reset, parity and substring examples share one mental move: keep exactly the information needed for later decisions. Their arrows differ because their meanings differ.

NFA: several possible runs

An NFA transition returns a set of possible next states. Its type is δ:Q×Σε→P(Q)\delta:Q\times\Sigma_\varepsilon\to\mathcal P(Q)δ:Q×Σε​→P(Q). Acceptance means at least one run reads the whole input and finishes accepting, with ε moves allowed. A dead branch doesn't kill the other branches. An ε arrow is optional; it does not force the machine to ignore a symbol arrow.

The pumping argument asks what must happen when finitely many states face a sufficiently long input. Machine conversion asks how another representation can preserve the same decisions. A proof is a chain of reasons that covers every case claimed. Examples help you discover an argument. They don't magically turn a claim about infinitely many inputs into something settled.

Start with the target, not fancy wording

Suppose the claim is: “If a DFA reaches the same state after strings u and v, then appending the same suffix z produces the same acceptance decision.”

What are you given? A deterministic machine, two runs ending at the same state, and one common remaining input z. What must you show? The final acceptance decisions agree. We don't need to remember the earlier strings; the current state plus the next symbol determines the next move.

Complete proof: Let q be the state reached after both u and v. The two remaining computations start at q and read the same string z. At each step, their current states and next input symbols are equal, so determinism gives equal next states. Hence their final states are equal. Since acceptance depends on whether that final state is in F, the decisions agree.

This is the engine behind the pumping lemma. Once you're back in the same state, the machine has no secret counter remembering how many laps you took. The circle is the memory. That's it.

Make the repeated-step reasoning explicit: induction

Induction proves a claim for every nonnegative integer by covering a starting case and a repeatable step. Think of a rule that lets you extend a correct run by one more symbol.

Claim: after k symbols of the common suffix above, the two machines are in the same state.

  • Base, k=0: neither suffix symbol has been read. Both states are q by assumption.
  • Induction hypothesis: assume the states agree after k symbols.
  • Step: if another symbol exists, both next symbols are the same symbol a. Apply δ to the same pair (state,a); the resulting states agree after k+1 symbols.
  • Conclusion: the states agree after all |z| symbols, including when |z|=0.

The hypothesis is a temporary assumption used to prove the next case. It is not permission to assume the final claim with no work. This pattern also proves a machine invariant: describe exactly what each state or stack represents after any processed prefix, verify the start, then verify every possible update.

Equality needs two directions

To prove a grammar generates exactly L, show:

  1. Soundness: every string the grammar generates is in L. No extra garbage gets through.
  2. Completeness: every string in L has a derivation. No valid input is excluded.

Worked example: S→0S1∣εS\to0S1\mid\varepsilonS→0S1∣ε generates exactly {0n1n∣n≥0}\{0^n1^n\mid n\geq0\}{0n1n∣n≥0}.

Soundness: A terminating derivation uses the wrapping rule some k≥0 times and then S→ε. Each wrap adds one 0 on the left and one 1 on the right, so the result is 0ᵏ1ᵏ.

Completeness: Take any 0ⁿ1ⁿ with n≥0. Apply S→0S1 exactly n times, then S→ε. This derives the chosen string. The two inclusions prove equality.

Contradiction and counterexamples

To prove L is not regular, assume it is regular and show this forces a statement incompatible with that assumption. You must name the contradiction. “This is impossible” is not a reason by itself.

To disprove “every binary string with equal counts is zeros-then-ones,” one counterexample suffices: 0101 has equal counts but is not in block order. You do not need to show that all equal-count strings fail. Which side says “every” matters.

∀\forall∀ means “for every”; ∃\exists∃ means “there exists.” Negating “every input is accepted” gives “some input is not accepted.” Negating “some input is accepted” gives “every input is not accepted.” Swap the quantifier and negate its claim. For P⇒QP\Rightarrow QP⇒Q, only P true and Q false is a counterexample.

How to discover a proof

Write the assumption and desired conclusion in ordinary English. Expand the relevant definition. Look at a tiny example to find what stays true. Then replace its particular numbers with arbitrary variables and justify the general step. Finally attack your own proof with boundary cases: zero, empty string, smallest permitted length, and a condition changed by one.

A construction proof supplies the required object and checks it. For example, to show every integer t between n and 2n is a sum of n numbers each 1 or 2: choose t−n copies of 2 and 2n−t copies of 1. The counts are nonnegative, sum to n, and their weighted sum is 2(t−n)+(2n−t)=t. Saying “clearly every value is possible” would skip exactly the part to prove.

4. Why finite memory forces a loop

First, build the mental model

Pumping lemma: finite memory eventually repeats itself · chap1_pumpinglemma1.pdf, pages 1–9

The question: when is a finite number of states not enough?

A DFA can remember parity with two states. Could it remember the exact number of leading zeros so it can demand that many ones afterward? For {0n1n:n≥0}\{0^n1^n:n\ge0\}{0n1n:n≥0}, the number may be arbitrarily large. “It needs to count” is a useful suspicion, but not yet a proof: plenty of counting tasks only need a remainder. We need a consequence that every DFA must obey.

Suppose a DFA has p states. Read p symbols. The computation has visited p+1 state positions: the initial state plus one after each symbol. With only p different states, some state was visited twice. That's the pigeonhole principle: more visits than available distinct places forces a repeat.

A repeat turns a path into a reusable loop

Split the input into three consecutive pieces. x gets us to the repeated state the first time. y takes us around the loop back to that same state. z finishes the original accepting journey.

Because the state after y is exactly the state before y, the rest of the machine cannot tell whether we took that loop zero times, once, twice, or a hundred times. Following z afterward still reaches accept. The DFA has no secret memory outside its current state. That's the whole damn mechanism.

The notation xyizxy^izxyiz means x, then i copies of y, then z. With i=0, y disappears; with i=1, it is the original string; with i=2, y is duplicated. We are editing a substring, not moving letters around.

Decode the theorem in its actual order

If L is regular, there exists a pumping length p such that every s in L with length at least p can be split as s=xyz satisfying:

  1. ∣y∣>0|y|>0∣y∣>0: the loop consumes at least one symbol.
  2. ∣xy∣≤p|xy|\le p∣xy∣≤p: the loop fits within the first p symbols.
  3. xyiz∈Lxy^iz\in Lxyiz∈L for every integer i≥0: every repetition count still works.

∣y∣|y|∣y∣ is the number of symbols in y. ∈\in∈ means “is a member of.” The theorem promises at least one suitable split, not every split. p belongs to the assumed machine; we don't get to declare p=3 because that makes an example convenient.

Why this helps prove impossibility

To show a language is not regular, assume a DFA exists and receive its unknown p. Choose a legal long string. Then show that no allowed split can keep all repetitions in the language. That contradicts the required loop property.

Be careful with the deck's counting examples. Equal numbers of 0 and 1 is not the same requirement as equal numbers of adjacent 01 and 10. The latter can be tracked using boundary information: in a binary string, changes from 0 to 1 and back alternate. Similar-looking counts can need radically different memory.

Keep: pumping is a necessary consequence of finite state memory. It is a tool for ruling regularity out, not a general way to establish regularity. Next we turn the mechanism into a complete quantified proof.

Question: how do we prove that no DFA, however cleverly designed, can recognize a language? Showing that your own three-state attempt fails isn't enough. Some other design might work. We need a restriction shared by every finite-state machine.

Why a loop is unavoidable

Suppose a DFA has p states. Reading its first p symbols visits p+1 states when you include the start. There are more visits than available states, so two visits must be to the same state. This is the pigeonhole principle: p boxes cannot hold p+1 objects with at most one in each.

Split an accepted input into x, y, z. x gets to the repeated state; y goes around the loop and returns; z is the rest of the input leading to acceptance. The loop consumes at least one symbol because the two visits occur at different times. It finishes within the first p input symbols.

Take a concrete conditional example: 00 [0] 111. Suppose the bracketed 0 loops back to the same state. Doing that loop twice gives 00 [00] 111; doing it zero times gives 00 [] 111, or 00111. All three computations reach the same state before the final 111, so the same suffix leads to acceptance. Yet only 000111 has equal numbers of zeros and ones. This explains the mechanism. It does not claim every DFA has its loop at this exact position.

The theorem, translated before use

If A is regular, there exists an integer p≥1 such that every s in A with |s|≥p has a split s=xyz satisfying:

∣y∣>0,∣xy∣≤p,xyiz∈A for every integer i≥0.|y|>0,\qquad |xy|\leq p,\qquad xy^iz\in A\text{ for every integer }i\geq0.∣y∣>0,∣xy∣≤p,xyiz∈A for every integer i≥0.

  • p: the pumping length; the hypothetical machine supplies it.
  • s: one sufficiently long accepted string.
  • x: prefix before the loop; may be empty.
  • y: the nonempty loop's input.
  • z: suffix after the loop; may be empty.
  • i: number of copies of y. i=0 deletes y; i=1 leaves the input alone; i=2 duplicates y.

The condition is necessary for regularity. A failed attempt to break pumping does not prove a language regular. To prove regular, construct a DFA, NFA, regular expression, or use a valid closure argument.

A complete exam proof

Claim: A={0n1n∣n≥0}A=\{0^n1^n\mid n\geq0\}A={0n1n∣n≥0} is not regular.

The mental model: control the damage, don't memorize one string

Pumping proofs have a fixed negotiation. You assume regularity; the lemma supplies p; you choose a sufficiently long member s; the hypothetical machine gets a legal split; you choose a repetition count that makes membership fail. The order matters. You must beat every legal split of your chosen s, not just a convenient one.

Write the plan in ordinary words first: “The loop is trapped in this region. Changing that region destroys this relationship.” Then translate the relationship into counts, positions, or arithmetic.

Variation 1: a word repeated twice

Let L={ww:w∈{0,1}∗}L=\{ww:w\in\{0,1\}^*\}L={ww:w∈{0,1}∗}. Here w is any binary string, and ww means two identical copies, in the same order. Choose s=0p1 0p1s=0^p1\,0^p1s=0p10p1. This is a member: its two copies are both 0p10^p10p1.

For every legal split, the bound ∣xy∣≤p|xy|\le p∣xy∣≤p forces y=0ky=0^ky=0k with 1≤k≤p. Pump down to get 0p−k1 0p10^{p-k}1\,0^p10p−k10p1.

Why can't this be some different word repeated twice? Don't merely say “the original halves differ”—maybe the dividing point moved. There are exactly two 1s, and the whole string ends in 1. In a square tt, each identical half must therefore contain one 1 and end in 1. Each half is a block of zeros followed by one 1, with the same number of zeros. Our two zero blocks have lengths p−k and p, which differ. No alternate split can save it.

That extra argument closes a real proof gap. A drawing of two unequal old halves would not.

Variation 2: square lengths

Let L={1n2:n≥0}L=\{1^{n^2}:n\ge0\}L={1n2:n≥0}. A string belongs exactly when its length is 0,1,4,9,16,… . Choose s=1p2s=1^{p^2}s=1p2. Its length is at least p. Every legal nonempty y has length k with 1≤k≤p.

Pump up once, i=2. The new length is p²+k. It is bigger than p² but smaller than the next square:

p2<p2+k≤p2+p<(p+1)2=p2+2p+1.p^2<p^2+k\le p^2+p<(p+1)^2=p^2+2p+1.p2<p2+k≤p2+p<(p+1)2=p2+2p+1.

There is no square strictly between consecutive squares, so the pumped word is outside L. The argument works for every k in the allowed range. Pumping down is less convenient: for p=1 and k=1 it gives length zero, which is a square. Choosing i=2 avoids that boundary trap.

What the quantifiers are saying

∃\exists∃ means “there exists”; ∀\forall∀ means “for every.” The lemma says a regular language has some p that works for every long member, with some legal split working for every repetition count. To refute it, show that for every proposed p, you can find a bad member for which every legal split has some failing repetition count.

Negating the order correctly prevents the classic bullshit proof where you choose a bad split and act as though no good split exists.

6. Build strings with a grammar

First, build the mental model

CFGs: a variable is unfinished work, a terminal is finished output · chap2_CFG1.pdf, pages 1–12

Start with what a grammar is trying to do

A DFA checks a completed string. A grammar builds strings. We still care about a language—a set of completed strings—but now ask which ones the construction rules can produce. There is no input head and no accepting circle in a grammar.

The deck's grammar is:

A→0A1∣B,B→#.A\to0A1\mid B,\qquad B\to\#.A→0A1∣B,B→#.

A and B are variables: placeholders for unfinished work. 0, 1, and # are terminals: finished output symbols that stay put. A is the starting variable. The vertical bar means “or,” so A has two alternative rules. The arrow means “you may replace this variable with that right-hand side.”

Run the rules all the way to completion

Begin with A. Choose its wrapping rule three times, then finish:

A⇒0A1⇒00A11⇒000A111⇒000B111⇒000#111.A\Rightarrow0A1\Rightarrow00A11\Rightarrow000A111\Rightarrow000B111\Rightarrow000\#111.A⇒0A1⇒00A11⇒000A111⇒000B111⇒000#111.

At 00A11, the zeros and ones are already output. A is the one unfinished job between them. Applying A→0A1 replaces that A, leaving its surrounding output untouched. We didn't replace the entire line with 0A1.

Each wrapping adds one zero on the left and one one on the right. Switching to B stops the wrapping; B→# puts a separator in the middle. Therefore the generated language is {0n#1n:n≥0}\{0^n\#1^n:n\ge0\}{0n#1n:n≥0}. n is the number of wraps. With zero wraps, A→B→# gives #. ε is not generated: no rule finishes with no terminal at all.

Why this can do what a DFA cannot

The growing expression stores unfinished structure. Every additional wrap leaves one more 1 waiting on the right. A finite grammar can describe arbitrarily deep nesting because its rules can reuse a variable. The finite rulebook does not impose a fixed bound on the size of a derivation.

A parse tree records the same construction as a tree. A node labeled A has children 0, A, 1 when that rule is used. Read the terminal leaves left to right to recover the completed string. The tree preserves who created whom, which a final string alone does not show.

Decode the formal package

G=(V,Σ,R,S)G=(V,\Sigma,R,S)G=(V,Σ,R,S) names a grammar. V is its finite set of variables; Σ is its finite terminal alphabet; R is its finite rule set; S is the starting variable. In this example S—the formal slot name—is filled by the variable A. The actual start does not have to be called S.

uAv⇒uwvuAv\Rightarrow uwvuAv⇒uwv says a rule A→w can replace A wherever it appears, with the same surrounding strings u and v retained. “Context-free” means the rule does not inspect those surroundings before permitting replacement. ⇒∗\Rightarrow^*⇒∗ means zero or more derivation steps.

The last slide adds two different ways to grow structure

For S→aSb|SS|ε, interpret a as an opening parenthesis and b as a closing one. S→aSb wraps one balanced structure inside a matched pair. S→SS places two balanced structures side by side. S→ε finishes with nothing. For aabbab, one derivation is S⇒SS⇒aSbS⇒aaSbbS⇒aabbS⇒aabbaSb⇒aabbab. Each arrow replaces one S.

Equal counts alone are insufficient: ba has one of each but closes before anything opens. A balanced-parentheses string must have equal final counts and every prefix must contain at least as many openings as closings. Wrapping and concatenation preserve both conditions. Conversely, split a nonempty balanced string after the close matching its first opening: inside that pair and after it are smaller balanced strings, exactly the wrapping and side-by-side jobs. This connects grammar rules to nested structure, the reason stacks will be useful.

What a correctness proof has to establish

Every derivation here produces matching outer blocks because each wrap adds exactly one of each symbol and the only finishing option inserts #. Conversely, any desired n can be produced by choosing n wraps then finishing. This proves both “no wrong strings” and “every required string.” Merely deriving 000#111 proves only one example.

The question: who belongs together?

The characters in a+a×a do not visibly say which operation groups first. A grammar can encode that structure. In the deck's layered grammar,

E→E+T∣T,T→T×F∣F,F→(E)∣a,E\to E+T\mid T,\quad T\to T\times F\mid F,\quad F\to(E)\mid a,E→E+T∣T,T→T×F∣F,F→(E)∣a,

E means an expression built from terms, T a multiplication-level term, and F an atomic factor: a single a or a parenthesized expression. These names are helpful meanings assigned to variables; the rules do the enforcing.

Build the example and see why precedence emerges

A leftmost derivation always expands the leftmost remaining variable:

E⇒E+T⇒T+T⇒F+T⇒a+T⇒a+T×F⇒a+F×F⇒a+a×F⇒a+a×a.E\Rightarrow E+T\Rightarrow T+T\Rightarrow F+T\Rightarrow a+T\Rightarrow a+T\times F\Rightarrow a+F\times F\Rightarrow a+a\times F\Rightarrow a+a\times a.E⇒E+T⇒T+T⇒F+T⇒a+T⇒a+T×F⇒a+F×F⇒a+a×F⇒a+a×a.

The final top-level split is E+T. The multiplication lives inside the right T. A factor can contain a whole addition only by using F→(E), which prints parentheses. That's why (a+a)×a has a different structure and different visible parentheses. The grammar is not calculating a numerical answer; it determines the syntactic grouping first.

Ambiguity means two trees, not two scheduling choices

Now use the flatter grammar E→E+E∣E×E∣(E)∣aE\to E+E\mid E\times E\mid(E)\mid aE→E+E∣E×E∣(E)∣a. It can build a+a×a with the root operation +, or with the root operation ×. The root-+ tree groups a+(a×a); the root-× tree groups (a+a)×a, even though the generated string has no parentheses.

Two corresponding leftmost derivations are:

E⇒E+E⇒a+E⇒a+E×E⇒a+a×E⇒a+a×a,E\Rightarrow E+E\Rightarrow a+E\Rightarrow a+E\times E\Rightarrow a+a\times E\Rightarrow a+a\times a,E⇒E+E⇒a+E⇒a+E×E⇒a+a×E⇒a+a×a,

E⇒E×E⇒E+E×E⇒a+E×E⇒a+a×E⇒a+a×a.E\Rightarrow E\times E\Rightarrow E+E\times E\Rightarrow a+E\times E\Rightarrow a+a\times E\Rightarrow a+a\times a.E⇒E×E⇒E+E×E⇒a+E×E⇒a+a×E⇒a+a×a.

That is a complete ambiguity witness: same terminal string, different parse structures, certified here by different leftmost derivations. If you merely expand independent left and right children in a different order, you may still get the same tree. That's scheduling, not ambiguity.

A grammar can be ambiguous even if another grammar for the same language is unambiguous. An inherently ambiguous language is stronger: every CFG generating it is ambiguous. Keep the object straight—one rulebook versus the whole language.

Designing a grammar by splitting the job

For {0n1n}∪{1n0n}\{0^n1^n\}\cup\{1^n0^n\}{0n1n}∪{1n0n}, a new start chooses which subgrammar to run. One wraps zeros around ones; the other wraps ones around zeros. Union means either branch may generate the string; neither branch has to satisfy both descriptions.

A DFA can also become a grammar. Give each state qᵢ a variable Rᵢ. For an arrow qᵢ—a→qⱼ, add Rᵢ→aRⱼ. For each accepting state, add Rᵢ→ε, allowing generation to finish there. A derivation now writes exactly the labels of a successful machine path. This connects checking to building.

Ambiguity asks whether one finished string has two different grammatical structures. It does not ask whether two different strings can be generated. Of course a useful grammar usually generates lots of strings.

Why “two derivations” alone is too weak

Take S→AB, A→a, B→b. You can expand A before B or B before A. Both routes make ab, but they describe the same parse tree: S has children A and B, and those become a and b.

To remove this irrelevant choice of expansion order, require a leftmost derivation: at each step replace the leftmost remaining variable. A grammar is ambiguous if some string has two distinct leftmost derivations, equivalently two distinct parse trees. One leftmost and one rightmost derivation do not automatically prove ambiguity.

A whole example from the 2022 paper

Grammar: H→bCb; C→mC | CbC | ε. Terminals b and m represent bread and meat. The start H is the whole hamburger. The string bmbmb can be built in these two leftmost ways:

H⇒bCb⇒bmCb⇒bmCbCb⇒bmbCb⇒bmbmCb⇒bmbmb.H\Rightarrow bCb\Rightarrow bmCb\Rightarrow bmCbCb\Rightarrow bmbCb\Rightarrow bmbmCb\Rightarrow bmbmb.H⇒bCb⇒bmCb⇒bmCbCb⇒bmbCb⇒bmbmCb⇒bmbmb.

H⇒bCb⇒bCbCb⇒bmCbCb⇒bmbCb⇒bmbmCb⇒bmbmb.H\Rightarrow bCb\Rightarrow bCbCb\Rightarrow bmCbCb\Rightarrow bmbCb\Rightarrow bmbmCb\Rightarrow bmbmb.H⇒bCb⇒bCbCb⇒bmCbCb⇒bmbCb⇒bmbmCb⇒bmbmb.

In the first route, the outer C first uses mC, then that remaining C splits into CbC. In the second, the outer C splits immediately, and the left child contributes the first meat. These are different structural choices, not merely doing the same independent replacements in another order. Every step shown replaces the leftmost variable, and both routes end at the identical terminal string.

That's a complete ambiguity witness. You don't need to show every string is ambiguous. The definition needs one witness.

The second route has an extra B→BB subtree. Deleting ε from a written string does not delete that historical tree structure. This is why identical-looking intermediate strings can occur in distinct derivations.

Grammar versus language

“G is ambiguous” is a statement about this grammar. It does not prove its language has no unambiguous grammar. A language is inherently ambiguous when every CFG for it is ambiguous. That is a stronger claim requiring a different argument. Don't upgrade the conclusion just because the wording sounds similar.

Underline the leftmost variable mentally before each step. Check the final terminal strings match exactly. State that the derivations are distinct and therefore the supplied grammar is ambiguous.

For arithmetic expressions, E→E+E|E×E|a permits different parse grouping of a+a×a. A grammar separating expression, term, and factor can impose precedence. It's the grammar structure doing the disambiguation; just writing “multiply first” beside an ambiguous grammar does not change its rules.

The mental model: change the wiring, keep the possible outputs

Every conversion stage should answer the same question: “How can I reconstruct an old derivation from this new one, and a new derivation from an old one?” If you only check that the final grammar looks like CNF, you can still have the wrong language. Format and equivalence are separate obligations.

We need an order because one repair can create the next kind of unwanted rule. Removing ε rules can create unit rules, so doing unit removal first would leave new handoffs behind.

Step 1: protect the start and find all nullable variables

Create S₀→S, with fresh S₀ appearing on no right-hand side. If the original grammar can generate ε, only this protected start will keep that ability in the final CNF.

Find nullable variables by repeated marking. First mark variables with a direct ε rule. Then mark A whenever it has a rule whose entire right-hand side consists of already-nullable variables. A terminal blocks this: a printed a cannot disappear. Repeat until a full pass adds nothing. This is a fixed point: further application changes nothing.

Why repeat? In A→B, B→C, C→ε, A is nullable indirectly. One left-to-right scan could miss it depending on rule order. With finitely many variables, each productive pass adds a mark and the process eventually stops.

Step 2: replace disappearing subtrees with explicit choices

For each rule, choose independently which nullable occurrences to omit. Keep the original rule too. For X→ABA with A nullable and B not nullable, the possibilities are ABA, AB, BA, B. The two As share a variable name but represent separate positions in a derivation.

Do not retain an ordinary empty right-hand side after this stage. Preserve S₀→ε exactly when the original start was nullable. Then remove the original ε rules from other variables.

Cycles need no special magic. With S→B|ε and B→S|ε, both variables are nullable; the language is just {ε}. The protected start may generate ε, but there is no terminal-producing work to invent. A conversion that manufactures a from this grammar is obviously wrong.

Here's the bit that makes the omission rule click. In an old derivation, a nullable variable might spend five steps becoming ε. In the new grammar, its parent can choose an alternative that leaves that position out immediately. Same finished word; fewer internal moves. We preserve the possible output, not the exact history of how it got printed.

Step 3: follow unit reachability, then copy real work

A unit rule has exactly one variable on its right, such as A→B. For each A, find every B reachable by zero or more unit rules. Copy every nonunit B-production onto A. Then remove unit rules.

Example: A→B, B→C, C→a|DE. A needs A→a|DE, and B needs B→a|DE. C keeps its original alternatives. The slides' CNF2 page 3 wording about removing B→u should not be read as deleting the nonunit production being copied; doing that can destroy valid outputs. Retain the useful nonunit rules.

Step 4: make terminal leaves and binary splits explicit

For X→aBCd, use U→a and V→d, then X→UBCV. Break the four-variable sequence into a chain, for example X→UH₁, H₁→BH₂, H₂→CV. Reading the leaves still gives a, then B's output, then C's, then d. Fresh helpers prevent collisions with existing variable meanings.

A rule X→a is already valid. Do not replace it by X→U unless you also remove the new unit rule afterward. The goal is standard shape, not maximum helper count.

Finite examples can expose a mistake, but the stage-by-stage derivation argument establishes equivalence for all strings.

Why the hell are we rewriting the grammar?

A rule can currently do several things at once: print terminals, create three pending jobs, hand off to one other variable, or produce nothing. That flexibility is convenient for writing a grammar, but awkward for algorithms that must reason about every derivation.

Chomsky normal form, CNF, limits a rule to one of two ordinary shapes:

A→BCorA→a.A\to BC\qquad\text{or}\qquad A\to a.A→BCorA→a.

The first splits one pending job into two pending jobs. The second finishes one job by printing one terminal. Capital letters here stand for variables, lowercase a for a terminal. They are shape examples, not the only letters allowed.

If ε belongs to the language, the new start may also have a rule to ε; that start must not appear on a right-hand side. CNF is a format for a grammar. It does not mean the language becomes regular, deterministic, or unambiguous.

Picture a job ticket. “Print a” completes it. “Do B, then C” tears it into two ordered subtickets. A variable is the ticket's label, not output printed on the page. This analogy maps only the pending-work structure: it does not introduce a real worker, time cost, or a rule that jobs must take equal time. CNF makes every ticket use one of those two shapes.

First understand what “can disappear” means

Nullable does not mean “delete this variable everywhere.” B can also produce b. Removing that possibility would mutilate the language. Nullable means we must preserve both choices: it may contribute something, or contribute nothing.

Why give a machine a stack?

For 0n1n0^n1^n0n1n, after reading n zeros the machine owes n matching ones. A DFA has only finitely many states, so it cannot keep a different state for every possible debt. A PDA adds a stack: a potentially unbounded pile where we can touch only the top. Push one marker per zero; pop one per one. Now the size of the debt is stored outside the finite control.

The state remembers the phase—still reading zeros, or already matching ones. The stack remembers the amount owed. Mixing those jobs makes diagrams feel random. Separating them makes the arrows follow from the requirement.

Think of each pushed zero as an IOU: “a future 1 must pay for this.” The $ marker says there are no more IOUs underneath. The control state says whether issuing new IOUs is still allowed. Once payment starts, a new zero isn't “more of the same”; it violates the required block order. That's why we need both the stack and the phase state.

The problem: the input may not announce the right plan

The bridge: generating a string and checking a string can cooperate

A grammar chooses how to build output. A PDA can guess those grammar choices while checking them against the supplied input. Its stack means: this is the sequence still owed by the current derivation. The next owed symbol belongs on top, so we can deal with it first.

The deck's grammar is S→aTb∣bS\to aTb\mid bS→aTb∣b, T→Ta∣εT\to Ta\mid\varepsilonT→Ta∣ε. S either produces a single b, or an a, then T's output, then b. T can produce any number of a's. So the language consists of b and all strings of one or more a's followed by one b.

The stack is the machine's to-do list, with the next job on top. Expanding a variable breaks a job into smaller jobs. Matching a terminal checks off finished output against the actual input. Don't let the notation blur those actions together: planning an a and reading an a are two different damn steps.

There are only two kinds of work

If the stack top is a variable, replace it using a grammar production. This consumes no input, because choosing how to produce a symbol is not the same as matching an actual symbol.

If the top is a terminal, it must equal the next input symbol. Consume that input symbol and pop the matching terminal. If they disagree, that branch has no matching move. A terminal cannot be expanded into something more convenient.

Initialize with S above a fresh bottom marker $. Finish when the pending work is exhausted, by removing $ and entering accept. Input must also be fully consumed.

What the sixteen variables are actually for

With four PDA states, the standard conversion introduces one variable Aₚᵩ for each ordered pair of states p,q: 4×4=16 variables. That does not mean the PDA suddenly has sixteen states. We are building a grammar whose variables summarize different kinds of journey through the original machine.

Aₚᵩ means: strings consumed by a run that starts in p with an empty stack and ends in q with an empty stack. The same run pattern can sit above a protected existing stack: it may build and clear extra work but never pop below that baseline. Merely having the same stack at both endpoints is not enough if the run disturbed the protected contents in between.

The PDA first needs a single accepting state, empty-stack completion, and transitions that each push or pop one symbol. The next deck explains that normalization carefully.

Think of a balanced segment as a subroutine that promises: “Whatever stack was underneath me, I'll leave it alone and clean up everything I add.” Aₚᵩ names that contract together with its entry and exit states. The grammar doesn't store a stack snapshot. It describes strings that can be read while honoring that contract.

First normalize the PDA

The course construction requires: one accepting state; empty stack on acceptance; each transition pushes one symbol or pops one symbol, never both and never neither.

14. Check determinism properly

First, build the mental model

DPDA: determinism is about competing enabled moves · chap2_DPDA1.pdf, pages 1–6

One table cell isn't the whole decision

For a DFA, the current state and next input symbol select exactly one move. For a PDA, a move may read input or ε, and may pop the top or ε. Several differently labeled transitions can therefore be enabled at the same situation. Determinism must rule out those competing actions, not merely forbid two answers in one cell.

Suppose the machine is in q, the next input is 0, and the stack top is X. It could potentially use any of these:

Transition lookup What it would do
δ(q,0,X) read the zero and pop X
δ(q,0,ε) read the zero without popping
δ(q,ε,X) pop X without reading
δ(q,ε,ε) move without reading or popping

If two are available, the machine has a choice right now. Different labels do not make that choice disappear.

Read the course definition precisely

This course's DPDA definition requires exactly one of those four entries to be nonempty, for every state q, input symbol a, and stack symbol x. Each nonempty entry returns one pair (next state, symbol to push) rather than a set of alternative pairs.

Some treatments use “at most one” and permit partial transitions. For these slides and exam questions, use the stated exactly-one convention. The next deck completes missing cases with rejecting behavior.

An entry equal to ∅ means there is no transition. A pair such as (r,ε) is an actual transition to r that pushes nothing. Those are very different: no action versus a legal action with no push.

Work one collision

Suppose δ(q,0,ε)=(r,X): read 0, push X. Also suppose δ(q,ε,X)=(s,ε): pop X without reading. When the next input is 0 and the current top is X, both can run. One consumes input and increases the stack; the other consumes nothing and decreases it. Each individual entry has one output, but the machine is nondeterministic.

To repair the design, the state must distinguish the phases in which those actions are allowed, or one of the conflicting moves must be removed while preserving the intended language. Writing the arrows farther apart on the page doesn't fix the collision.

Deterministic does not mean “will accept or reject quickly”

An ε cycle may keep running without consuming the next input symbol. A configuration may become stuck when the input or stack is empty and its required action is unavailable. The four-way condition is stated over actual alphabet symbols; ε is the no-consumption option, not a real member of the input alphabet.

Acceptance is still about a computation that has consumed the whole input and is in an accepting state. Visiting an accepting state while unread input remains isn't enough. This is unlike a Turing machine's accepting halt state, which will be introduced later.

The broader connection

Nondeterminism adds no language-recognition power to DFAs versus NFAs, but deterministic PDAs are more restricted than general PDAs. A stack does not make every midpoint guess deterministic. The absence of a visible separator can matter because the machine may not know when to stop pushing and start popping.

Why a PDA is not always convertible to an equivalent DPDA

DFA and NFA recognize the same languages. PDA and DPDA do not: deterministic context-free languages form a proper subclass of context-free languages. Subset construction cannot solve this by making each possible stack configuration a finite state; stacks have unbounded length, so there may be infinitely many configurations.

A fixed stack bound is different. If a PDA is guaranteed to use at most m stack cells, there are finitely many stack strings, and an NFA can use states (q,stack). Start (q₀,ε), accept all pairs whose q is accepting, and simulate each legal stack update. This is the idea behind 2022 Problem 4(b). The bound must be uniform over all inputs; saying each individual run uses finitely many cells is not enough.

Why give a machine a stack?

For 0n1n0^n1^n0n1n, after reading n zeros the machine owes n matching ones. A DFA has only finitely many states, so it cannot keep a different state for every possible debt. A PDA adds a stack: a potentially unbounded pile where we can touch only the top. Push one marker per zero; pop one per one. Now the size of the debt is stored outside the finite control.

The state remembers the phase—still reading zeros, or already matching ones. The stack remembers the amount owed. Mixing those jobs makes diagrams feel random. Separating them makes the arrows follow from the requirement.

Think of each pushed zero as an IOU: “a future 1 must pay for this.” The $ marker says there are no more IOUs underneath. The control state says whether issuing new IOUs is still allowed. Once payment starts, a new zero isn't “more of the same”; it violates the required block order. That's why we need both the stack and the phase state.

Build the deck's counted-block machine

Use $ as a fresh bottom marker. It is a stack symbol, not an input symbol. Push it before processing a nonempty candidate. During the zero phase, each input 0 pushes a 0. The first 1 changes to the matching phase and pops a 0. Further ones keep popping. When the top becomes $, an ε move can remove it and enter accept.

There are no input-consuming transitions for 0 after the matching phase begins: that enforces block order. There is no matching 1 transition when only $ remains: that prevents too many ones. The original start is accepting to include ε when n=0.

Weighted counts: a complete derivation

2022 Problem 2 uses 0ᵐ1ⁿ with 0.5n≤m≤1.5n, for nonnegative integer m,n. Multiply the condition by 2: n≤2m≤3n. This suggests pushing two markers per zero, then popping 1,2,or3 markers for each one. Successful emptying means the total number popped is exactly 2m.

But why can every total in that interval be achieved? Write t=2m. If n≤t≤2n, choose t−n twos and 2n−t ones. These counts are nonnegative, sum to n, and sum in value to t. If 2n≤t≤3n, choose t−2n threes and 3n−t twos; again n choices with total t. This proves the “if the inequality holds, a successful set of choices exists” direction. The other direction follows since n numbers each between 1 and 3 sum to a value between n and 3n. For n=0, the inequality forces m=0 and the empty sum works.

The 2021 paper asks for a PDA with at most two states recognizing binary strings whose number of ones is divisible by six. A six-state DFA would remember the remainder in its state. A minimality proof for a one-state PDA

In the 2020 language B={0ᵐ1ⁿ | m≥n≥0}, ε must accept. A one-state final-state PDA therefore has its only state accepting. It also must accept 01 by some run starting with an empty stack. That same run can be replayed on another 01, leaving any old stack content underneath: it never needs to pop below the level where its own first run began, and ε in a pop field does not test emptiness. The control state is still the same. Thus it accepts 0101, which violates block order. Contradiction.

The model assumptions matter: this is final-state acceptance and the course's no-pop ε convention. Do not transplant the proof unexamined to a model with empty-stack tests or a different acceptance rule.

16. Program a Turing machine on paper

First, build the mental model

Turing machines: a finite program with a rewritable workspace · chap3_TM1.pdf, pages 1–8

What changes when the stack isn't enough?

A PDA can only inspect the top of its stack. A Turing machine, or TM, has a tape and a head that moves left or right. It can read a cell, overwrite it, move, and come back later. The finite state still stores the current phase of the program; the tape stores the growing work.

The tape has no fixed upper bound on usable cells. That does not mean infinitely many cells are processed in one move. At every finite point in a computation, only finitely much work has happened. “Unbounded workspace” and “infinite work for free” are completely different claims.

One transition does three specific things

δ(q,a)=(r,b,R)\delta(q,a)=(r,b,R)δ(q,a)=(r,b,R) means: in state q reading tape symbol a, write b in this cell, move the head one cell right, and enter r. With L, move left instead. At the tape's left boundary, the course model keeps the head there when it attempts to move farther left.

A blank is an actual tape symbol. ε is a zero-length string or no-consumption notation in other models. A blank cell is not “no cell,” and writing a blank is a real write operation. Tape symbols may include marks such as x that never appear in the original input alphabet.

Build the slide's matching idea: w#w

The separator # tells us where the first copy ends. On input 01#01, mark the first unprocessed left symbol, remember whether it was 0 or 1 in the finite control, cross the separator, and compare it with the first unprocessed right symbol. Mark that symbol too. Return to the left portion and repeat.

After the first round, marks stand where the two zeros were. After the second, both ones are marked too. Finally verify that no extra unmatched symbol remains on the right. Accept only then.

For 01#00, the second comparison fails. For 01#010, the first two comparisons succeed but the final leftover check fails. For malformed input with a missing or extra separator, the machine must reject through its format checks. Matching the examples isn't enough; each clause of the language needs a reason in the program.

What belongs in the seven-part definition?

(Q,Σ,Γ,δ,q0,qaccept,qreject)(Q,\Sigma,\Gamma,\delta,q_0,q_{accept},q_{reject})(Q,Σ,Γ,δ,q0​,qaccept​,qreject​): states; input alphabet; tape alphabet; transition rule; start; accepting halt state; rejecting halt state. Γ includes the blank and all input symbols. Σ excludes the blank. The accepting and rejecting states are distinct and halt immediately when entered.

This differs from a finite automaton or PDA: visiting their accepting state does not necessarily end the run, and acceptance is evaluated after the input is consumed. A TM's program must arrange its checks before entering accept.

The proof has two separate jobs

Correctness says successful comparisons and the final leftover check establish exactly two equal blocks. Halting says the procedure finishes: each round marks another left input symbol; each sweep crosses a finite occupied region; there are only finitely many unmarked left symbols. A convincing trace of 01#01 proves neither claim for every input, but it makes the invariant visible.

A Turing machine has a tape it can read and write, plus a head that moves. Unlike a stack, you can revisit earlier positions. This lets the machine use marks, repeated scans, and work areas. The exam often gives a plan and asks you to compile it into a precise diagram.

Decode one transition

δ(q,a)=(r,b,R)\delta(q,a)=(r,b,R)δ(q,a)=(r,b,R) means: in state q, reading tape symbol a, write b in that cell, move right, and enter r. a→b,R is the diagram label. a→R is shorthand for a→a,R: keep the symbol, move right.

The seven-part definition is (Q,Σ,Γ,δ,q₀,q_accept,q_reject). Σ is the input alphabet; Γ is the tape alphabet and contains the blank and any marks. Standard course definitions exclude blank from Σ. Historical problems can use their own explicit notation; identify any special convention in the question rather than silently changing it.

Entering q_accept or q_reject halts immediately. This differs from a DFA's final-state-at-end rule. The TM must itself perform all needed checks before accepting. A state reached too early does not wait around to read the rest.

A configuration records current state, tape, and head position. In u q v, the state symbol q is inserted immediately before the cell being scanned, which is the first symbol of v. q is not written on the tape.

Build a serious TM from phases

For the slide language {w#w∣w∈{0,1}∗}\{w\#w\mid w\in\{0,1\}^*\}{w#w∣w∈{0,1}∗}:

  1. Select the next unmarked left symbol; mark it x. The state remembers whether it was 0 or 1.
  2. Scan past # to the first unmarked right symbol; compare it and mark it x.
  3. Return across the right block to #, then through the left block until the correct left marker boundary.

Proof obligations for a decider

Invariant: after k completed rounds, the first k symbols on each side were equal and are marked; unmarked suffixes are untouched. Do not forget malformed inputs when the problem requires checking them.

A recognizer accepts members but may reject or loop on nonmembers. A decider halts on every input. A correct-looking acceptance trace alone proves neither total correctness nor termination.

A state name alone no longer describes the situation

For a DFA with fixed input position, the state was enough memory. For a TM, two visits to q can have different tape contents and head positions. A configuration must record all three: control state, tape, and head location. Otherwise a trace can silently lose the information that determines the next move.

The notation uqvu q vuqv writes the tape prefix u to the left of the head, inserts state q at the head position, and writes the scanned symbol as the first symbol of v. q is not a tape symbol; it is an annotation in the snapshot.

Decode one transition completely

Suppose a configuration is a q bc: the tape contains abc, the head reads b, and the state is q. If δ(q,b)=(r,x,R), the new configuration is ax r c. The b was overwritten by x; the head moved to c; the state became r.

If instead δ(q,b)=(r,x,L), the result is r axc: the head now reads the a to the left. The entire tape is still axc; only the placement of the state annotation differs. At the left boundary there is no earlier cell to move into, so that case follows the boundary rule separately.

This is why copying only the state sequence is not a full TM trace. You need the tape edits and head movement too.

Three possible outcomes, not two

A TM may accept, reject, or keep running forever. A recognizer for L must accept every member and must never accept a nonmember. On a nonmember it may reject or loop. A decider must halt on every input, accepting members and rejecting nonmembers.

Every decider is a recognizer. Calling a recognizer “an algorithm that answers yes or no” overstates its guarantee: on some no-instances it may never answer. You cannot turn it into a decider by getting impatient after a million steps; a genuine accepting run might take a million and one.

Read the deck's constructions as phase programs

The w#w machine alternates marking, crossing, comparing, and returning. Its return states need different jobs on the two sides of #; reaching a marked symbol on the right is not the same as reaching the last processed symbol on the left. State meanings explain why several apparently similar left-moving states exist.

The slide language is aibjcka^ib^jc^kaibjck with ij=k and i,j,k≥1: all three blocks must be nonempty. Check that format first, then use repeated matching: for each a, traverse the b-block and account for j c-symbols. Restore temporary b-marks before the next a, while keeping track of c-symbols already spent. The a-count controls the number of repetitions, and the b-count controls each repetition's cost. A final check rejects unused or insufficient c's. The slide's positivity condition rejects zero-size blocks at the format check. A variation allowing zero would need different boundary handling; don't silently change the supplied language.

Reuse the comparison routine on a whole list

Pages 13–14 ask that the binary blocks in #x₁#x₂…#xₗ all differ. Compare every pair, not only neighbors. For #0#1#0, the first and second differ, and the second and third differ, but the first and third are equal. Mark the two selected separators, copy or compare their blocks using the earlier matching routine, then advance to the next pair. With l blocks there are l(l−1)/2 pairs, so a systematic finite pair schedule terminates. The subscripts identify positions in the list, not bits inside one block.

For any construction, state the invariant tying the marks to completed work. Then show why acceptance implies the required relation and why a valid input can complete the procedure. Finally show termination using finite scans and a finite number of progressing rounds. “It keeps trying until it works” is not a halting argument.

18. More tapes, more branches, same power

First, build the mental model

One tape simulates many: encode the whole situation, then update it · chap3_multitapeTM2.pdf, pages 1–5

The job: replace convenient hardware with an encoding

A multitape machine has k tapes and k head positions. A single tape can store their finite used contents as separated blocks, for example #block₁#block₂#…#blockₖ#. Use a marked version of a symbol to indicate each simulated head's position. The delimiter and marked symbols are extra members of the simulator's finite tape alphabet.

The representation must retain both the data and the head locations. Merely joining the tape contents loses which cell each simulated head reads next. That's the same lesson as configurations: an encoding has to preserve everything needed to determine the next step.

Simulate one joint step in phases

First sweep across the encoded blocks and read each marked symbol. Remember the k-symbol tuple in the simulator's finite control. This is possible because k and the simulated tape alphabet are fixed for this machine, so there are only finitely many possible tuples.

Use the simulated transition function to determine the new state, writes, and movements. Make another sweep to update each marked cell and move the head marker to its neighbor. Different blocks may move their heads in different directions, but all updates come from the same old snapshot.

For example, if the simulated heads read (0,1) and the rule writes (x,0) with movements (R,L), the simulator must find those two marked cells, replace their contents, and move the two markers appropriately. It must not let the new x influence the choice of the second write.

What if a simulated tape needs more room?

If a head moves past its block's currently represented end, insert a blank cell into that block. Shift later encoded cells right to make space. A finite-control carry can move symbols one by one; this is tedious but implementable. The block remains a faithful representation of a tape with additional blank cells available.

The simulation is allowed to use many real steps for one simulated step. Computability asks whether the same answers can be produced at all, not whether the hardware has identical speed.

The invariant is the proof

At the beginning of each simulated step, the single-tape encoding represents exactly the multitape machine's complete configuration. Initialization establishes this. Reading the stored head tuple and applying the same transition preserves it. Therefore each finite accepting or rejecting computation is reproduced, and an endless simulated computation continues rather than being falsely turned into a halt.

Conversely, a multitape machine can ignore extra tapes and behave like a one-tape machine. The two simulations establish equal recognition and decision power.

Why this matters later

We can design algorithms using convenient multiple tapes, then know a standard TM can implement them. In complexity theory we revisit this exact construction and count its cost: scanning and shifting a growing representation can turn t simulated steps into roughly quadratic work. Same computability is compatible with different efficiency.

Keep: encode complete configurations; preserve them one simulated step at a time. The proof is an invariant plus a way to implement each update.

Two tapes: one simultaneous move

A k-tape transition reads k symbols, writes k symbols, and moves k heads, while changing one shared control state. For two tapes,

δ(q,a,b)=(r,c,d,R,L)\delta(q,a,b)=(r,c,d,R,L)δ(q,a,b)=(r,c,d,R,L)

reads a on tape 1 and b on tape 2, writes c,d respectively, moves head 1 right and head 2 left, and enters r. Do not run the tape-1 line as one machine step and the tape-2 line as another. They are one joint instruction.

The course allows a stay move S for multitape machines. The input starts on tape 1; all other tapes are blank. Any extra left marker you want must be a permitted symbol, and its initialization must be part of the construction.

A concrete copy routine

Suppose the tape alphabet permits a marker $. First write $ at the beginning of tape 2 and move its head right, leaving tape 1 at the first input character. For each a∈{0,1}, read a on tape 1 and blank on tape 2; write a on tape 2 and move both heads right. At tape-1 blank, the copy is complete. Move tape-2 head left over copied symbols until $, then right. Now tape 2 is positioned at the copy's first symbol.

This illustrates initialization, simultaneous updates, and boundary detection. It is not a substitute for a past question that restricts Γ={0,1,#,⊔} and forbids $. Under such a restriction you must use the permitted marking strategy or boundary behavior.

Simulating many tapes with one

Encode each tape's used region as a block separated by #. Mark the scanned cell in each block using a dotted version of its symbol. A one-tape simulator scans the blocks to learn the k scanned symbols, remembers that finite tuple in its control, then scans again to perform the prescribed writes and move the marks. If a simulated head needs a fresh cell, insert a blank in that block and shift later material right.

For fixed k and finite Γ, the tuple of scanned symbols has finitely many possibilities, so finite control can remember it. Each simulated step takes finitely many scans. This proves simulation of arbitrary computations, not just a sample trace. The reverse direction is immediate: a one-tape machine is a special case of a multitape machine.

A stay move can also be simulated: write the requested symbol, move right into an intermediate state, then move left while preserving that next cell. Choosing right then left avoids problems at the left boundary.

Nondeterministic TM: why breadth-first matters

An NTM accepts if at least one branch accepts. A depth-first simulator may follow one infinite branch forever while another branch accepts after five steps. So enumerate the tree fairly, by depth: all paths of length 0, then 1, then 2, and so on. Each layer is finite because each configuration has finitely many next moves.

If an accepting branch exists, it has a finite length d, and the breadth-first simulator eventually visits it. Thus a deterministic TM can recognize the same language. This is not NFA subset construction into finitely many control states; TM configurations include arbitrarily long tape contents.

If every branch halts on every input, finite branching implies the computation tree for a fixed input is finite (the relevant consequence of König's lemma). Then exhaustive breadth-first simulation can also reject after all branches finish. This establishes equivalence for deciders too. “Every branch is finite” alone would not imply a finite tree if infinite branching were allowed; finite branching is essential.

Fresh practice

An NTM's left branch loops forever; its right branch accepts after three steps. Describe what a depth-first simulator and a breadth-first simulator might do, and whether the NTM accepts.

Show the answer

The NTM accepts because its right branch accepts. A depth-first simulator choosing the left branch first can loop forever and never discover this. Breadth-first explores all finite depths fairly, so it eventually reaches the right branch's accepting configuration at depth three. This explains recognizer equivalence; it does not make the original NTM a decider, because one branch fails to halt.

The whole-course question gets bigger

We've shown that several formal machine designs have the same computability power. Now connect them to the informal word algorithm: a finite, mechanical procedure whose individual steps can be carried out effectively. The Church–Turing thesis says that effectively computable procedures are captured by Turing machines.

This is a thesis linking an informal notion to a formal model, not a theorem proved by manipulating two formal definitions. Equivalence between one-tape and multitape TMs is a theorem; the claim that the model captures every effective method has a different logical status.

Searching for an integer root: yes can be easier than no

Given a polynomial with integer coefficients, try integer inputs and evaluate it. For one variable, test 0,1,−1,2,−2,… . If an integer root exists, this enumeration eventually finds it. If none exists, an unbounded search alone runs forever. It is a recognizer-style strategy for the yes-instances, not automatically a decider.

For a univariate polynomial of positive degree with nonzero leading coefficient, a computable bound on root magnitude turns this into a finite search. Once every integer within a valid bound has been checked, there are no other possible integer roots to miss. For the slide example 4x3−2x2+x−74x^3-2x^2+x-74x3−2x2+x−7, a bound such as |x|≤7 suffices. Constant and zero polynomials are handled separately rather than dividing by a nonexistent leading term.

The critical extra ingredient is the stopping certificate supplied by the bound. “I haven't found a root yet” is not the same information as “I've exhausted every possible root.”

Why the multivariable result is deeper

For polynomial equations in several integer variables, enumerating all integer tuples still recognizes existence of a solution. Hilbert's tenth problem asked for a general deciding procedure. The negative result says no such algorithm exists for all instances. This does not follow just from the fact that our current brute-force search may loop; a bad algorithm doesn't prove all algorithms impossible. An impossibility theorem needs a reduction or other general argument.

Three levels of describing a TM

A formal description lists states and transitions. An implementation-level description explains tape layouts, head movements, and marking. A high-level description uses algorithmic steps such as “search the finite graph,” while making those steps effective and termination clear.

For graph connectivity, begin with one marked vertex, repeatedly mark neighbors of marked vertices, and stop when a whole pass adds nothing. A finite graph has only finitely many vertices to add. Accept if all are marked. The algorithm's monotone progress explains termination; the reachability invariant explains correctness.

An input encoding, written with angle brackets such as ⟨G⟩, turns an abstract object into a finite string. Invalid encodings must have specified treatment. The machine reads symbols, not a Platonic graph floating in the void.

Three levels of memory

Finite automata: finite state only. DFA, NFA, and regular expressions describe the regular languages. An NFA can branch but does not gain language-recognition power over a DFA.

Pushdown automata: finite control plus one unbounded stack. Nondeterministic PDAs and CFGs describe the context-free languages. Every regular language is context-free: a PDA can simulate a DFA while ignoring its stack. Some context-free languages, such as 0ⁿ1ⁿ, are not regular. DPDAs recognize a proper subclass of CFLs.

Turing machines: rewritable tape with a moving head. Multitape and nondeterministic variants have the same recognition power as ordinary deterministic TMs. Deciders halt on every input; recognizers may loop on nonmembers. The ability to simulate another model establishes containment; separating examples establish that a containment is strict.

The published course explicitly omits the detailed non-context-free-language discussion at the end of PDA 5. CFL pumping was absent as a direct task in the six inspected Midterm 2 papers. It is not part of this site's core practice route unless current class information adds it. Regular-language pumping is a separate theorem and must not be used to prove a language is not context-free.

Regular-language closure: what “closed” means

A class is closed under an operation if applying that operation to languages in the class always produces another language in the class. “Open” is not the usual opposite term here; say “not closed.” One result being regular does not establish closure of the whole class.

RE operations are union, concatenation and star. ε denotes the language {ε}; ∅ denotes the empty language. Therefore Rε=R, R∅=∅, R∪∅=R, and ∅*=ε. Concatenation order matters.

Someone claims: “A and B are nonregular, so A∪B must be nonregular.” Disprove this using a language L and its complement over the same alphabet, and explain why both can be nonregular.

Show the counterexample

Take L={0ⁿ1ⁿ | n≥0}, which is nonregular, and its complement over {0,1}*. The complement is also nonregular: if it were regular, closure of regular languages under complement would make L regular, a contradiction. Yet their union is {0,1}*, which is regular. Reading an explanation and producing a proof from a blank page are different skills. This workbook trains both. The target is strong performance on unfamiliar exam questions, including exact procedures and complete justification.

Start with a model you can run in your head

The daily loop

  1. Retrieve before rereading. Start with one previously studied task. Write what you remember on paper. Then check it.
  2. Learn one complete example. Read the problem, its purpose, each transition or proof step, and why that step is justified. Follow the linked slide pages when the original diagram matters.
  3. Close it and produce. Solve a related task without copying the example. If you need help, use the hint; record the attempt as assisted.
  4. Repair the first broken link. Was it notation, the mechanism, the procedure, choosing a method, or proving the claim? Relearn that link, then attempt a different example.
  5. Return after a delay. Aim for the next day, roughly three days later, then a week later. These are adjustable defaults, not a scientifically optimal schedule. Mix related topics after you can attempt their basic procedures.
