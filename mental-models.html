Round zero — what the hell is this course trying to do?

Alright. Before another Greek letter lands on your screen, fix the job in your head: someone gives us a finite input, and we want to determine whether it follows a rule.

Take 0011. A rule might say: “zeros first, then exactly the same number of ones.” This input passes. 001 fails because one zero has no matching one. 0101 fails the order requirement even though the counts match. The rule has two conditions. Forget either and you solve a different problem.

A string is one input sequence. An alphabet is the set of symbols allowed in it. A language is the set of all strings satisfying the rule. The language is the target; a machine is our proposed checker. A machine can be designed incorrectly. Calling a circle “accept” doesn't make its decisions match the target by magic.

First build the machine in your head: what can it remember?

Imagine reading 000… and then receiving the first 1. The earlier zeros are behind you. To decide whether enough ones follow, something must preserve the number of unmatched zeros. That's the actual problem. The circles and arrows are our way of specifying the solution—or proving a proposed kind of solution cannot exist.

Model What survives from earlier input? What that buys us
DFA One of finitely many state labels A finite summary: odd/even, the last symbol, remainder modulo 3
NFA Several possible finite-state runs Convenient guesses; a DFA can track the set of possibilities
PDA A finite state and an arbitrarily growing stack Store one marker per unmatched obligation; discharge the newest one first
Turing machine A finite state, a writable tape, and a movable head Write down information, revisit it, change it and compare separated pieces

A stack is a pile whose top is the only accessible end. A tape is a row of cells you can revisit by moving a head. Those access rules matter as much as the amount of storage. “More memory” is too vague; ask what can be written, inspected, and retrieved next?

For 0011, a PDA pushes two markers while reading the zeros, then pops one per 1. State labels enforce “no zeros after ones.” The stack handles the count; the state handles the phase. That's how the parts cooperate.

Grammars approach the same target from the other direction

A checker receives a finished string. A grammar starts with an unfinished job and constructs a string using replacement rules.

Consider S → 0S1 | ε. S is the unfinished job. → means “may be replaced by.” The vertical bar separates choices. ε means produce no symbols.

S
0S1       add one zero before the unfinished job and one one after it
00S11     repeat that same wrapping move
0011      replace the remaining S by ε

Every wrapping adds a matched pair, and every zero is placed before the unfinished middle while every one is placed after it. The rule builds equality and order into the structure. The PDA's stored markers are another way to manage those unfinished obligations. Grammar ↔ PDA conversions make that connection exact.

CNF then changes the grammar's internal building blocks while preserving its finished strings. It is like reorganizing a recipe into smaller instructions: the meal must remain the same. We will explain exactly what corresponds, so the analogy doesn't have to carry the proof.

A proof is the explanation that survives every input

Watching 0011 work tells us about 0011. To justify the whole PDA, we need a statement that remains true throughout every run: during the matching phase, the stack has one marker for each earlier zero not yet matched by a one. That statement connects the changing machine to the fixed language rule.

To use it, check three things: it starts true; each allowed move preserves it; the final acceptance condition means the rule is satisfied. We also show every valid string has a successful run. This is the bridge from “I can follow the diagram” to “I can prove the diagram works.”

The pumping lemma goes the other way: finite memory forces some long runs to repeat a state, creating a reusable loop. If reusing that loop necessarily breaks the target language, no DFA could have been its correct checker. The loop is forced by the resource limit; the contradiction is between the checker's behavior and the target rule.

Where the later chapters go

Once a tape gives us a general model of an algorithm, we ask a bigger question: does any algorithm solve this problem and always finish? Decidability studies that. Reductions show that a solver for one problem would give a solver for another. Complexity then asks how the number of steps grows with input length. “A solution exists,” “it eventually finishes,” and “it finishes quickly” are three different claims.

The whole idea

This deck gives us the grammar for talking precisely about computers. Before proving anything, ask: what objects are involved, and what exactly am I claiming about them? A bunch of notation becomes much less cursed once every symbol has a job. Pages 1–9 introduce objects and logic; pages 10–15 show how definitions become reasons in a proof.

Aight, first stop: what kind of thing are we even holding? A shopping bag, a queue and a filled-out form are all collections, but you cannot swap their rules around. Sets, sequences and tuples have the same issue. If we identify the object first, the symbols stop looking like random-ass punctuation.

Round 1 — Sort the damn objects before manipulating them · pages 1–6

Imagine a contact list, a queue and a form. A set behaves like a contact list where the question is “is this person included?” Adding the same person twice does not create a new member. A sequence behaves like a queue: who comes first matters, and repeated entries remain. A tuple is an ordered record with a fixed number of fields. These are analogies for membership and order, not claims about software implementation.

Now read the symbols as complete sentences. x∈A means x is a member of A. x∉A means it is not. A⊆B means every member of A is also in B; A may equal B. The slides sometimes use ⊂ for subset, so check the intended convention rather than assuming “strictly smaller.” ∅ is a set with no members. {∅} has one member: the empty set. An empty box and a box containing an empty box are different objects.

A Cartesian product A×B makes ordered pairs, one choice from each set. The order fixes the fields: (1,x) means number first, letter second. A function f:A→B promises one output in B for each input in A. Its domain is A; B is the codomain of allowed outputs. It need not use every output, and two inputs may share an output. A relation merely records which combinations satisfy a condition. The scissors-paper-stone table on page 2 is a relation: T means “the row choice beats the column choice.”

For page 3, ∀x means “for every x”; ⇒ means “implies”; ⇔ means “in both directions.” The three equivalence conditions prevent a grouping rule from behaving inconsistently. Modulo 7 means remainder after division by 7. Thus 2, 9 and 16 belong to one remainder class even though they are different integers.

A graph consists of vertices and edges, not merely circles on paper. Undirected edges join unordered endpoints; directed edges have a source and destination. A subgraph chooses some vertices and some original edges between chosen vertices. It cannot invent a connection absent from the original or retain an edge whose endpoint was removed. An induced subgraph, a stronger condition, must retain every original edge between its chosen vertices; ordinary subgraphs need not.

Round 2 — Why “if” is such a sneaky little word · pages 7–10

AND, written ∧, requires both statements. OR, written ∨, allows either or both. NOT, written ¬, reverses truth. XOR permits exactly one. In Boolean calculations 0 and 1 mean false and true; elsewhere they may be literal input symbols. Same marks, different jobs.

“If P, then Q” makes a promise about cases where P holds. It is broken only by P=true and Q=false. That explains all four rows of the implication table: false/false and false/true do not break the promise; true/true keeps it; true/false breaks it. This is why P→Q agrees with ¬P∨Q. It does not grant the reverse Q→P. Wet ground could come from a sprinkler.

A proof starts with what is granted and earns what is claimed. Direct proof: assume P, derive Q. Contrapositive: assume ¬Q, derive ¬P. Contradiction: assume the claim fails, derive something impossible. The page 10 label is loose; its displayed ¬Q→¬P is specifically the contrapositive. Do not memorize the loose label and carry that confusion into an exam.

Round 3 — Every missing step in the square-root argument · pages 11–15

A rational number can be written m/n with integers m,n and n≠0. “Lowest terms” means cancel all common factors first. An irrational number has no such representation. Assume √2=m/n in lowest terms. Squaring gives 2=m²/n², so 2n²=m². Therefore m² is even.

Why does that force m even? Every odd integer has the form 2k+1. Its square is 4k²+4k+1, which is odd. So an even square cannot come from an odd m. Write m=2k, substitute, and obtain 2n²=4k², hence n²=2k². The same reasoning makes n even. Now m and n both contain factor 2, contradicting our lowest-terms choice. The assumption that √2 was rational must fail.

The even-degree argument uses a different engine: count the same quantity from the edges instead of from the vertices. The square-root argument uses a forbidden consequence of the assumption. “Proof” is not one magic sentence pattern; it is a chain in which each step has a reason.

Build the objects from scratch

A set is a collection where membership matters. {0,1} and {1,0,1} name the same set. A sequence preserves order and repetitions: 01 differs from 10, and 11 differs from 1. A tuple is a fixed-length sequence of entries. A machine's five-tuple is therefore a record with five different fields, not five arbitrary decorations.

A function gives exactly one output for every allowed input. Its output may itself be a set. That is how an NFA transition can be a perfectly valid function even though the machine has several possible next states. A relation records which pairs satisfy a condition; it need not select a single partner.

The Cartesian product lists ordered choices from two sets. If A={1,2} and B={x,y}, then A×B contains (1,x), (1,y), (2,x), (2,y). Later, “state × symbol” simply means “give me those two pieces of information together.”

Watch a definition do useful work

Pages 3–4 use “same remainder modulo 7.” Two integers are related when their difference is a multiple of 7. Why is this an equivalence relation—a way of grouping genuinely interchangeable cases?

An integer differs from itself by zero, so it relates to itself (reflexive). If i−j=7a, then j−i=7(−a), so reversing the pair preserves the relation (symmetric). If i−j=7a and j−k=7b, adding gives i−k=7(a+b), so the relationship passes through the middle number (transitive). Each fancy word has just become a checkable property.

How a proof grows out of the picture

Page 11 asks why an undirected graph's total degree is even. A vertex is a node; an edge joins endpoints; a vertex's degree counts incident edge-ends. Look at one edge. It contributes one end at each endpoint, so two contributions overall. Repeat that accounting for every edge: total degree = twice the number of edges. Twice an integer is even. Done. We counted a generic contribution, so the argument covers every finite graph, not just the drawn example. A self-loop, if allowed, contributes two to its vertex's degree.

An implication “P implies Q” says there cannot be a case with P true and Q false. It does not say Q happens only because of P. “Rain implies wet ground” allows wet ground from a sprinkler. To disprove a universal implication, find one case satisfying P but violating Q.

Source wording to separate: page 10 writes the contrapositive ¬Q→¬P under a contradiction heading. Contraposition proves that equivalent implication. Contradiction assumes the original claim fails and derives an impossibility. Pages 13–15 use contradiction: write √2=m/n in lowest terms; its square forces m even, then n even, contradicting lowest terms. Those methods are related but their opening assumptions differ.

A state diagram will use sets, functions and a graph to define a checker. Proofs will connect its behavior to a claim about all inputs. Your job is to track object, condition, reason before worrying about polished wording.

The whole idea

The automatic door on pages 1–3 is the cleanest starting point: the same sensor reading can require different behavior depending on whether the door is already open or closed. A state stores the relevant situation from before this instant. The circle is the drawing of that stored situation. It is not the memory concept itself.

Think of the door controller as a tiny employee with a brutally small memory. It does not keep a video of everyone who passed. It remembers whether the door is open or closed. The whole damn design question is: does that remembered fact, plus the next sensor input, tell it what to do?

Round 1 — The door has memory, but it ain't remembering your life story · pages 1–3

The door example explains why states exist. Its input alphabet has four categories: front, rear, both, neither. These are four symbols even though their English names contain several letters. In closed, only front opens the door; rear, both and neither keep it closed. In open, front, rear or both keep it open; neither closes it. The rule avoids swinging the door into someone behind it.

The same input “both” has different results depending on current state. So input alone is insufficient. The controller needs one stored fact: open or closed. One bit can distinguish two possibilities. The idealized model ignores motor speed, sensor noise and physical engineering; it isolates the update logic. Automaton is singular, automata plural. A model is simplified on purpose so we can prove something about it.

Round 2 — Work the actual three-state machine all the way through · pages 4–8

This machine has a different job from “ends in 1.” It requires at least one 1 and an even number of zeros after the last 1. Zero zeros counts as even, because 0=2×0.

Give the circles meanings: q₁ means no 1 has appeared; q₂ means a 1 has appeared and the trailing zero count is even; q₃ means a 1 has appeared and that count is odd. From q₁, a 0 changes nothing and a 1 establishes the first 1. From q₂, 0 makes the count odd while 1 resets it to zero. From q₃, 0 makes the count even while 1 again resets it to zero. That's the whole table, derived from meaning rather than guessed arrows.

For 1101, q₁→q₂→q₂→q₃→q₂. All four symbols have been consumed, and q₂ accepts. For 10, q₁→q₂→q₃ and the input ends: reject. The visit to q₂ halfway through did not settle the result. For 000, remain at q₁: no 1 ever appeared. For 100, finish at q₂: two zeros after the last 1.

Round 3 — Turn the notation into a form you can fill · pages 6–10

Q is the list of allowed memory situations. Σ, pronounced sigma, is the input-symbol list. δ, delta, is the update table. q₀ names the designated starting state. F is the collection of successful final states. Finite constrains Q and Σ to finitely many elements; strings may still be arbitrarily long.

The statement q₀∈Q says the start must be one of the available states. F⊆Q says accepting states come from that same inventory. Neither statement requires a state literally labeled q₀. In the slide q₀=q₁. This is like a form field “manager” filled with a person's name: the role and its occupant are different levels.

A=L(M) says the language called A is exactly the collection accepted by machine M. A is not an accepting-state set; F is. In {w | condition}, w stands for a whole string and the vertical bar means “such that.” In |w|, the pair of bars means length. In “#0,” # means number of zeros. No, these marks don't all do the same job.

The final two-state example needs less memory than the three-state one. Once the next symbol arrives, knowing earlier symbols cannot improve the ends-in-1 decision. That is the design question to keep: which differences in the past can still change the answer for a future continuation?

Build the machine before the notation

A door controller receives a sensor category such as front, rear, both or neither. Its current state plus that reading determines the next state. You do not need the entire history of everyone who walked past. You need the small summary that makes the next decision possible.

A DFA applies the same idea to a string: read one symbol, update the summary, repeat. “Deterministic” means a current state and symbol specify exactly one next state. “Finite” means the list of available summaries is fixed and finite. It cannot invent a new state every time the input gets longer.

Acceptance is checked after all input is read. An accepting state may have outgoing arrows because the current prefix might be valid while a longer string is not. Walking through an accepting state halfway through is not an early victory lap.

Follow the actual slide example

Pages 9–10 ask for strings ending in 1. What must survive from the past? Only whether the most recently read symbol is 1. Use q₁ for “no last 1” and q₂ for “last symbol was 1.” Initially q₁: no symbol has been read, and the empty string does not end in 1.

Current summary      Read 0       Read 1
q₁: not ending in 1   q₁           q₂
q₂: ending in 1       q₁           q₂

For 1010, start q₁. Read 1→q₂, 0→q₁, 1→q₂, 0→q₁. End in q₁, so reject. Notice why both rows agree: whatever happened before, a new final 0 makes the current prefix end in zero. The update rule follows from the state's meaning.

Now decode the five pieces

The tuple (Q,Σ,δ,q₀,F) names the same machine in five fields. Q is the finite set of states; Σ is the input alphabet; δ is the update function; q₀ is the chosen starting state; F is the set of accepting states. In this example Q={q₁,q₂}, Σ={0,1}, q₀=q₁ and F={q₂}. The subscript 0 in q₀ means “designated start,” so its actual label can be q₁. Annoying notation, yes; no mathematical conflict.

δ(q₁,1)=q₂ reads “from q₁, on input 1, go to q₂.” Its type Q×Σ→Q means it consumes a pair and returns one state. It says nothing about how many accepting states are permitted. F may contain several states or none.

Why this works

After every nonempty prefix, the machine is at q₂ exactly when that prefix ends in 1. Check the first symbol, then notice each update preserves the statement. At the end, F selects exactly the required strings. This statement is the machine's invariant: its maintained meaning.

The whole idea

The design question is: which differences between input histories can safely be forgotten? If two histories require the same behavior for every possible continuation, one state may represent both. If some continuation must distinguish them, merging them loses information. This is the reason to design state meanings before drawing arrows.

Say I hide the input you already read. What facts would you need me to leave on a sticky note so you can finish the decision? That sticky note is the state. For “same first and last symbol,” forgetting the first symbol wrecks the job, even if you remember the last one perfectly.

Round 1 — The first letter stays; the last letter keeps changing · pages 1–4

For strings beginning and ending with the same symbol, one memory slot is not enough. You need to retain the first symbol and update the most recent one. The slide uses a separate start s, then two states for strings starting with a and two for strings starting with b. Only the matching-end state in each branch accepts. A one-letter a counts: its first and last symbol are the same occurrence. Empty input has no first symbol, so the start is nonaccepting.

Picture pinning the first character to a clipboard and overwriting a “latest character” field. The pinned field explains why you cannot merge the a-start and b-start branches merely because both currently end in a. A future a may accept one and reject the other.

The proof has two obligations. If the machine accepts, its recorded first and last symbols agree. If a nonempty string's first and last symbols agree, the updates put it in the corresponding accepting state. The first direction forbids false positives; the second forbids missed valid strings. “It worked on aba” establishes neither universal direction.

Round 2 — Modulo is a tiny scoreboard · pages 5–8

The reset example remembers the sum of the current segment modulo 3: only remainder 0, 1 or 2. Reading digit d changes remainder r to (r+d) mod 3. This sums digits; it is not interpreting the entire input as a base-three integer. Reading reset discards the old segment and sets remainder to 0.

Trace the slide's 10⟨reset⟩22⟨reset⟩012: remainders 0→1→1→0→2→1→0→0→1→0. End remainder zero means accept. The reset token is one alphabet symbol. Angle brackets here visually name that token; they are not extra characters to feed the machine.

Round 3 — The formal run is just a receipt for every step · pages 9–10

Write input w=w₁…wₙ. The subscript identifies a position: w₁ is the first symbol, wₙ the last; n is length. Write r₀…rₙ for the visited states. There are n+1 state entries because we record the starting situation before consuming any symbol.

r₀=q₀ checks the receipt starts correctly. δ(rᵢ,wᵢ₊₁)=rᵢ₊₁ checks each update uses the actual table. rₙ∈F checks the ending state. The symbol ∃ means “there exists.” In a DFA the valid run is unique, but the formal acceptance statement can still say such a run exists. It is a definition of accepting runs, not a command that every input must accept.

A language is regular if some finite automaton recognizes it exactly. “Some” means at least one, not exactly one. Showing your attempted machine fails does not prove no machine exists. Conversely, producing one correct finite machine is enough to establish regularity.

Round 4 — Remember a useful suffix, not the whole damn string · pages 11–14

For odd numbers of 1s, each 1 toggles even↔odd; 0 preserves the count's parity. Parity means evenness or oddness. Empty input has zero ones, so start even and reject it.

For “contains 001,” before finding the pattern retain the longest ending piece that could begin 001: nothing useful, 0, or 00. From 00 on 0, stay at 00, because the newest two zeros still could start a match. From 0 on 1, return to no useful suffix. From 00 on 1, the match is complete; stay accepting on every later symbol. Once a substring has occurred, later input cannot un-occur it. That is why this accepting state loops forever, whereas the ends-in-1 accepting state did not.

Build the picture from the slide examples

Pages 1–4 recognize nonempty strings whose first and last symbols agree. You need the first symbol permanently, and you update the current last symbol. A separate initial situation handles “nothing read yet.” One symbol such as a already has matching first and last symbols; the empty string needs its own decision.

Pages 6–8 keep the sum since the last reset, modulo 3. Modulo 3 means the remainder after division by 3: 0, 1 or 2. You can throw away the actual sum because adding the next digit affects the final remainder using only the current remainder. A reset overwrites the summary with remainder zero. This is deliberate forgetting, not random loss of memory.

One complete construction: odd many ones

Pages 11–13 ask for binary strings with an odd number of 1s. “Odd” means 1,3,5,…; “even” means 0,2,4,…. You do not need to distinguish one 1 from a thousand and one. Both require the same future toggles.

Let qₑ mean “even many ones so far,” and qₒ mean “odd many.” Start qₑ because the initial count is zero. Accept at qₒ. Reading 0 changes no count, so each state loops on 0. Reading 1 changes parity, so it switches states.

For 010101, the summaries after each symbol are even, odd, odd, even, even, odd. Accept. If you append another 1, the answer flips. That is exactly what the rule demands.

The formal computation page is a run log

On page 9, w=w₁…wₙ names the input symbols. The r₀,…,rₙ names the visited states. w entries are what we read; r entries are what we remember afterward. There are n symbols but n+1 recorded states because r₀ records the situation before reading anything.

r₀=q₀ says start correctly. δ(rᵢ,wᵢ₊₁)=rᵢ₊₁ says each adjacent row follows the update rule. rₙ∈F says the final recorded state belongs to the accepting set. “∈” means membership. It is an acceptance test, not a claim that every run must accept.

A language is regular if some finite automaton recognizes exactly its strings. That is an existence claim about a checker. A language does not become regular because its English description sounds simple.

Why this method generalizes

The odd/even invariant holds at the start and survives each symbol. That gives a proof for arbitrarily long inputs. The “contains 001” machine on page 14 uses another summary: how much of the useful suffix 001 has been matched, or whether it was already found. After 000, the useful suffix is still 00; an extra zero should not erase both zeros from memory.

Round 1 — Three operations, three different jobs · pages 1–5

Union A∪B is a choice of whole strings: accept something belonging to A or B or both. Concatenation A◦B glues one complete member of A before one complete member of B. It preserves order. Star A* glues any finite number of A-members, including zero members. “Zero members” produces ε, the length-zero string. Thus goodbad and badgood both belong to A*: each block is chosen independently, but the order within a chosen block stays intact. The empty language ∅ has no block to choose; nevertheless ∅*={ε}, because choosing zero blocks is still permitted.

Closed under is a property of a family under an operation. “Regular languages are closed under union” means taking two regular languages never takes you outside the regular-language family. You have two working checkers. Now we need plumbing that joins their jobs without secretly eating a symbol or restarting the input. ε is the free handoff: change where the checking continues, keep the unread input where it is. The tricky shit is deciding which handoffs are legal and when.

Round 1 — ε hands off control without stealing a character · pages 1–7

For union, imagine a reception desk with two doors to two departments. The desk chooses which checker to enter; it does not consume part of the customer's document. That is why the fresh start has ε arrows to both original starts and no 0/1 arrows of its own. If the alphabet is a/b, the same reasoning applies. The dispatch mechanism is independent of the input symbols.

Before joining machines, rename states so their state sets are disjoint. Otherwise both could contain a q₁ and you might accidentally merge unrelated rooms. Keep all old transitions. Accept in either machine's original accepting states. A successful new path chooses one department and then follows its old checker on the entire input. Conversely, any successful old path remains available through its ε entrance. That's both directions of the union proof.

The piecewise δ definition is a dispatch table: if q belongs to Q₁ use δ₁; if q belongs to Q₂ use δ₂; at the new start on ε return {q₁,q₂}; at the new start on a real symbol return ∅. A missing last case would leave the formal function incompletely specified.

Relabeling the old start accepting would accept 0, although 0 cannot be assembled from complete 01 chunks. A fresh start accepts ε without blessing every nonempty path that returns to the old start. This is a teaching counterexample, separate from the unlabeled slide diagram.

The fresh start has no incoming arrows in this construction. It does not “loop to itself” merely because it accepts. Accepting is a final-state property, not an arrow. The alphabet still consists of the original real input symbols; ε is a free control move. Those three facts prevent the exact confusion that makes star diagrams look like arbitrary bullshit.

To prove correctness, divide an accepting run at each added restart arrow. Each consumed chunk belongs to A. Conversely, concatenate accepting old runs for any finite list of A-members and connect them with the ε restarts. The fresh accepting start handles the list with no chunks.

The job: describe patterns without drawing every state

A machine reads a string and gives a verdict. A regular expression describes which strings belong. Same target, different tool: a checker versus a compact recipe. Don't read a regular expression as one giant literal word. Its operations build sets of possible words.

Hold up: the same δ symbol is doing a different job now. In a GNFA, give it two stations and it tells you the expression labeling travel between them. It is not being asked for “the next state after this letter.” Once the input and output types are clear, the formula has somewhere to live.

Round 1 — δ has changed jobs again · pages 1–2

For a DFA, δ takes a state and input symbol and returns the next state. For an NFA, it returns a set of possible next states. For a GNFA, δ takes two endpoint states and returns the regular expression labeling their connection. Do not read every delta in this course as the same damn function.

δ:(Q−{qaccept})×(Q−{qstart})→R.\delta:(Q-\{q_{accept}\})\times(Q-\{q_{start}\})\to\mathcal R.δ:(Q−{qaccept​})×(Q−{qstart​})→R.

There is exactly one designated start and one designated accept. That is why the tuple contains q_start and q_accept rather than F. Add them fresh, connect start to the old start by ε, and old accept states to the new accept by ε. Merge parallel arrows by union. Keep existing loops. Missing arrows get ∅. Choose an internal state k to remove. For remaining endpoints i and j, name i→k as R₁, k→k as R₂, k→j as R₃, and i→j as R₄. The new edge is R₁R₂*R₃∪R₄. Entry, any number of loops, exit, OR the old bypass.

It does not accept a alone, because entering without leaving does not reach j. If entry is ∅, the detour is impossible regardless of the loop. If only the loop is ∅, the detour still allows ac. Base case is the two-state graph. Recursive step reduces the number of states by one. A finite graph cannot keep losing states forever, so the algorithm terminates.

The correctness proof follows that reduction: removal preserves the language, and the two-state graph's single usable start-to-accept label describes exactly its accepted strings. Different removal orders may produce different-looking expressions with the same language; syntactic equality is not required.

The final slide asks whether starting from an NFA is okay. Yes: its ordinary labels and ε labels are already regular expressions. The question: when is a finite number of states not enough?

A DFA can remember parity with two states. Could it remember the exact number of leading zeros so it can demand that many ones afterward? For {0n1n:n≥0}\{0^n1^n:n\ge0\}{0n1n:n≥0}, the number may be arbitrarily large. “It needs to count” is a useful suspicion, but not yet a proof: plenty of counting tasks only need a remainder. We need a consequence that every DFA must obey.

Suppose a DFA has p states. Read p symbols. The computation has visited p+1 state positions: the initial state plus one after each symbol. With only p different states, some state was visited twice. That's the pigeonhole principle: more visits than available distinct places forces a repeat.

A finite-state checker eventually has to reuse a memory situation on a long enough accepted input. Reusing a state creates a loop. Now we can replay that loop and ask whether the language’s rule survives. That is the whole engine; the theorem’s alphabet soup tells us exactly when we are allowed to use it.

Round 1 — “It needs to count” is a suspicion, not a proof · pages 1–2

For 0ⁿ1ⁿ, the machine must match an arbitrarily large number of leading zeros with trailing ones. Finite memory sounds inadequate, but the exam needs an argument ruling out every possible DFA design. Saying “I can't draw one” only reports your own failed design attempt.

The adjacent-pattern example shows why intuition can screw you over. C requires equally many individual 0s and 1s. D requires equally many adjacent 01 and 10 occurrences. An occurrence is an adjacent pair; overlaps count. In 01010, there are two 01s and two 10s, but three zeros and two ones.

Every 01 is a switch into the 1-region, and every 10 switches back. For a nonempty binary string, the two counts balance exactly when first and last symbols agree. If it starts 0 and ends 1, there is one extra 01; reverse endpoints give one extra 10. ε has both counts zero too. So D is regular: remember the first and current last symbol, with ε accepted. Individual counts C do not collapse into that bounded endpoint summary.

Round 2 — Who chooses what in the theorem? · pages 3–4

The statement is: if A is regular, there is an integer p≥1 such that every accepted string s with length at least p has some split s=xyz satisfying three requirements. y is nonempty; x and y together fit within the first p symbols; repeating y any number i≥0 keeps the string in A.

p is a threshold, not a chosen example string. x is the prefix before the loop, y the loop's consumed substring, z the suffix after it. Concatenation xyz means those exact three pieces in that order. y⁰=ε deletes y; y¹=y leaves it once; y²=yy doubles it. x and z stay fixed.

The quantifier order matters: ∃p, then ∀s, then ∃x,y,z, then ∀i. “For every” means all allowed choices; “there exists” means at least one suitable choice. The split can depend on s. Once selected, it must work for every i. A different successful split for every i is not what the theorem says.

This is a necessary condition for regularity. Regularity guarantees it. Showing a few strings pump does not establish regularity. To use the lemma against regularity, we must show the promised condition cannot hold.

Round 3 — The loop is forced by too many visits and too few rooms · pages 5–9

Assume a DFA for A has p states. Reading the first p symbols records p+1 visits, including the starting state before any input. Pigeonhole principle: placing more visits than available states forces two visits to the same state. Choose their positions j<l in the slide's q₁,…,qₙ₊₁ numbering.

The characters before the first visit form x=s₁…sⱼ₋₁. Those between the visits form y=sⱼ…sₗ₋₁. The rest form z=sₗ…sₙ. The two visits are distinct positions, so l−j>0 and y is nonempty. Both are among the first p+1 visits, so l−1≤p and |xy|≤p.

At the end of x the machine is at the loop state. Reading y returns to that same state. Reading it twice returns there twice; skipping it leaves the machine there already. In every case the unchanged z starts from the same state and reaches the old accepting endpoint. That's the mechanism behind “for all i.”

If A has no strings as long as p, the conditional promise about long members has no counterexample. This is called vacuous truth. The lemma does not insist every regular language contain long strings. A finite language is regular and may satisfy the threshold condition simply because there are no eligible strings.

Round 1 — Build a proof from the promise you are attacking · pages 1–2

The question: who belongs together?

The characters in a+a×a do not visibly say which operation groups first. A grammar can encode that structure. In the deck's layered grammar,

E means an expression built from terms, T a multiplication-level term, and F an atomic factor: a single a or a parenthesized expression. These names are helpful meanings assigned to variables; the rules do the enforcing.

The expression can have one spelling and two different structures underneath. Think of “add first” versus “multiply first”: same visible ingredients, different grouping. The grammar has to tell us which groups belong together. Merely changing the order in which you expand independent jobs does not create a new structure.

Round 1 — The grammar can enforce which operation binds first · pages 1–3

For a+a×a, the top split is E+T. The left E finishes as a; the right T splits as T×F and finishes as a×a. Thus the multiplication forms one subtree inside the addition. Round 3 — Different schedules are not necessarily different structures · pages 7–12

E ⇒ E+E ⇒ a+E ⇒ a+E×E ⇒ a+a×E ⇒ a+a×a

A grammar is ambiguous when at least one string has two parse trees. A language is inherently ambiguous when every CFG generating it is ambiguous. The slide's final wording loosely says “a CFG is inherently ambiguous”; the property being described belongs to the language. Why the hell are we rewriting the grammar?

A rule can currently do several things at once: print terminals, create three pending jobs, hand off to one other variable, or produce nothing. That flexibility is convenient for writing a grammar, but awkward for algorithms that must reason about every derivation.

Chomsky normal form, CNF, limits a rule to one of two ordinary shapes:

A→BCorA→a.A\to BC\qquad\text{or}\qquad A\to a.A→BCorA→a.

The first splits one pending job into two pending jobs. The second finishes one job by printing one terminal. Capital letters here stand for variables, lowercase a for a terminal. They are shape examples, not the only letters allowed.

If ε belongs to the language, the new start may also have a rule to ε; that start must not appear on a right-hand side. CNF is a format for a grammar. It does not mean the language becomes regular, deterministic, or unambiguous.

Picture a job ticket. “Print a” completes it. “Do B, then C” tears it into two ordered subtickets. A variable is the ticket's label, not output printed on the page. This analogy maps only the pending-work structure: it does not introduce a real worker, time cost, or a rule that jobs must take equal time. CNF makes every ticket use one of those two shapes.

Aight, imagine a messy kitchen where a recipe step can do six jobs, delegate to another recipe, or produce nothing. CNF makes every ordinary instruction do one of two things: split into two jobs, or print one finished symbol. Same possible finished strings. Cleaner instructions. The mental model: change the wiring, keep the possible outputs

Every conversion stage should answer the same question: “How can I reconstruct an old derivation from this new one, and a new derivation from an old one?” If you only check that the final grammar looks like CNF, you can still have the wrong language. Format and equivalence are separate obligations.

We need an order because one repair can create the next kind of unwanted rule. Removing ε rules can create unit rules, so doing unit removal first would leave new handoffs behind.

A recipe can delegate to another recipe that delegates straight back. If your cleanup keeps chasing that loop, you never finish. So we collect what is reachable, remember what we already found, and stop when nothing new appears. That stopping point is a fixed point; it is bookkeeping with a termination reason.

Round 1 — Stop playing whack-a-mole with ε rules · pages 1–2, 6–8

The source cycle S→B|ε, B→S|ε shows why naive editing can loop forever. Remove S→ε and B can recreate it; remove B→ε and S can recreate it. The grammar is finite, but an undisciplined procedure can keep repeating the same work.

Compute the nullable set first. Initially mark variables with an explicit ε rule. Repeatedly mark X when it has a rule whose entire right side consists of already-marked variables. A terminal blocks that reasoning because it cannot disappear. Stop when a complete pass adds no new variable. This stable result is a fixed point. Each productive pass marks something new and there are finitely many variables, so termination is guaranteed.

For the cycle, S and B are both nullable immediately. Add fresh S₀→S and preserve S₀→ε. Generate omission alternatives once, retaining originals, then remove ε rules of nonstart variables. Record handled combinations instead of reintroducing them indefinitely. The original language is only {ε}, so after eliminating unit-only dead ends the final useful CNF grammar can simply be S₀→ε.

Round 2 — A set of reachable delegates kills unit cycles · pages 3–4

A unit rule has exactly one variable on the right, such as A→B. For each X, compute Unit(X), the variables reachable from X using zero or more unit rules. Include X itself: its existing nonunit productions must survive. If X→Y and Y→Z, then Z belongs to Unit(X). If Z→X, you have a cycle, not an instruction to repeat forever.

For every Y in Unit(X), copy each nonunit Y→u as X→u. Then discard unit rules. Page 3's wording says to remove both A→B and B→u; deleting B→u globally would be unsafe when other rules still need B. The intended language-preserving move copies B's work to A and retains B's work. This is a source wording correction, not permission to silently alter the target grammar.

Round 3 — Make one complicated rule obey the two permitted shapes · page 5

Teaching example: X→aBCd. Introduce U→a and V→d. Replace the rule by X→UBCV, then split it into X→UY₁, Y₁→BY₂, Y₂→CV, using fresh helpers. Expand the helpers and you recover the exact ordered string aBCd.

Do not replace a rule X→a by X→U unnecessarily; that creates a forbidden unit rule. Terminal wrappers are needed when a terminal appears in a right side of length at least two. A right side of three or more variables needs a binary chain. A two-variable right side already has the correct shape.

Round 4 — Turn the recipe into checks you can actually use

After fresh start, nullable handling, unit handling, terminal isolation and binary splitting, inspect the result against the definition. Every ordinary alternative must be one terminal or two variables. The designated start must not occur on a right side. Its ε rule must be present exactly when the old language included ε.

Also inspect freshness: helper labels cannot accidentally collide with old variables. Inspect order: BC differs from CB. Inspect occurrences: three nullable appearances create up to 2³ choices before duplicates are merged. Duplicate productions do not change a grammar's language, but losing a distinct omission alternative can.

The conversion is systematic because each stage solves one precise violation. If a rule is still illegal at the end, identify which violation remains instead of restarting the whole procedure. The hidden issue: accepting state does not mean the stack is empty

Our general PDA accepts when a run consumes all input and finishes in an accepting state. It may still have stack contents. But the PDA→CFG construction summarizes balanced empty-to-empty runs. We therefore need an equivalent PDA that finishes with an empty stack at one designated accepting state.

This is a change of representation, not permission to change which strings accept. A cleanup gadget is correct only if it cannot help the original machine do extra input processing that used to be impossible.

Cleanup sounds harmless until the machine dumps its stack and strolls back into ordinary computation with evidence erased. That can accept new strings and fuck up the language. We need a one-way exit into cleanup. The source counterexample shows exactly what goes wrong when that boundary is missing.

The dummy is temporary bookkeeping, not a terminal and not an original stack symbol with hidden meaning. Make it fresh so no original operation confuses it with its own markers. The safe gadget is a one-way exit

Add a fresh bottom marker under the original stack contents. Add a fresh drain state. From each old accepting state, allow an ε handoff into this drain. There, pop original stack symbols using ε transitions. When the fresh bottom marker appears, pop it and enter the sole new accepting state.

There is no way back to the old machine and no input-consuming transition in the drain. If a branch guesses completion too early, unread input remains forever, so it cannot accept. If an old accepting run has actually consumed the whole input, it can safely drain and finish. Those two observations establish the language-preserving role of the gadget.

The marker must be fresh: an old computation must not confuse it with one of its legitimate stack symbols. It marks the baseline that the old machine cannot cross.

Normalize individual transitions too

The grammar construction wants each transition to perform exactly one push or one pop. For a transition that both pops b and pushes c, use a fresh intermediate state: first perform the pop (and any input consumption), then perform an ε push of c. The intermediate state has only the intended continuation, so no other old transition can interrupt the halfway state.

For a transition that changes state but neither pushes nor pops, insert a push of a fresh temporary symbol followed by its pop. This creates a balanced two-step version of the same action. Consume the input only once across the two steps.

Fresh states and symbols are not decoration. Reusing an old state could create extra exits; reusing a marker carelessly could allow a wrong pop to match.

What changes when the stack isn't enough?

A PDA can only inspect the top of its stack. A Turing machine, or TM, has a tape and a head that moves left or right. It can read a cell, overwrite it, move, and come back later. The finite state still stores the current phase of the program; the tape stores the growing work.

The tape has no fixed upper bound on usable cells. That does not mean infinitely many cells are processed in one move. At every finite point in a computation, only finitely much work has happened. “Unbounded workspace” and “infinite work for free” are completely different claims.

Now the machine gets a writable notebook. It can mark something, walk away, and come back to read the mark. That is a huge change from a stack that only exposes its top. But there is no teleporting: the head still moves cell by cell, and every mark needs a stated meaning.

Round 1 — The tape is a workspace you can revisit · pages 1–2

Finite automata retain a bounded state summary. A PDA adds an unbounded stack but only exposes its top. A Turing machine adds a tape whose cells can be read, overwritten and revisited by moving left or right. That's the new power: the machine can leave marks and come back to them later.

“Unrestricted memory” on the slide concerns access compared with a stack. A TM still has strict local mechanics: one head reads one cell, one transition writes one symbol and moves one cell. It cannot teleport to an arbitrary address or inspect infinitely many cells at once. The tape is unbounded in the model; each finite computation visits only finitely many cells.

Unlike DFA/PDA acceptance after the full input has been processed, entering q_accept or q_reject halts a TM immediately. A correctly designed TM must inspect what the language requires before choosing either state. The model does not force it to scan every original input cell first.

Round 2 — Same order is why this job needs revisiting · pages 3–4

The language {w#w:w∈{0,1}*} asks for two identical strings in the same order. For w=01, the accepted input is 01#01, not 01#10. A simple push-first-half/pop-second-half strategy naturally compares reverse order, which is the wrong job here.

The TM marks the next unmatched symbol on the left, remembers whether it was 0 or 1 in its finite state, crosses #, finds the next unmatched symbol on the right, compares and marks it, then returns left. Each round matches the corresponding position. Marks x mean “already handled,” not an extra input symbol supplied by the user.

Before accepting, check exactly one separator, legal input symbols, no unmatched left symbols and no extra unmatched right symbols. # accepts because w=ε is permitted. 0# and #0 reject because lengths differ. 01#00 rejects at the second comparison. These cases explain why merely finding one matching pair is insufficient.

Round 3 — Every field of the formal machine · pages 5–8

The seven-tuple is (Q,Σ,Γ,δ,q₀,q_accept,q_reject). Γ is the tape alphabet, containing the input alphabet Σ plus blank and any work markers. Blank ⊔ is not an input symbol; it fills cells beyond the input. There is one designated accepting state and a distinct rejecting state.

δ(q,a)=(r,b,L)\delta(q,a)=(r,b,L)δ(q,a)=(r,b,L)

means: while in state q scanning tape symbol a, overwrite that cell with b, enter state r, and move the head left. The output is a triple. L and R are directions, not symbols written on the tape. The state is held by the control; it is not itself a tape character.

Read the language before reading the arrows

The deck's language is {02n:n≥0}\{0^{2^n}:n\ge0\}{02n:n≥0}. The number of zeros must be a power of two: 1, 2, 4, 8, 16, … . This is not 02n0^{2n}02n, which describes even lengths. 000000 has even length six, but six is not a power of two. ε has length zero and is also excluded.

The numerical idea is simple: one is a power of two; a larger odd count isn't; a larger even count is a power of two exactly when its half is. So repeatedly halve an even count until either one remains or an odd count greater than one appears.

The tape is doing the counting for us. The finite controller only needs to remember “keep this one” versus “cross this one out.” So the trick isn't stuffing the number eight or eight billion into a state label; it's leaving the work distributed across the tape and shrinking it by a rule we can justify.

Crossing a zero out does not physically remove its tape cell. The notebook still contains the crossed-out mess, and the head still travels across it. This machine also reserves the first position. We have to distinguish what you literally see on tape from the count that this encoding represents.

Round 1 — We are testing the input's length, not its binary value · pages 1–3

The language {0^(2ⁿ):n≥0} contains strings with 1,2,4,8,… zeros. n is the exponent; 2ⁿ is the number of input symbols. Empty input is not included because 2ⁿ is never zero. A string 0000 represents length four, not the integer zero written four times.

A positive integer is a power of two exactly when repeatedly halving it reaches 1 without encountering an odd number greater than 1. For length 8: 8→4→2→1. For length 6: 6→3, then reject. Length 1 accepts immediately. That's the mathematical job the tape operations implement.

Crossed-out x symbols remain physically on the tape. “Remaining zeros” means unmarked zeros, not the total number of occupied tape cells. The head skips x without treating it as a new input zero. Forgetting that representation makes the source trace look like the tape length is mysteriously changing.

For input 0000, after initialization the physical tape is ⊔000. That still represents four. One pass marks the first live zero and then alternates keeping/marking, producing ⊔x0x, representing two. The next pass gives ⊔xxx, representing one. A subsequent scan finds no live zero and accepts. The blank at the left is not evidence that the original input had an empty first symbol.

How a tape implements “halve the count”

Scan the live zeros and mark every other one. States alternate between “keep the next live zero” and “cross out the next live zero.” Marks are ignored on later passes; they are old work, not new zeros. The head returns to the left boundary to start another pass.

The state alternation records parity during one sweep. It does not store the whole count. The surviving unmarked cells carry the reduced count between sweeps. This is a recurring theme: use finite control for a small phase distinction, external memory for an unbounded amount.

Use the simulated transition function to determine the new state, writes, and movements. Make another sweep to update each marked cell and move the head marker to its neighbor. Different blocks may move their heads in different directions, but all updates come from the same old snapshot.

For example, if the simulated heads read (0,1) and the rule writes (x,0) with movements (R,L), the simulator must find those two marked cells, replace their contents, and move the two markers appropriately. It must not let the new x influence the choice of the second write.

What if a simulated tape needs more room?

If a head moves past its block's currently represented end, insert a blank cell into that block. Shift later encoded cells right to make space. A finite-control carry can move symbols one by one; this is tedious but implementable. The block remains a faithful representation of a tape with additional blank cells available.

The simulation is allowed to use many real steps for one simulated step. Computability asks whether the same answers can be produced at all, not whether the hardware has identical speed.

The invariant is the proof

At the beginning of each simulated step, the single-tape encoding represents exactly the multitape machine's complete configuration. Initialization establishes this. Reading the stored head tuple and applying the same transition preserves it. Therefore each finite accepting or rejecting computation is reproduced, and an endless simulated computation continues rather than being falsely turned into a halt.

Conversely, a multitape machine can ignore extra tapes and behave like a one-tape machine. The two simulations establish equal recognition and decision power.

Why this matters later

We can design algorithms using convenient multiple tapes, then know a standard TM can implement them. In complexity theory we revisit this exact construction and count its cost: scanning and shifting a growing representation can turn t simulated steps into roughly quadratic work. Same computability is compatible with different efficiency.

Keep: encode complete configurations; preserve them one simulated step at a time. The proof is an invariant plus a way to implement each update.

What branches now?

An NTM can have several legal actions for the same state and scanned symbol. Each action creates a possible next configuration: state, tape contents, and head position. As choices accumulate, the computation forms a tree. Branches are alternative histories, not multiple heads sharing one mutable tape.

A string accepts if at least one branch reaches accept after finitely many steps. A rejecting branch alone doesn't settle the input. A branch that loops also doesn't accept. The whole existential claim is: is there a finite successful computation somewhere in the tree?

A branch gets its own whole notebook, not just a different mood in the same state. One branch can overwrite a cell while another keeps it unchanged. Acceptance asks whether any legal branch succeeds. There is no probability threshold, and we cannot steal a useful tape mark from a different branch.

Round 1 — Each branch gets its own whole machine configuration · pages 1–2

An NTM transition returns a set of triples (state, write symbol, direction). Starting from the same state and scanned symbol, different branches may write different data and move in different directions. Each branch therefore needs its own state, tape contents and head position. You cannot merge branches just because their state names match.

Acceptance is existential: if one finite branch reaches q_accept, the input is accepted. Another branch rejecting or running forever does not cancel that success. If no branch accepts, the recognizer does not accept; a simulation may reject after exhausting a finite tree or continue forever when the search remains infinite.

This is mathematical branching, not a probabilistic choice with a success percentage. The definition asks whether an accepting branch exists. How to systematically simulate that existence on a deterministic machine is the next deck's problem.

Round 2 — Guess a place where aab starts · pages 3–5

The NTM scans right over a and b. Whenever it sees a, it may continue scanning or guess that this is the first a of an aab occurrence. The checking branch then demands another a and then b. On success it immediately accepts, even if more input remains, because finding that substring already proves the language condition.

For baaba, a branch guesses the second position, checks a then b, and accepts. A wrong guess later may reject; irrelevant. For ababa, every attempted aab check fails, and the continuing scan eventually reaches blank and rejects. All branches in this simple example move right through finite input and halt.

Notice a model difference: an NFA must consume the entire input to accept, so its substring-finding accept state needs loops for the remaining suffix. A TM may halt as soon as the fact “contains aab” has been established. The target language is the same; the acceptance mechanisms differ.

Round 3 — A witness is a proposed explanation we can check · pages 6–7

The unary compositeness language contains 0ⁿ when n is composite. Composite means n=pq with integers p,q≥2; allowing 1 as a factor would falsely call every positive number composite. Lengths 0 and 1 are not composite, and primes have no permitted factor pair.

The NTM guesses candidate p and q, then checks the multiplication relation using finite tape routines. To make every branch halt, bound the guesses by the input length n. One implementation nondeterministically decides when to stop constructing a candidate, but rejects if the candidate exceeds n. Merely saying “stop at any time” without a bound could introduce an infinite never-stop branch.

For n=6, a branch choosing p=2,q=3 succeeds. A branch choosing 2 and 2 fails. For n=5, every bounded candidate fails. A deterministic machine could enumerate the same finite candidate pairs sequentially; nondeterminism does not make an undecidable problem decidable here.

The slide asks why sequentially trying every pair sounds deterministic. Because it is. The nondeterministic description instead branches over possible witnesses and verifies each branch's candidate. These two descriptions can recognize the same language while distributing the search differently. Two branches may reach the same control state with different guessed factors on tape. Their later verification differs. You cannot merge them merely because both circles are named q. An NFA's finite state-set method does not directly apply to TMs: tape configurations can be arbitrarily large and there can be infinitely many of them.

A deterministic simulator might try the first branch to completion, then the second. But the first can loop forever while the second accepts in ten steps. Waiting for completion would miss an available yes-answer. We need a fair schedule that never lets one infinite branch hog all the attention. That's why the next deck uses breadth-first exploration.

The problem is scheduling, not lucky guessing

To simulate an NTM deterministically, we must eventually inspect every finite candidate computation. A depth-first strategy can get trapped following an infinite branch. Breadth-first search explores all branches to depth 0, then 1, then 2, and so on. A successful branch of depth d is eventually inspected because only finitely many nodes occur at each earlier depth.

The finite branching condition matters: the transition table supplies finitely many choices per step. Without it, “finish this level before the next” might itself require infinite work.

One branch can wander forever while a successful branch sits two steps away. A simulator that follows the wanderer forever is doing a lousy search. Breadth-first exploration shares attention by depth. Every finite successful path eventually gets its turn. That fairness is the mechanism, not an optional implementation flourish.

Round 1 — Don't let one infinite branch hog the whole damn search · pages 1–3

Depth-first search follows one branch deeply before returning to alternatives. If that branch loops forever, the simulator never visits a short accepting branch next door. Therefore a naive depth-first simulation is not a correct recognizer for an arbitrary NTM.

Breadth-first search examines depth 0, then depth 1, then depth 2, and so on. Every finite accepting computation lies at some finite depth, so it will eventually be reached. This property is fairness: no finite branch prefix is permanently starved by another branch's endless work.

The maximum branching factor b is finite because the NTM has finitely many states and tape symbols, each transition offering finitely many choices. The number of nodes at each fixed depth is finite even though the whole tree may be infinite. That lets each breadth-first layer finish.

Round 2 — The three tapes have three distinct jobs · pages 4–7

Tape 1 preserves the original input. Tape 2 holds a fresh simulation of one branch. Tape 3 holds its address, a finite sequence of branch-choice indices. Address 231 means take child 2, then child 3, then child 1; it is not input data or a tape location.

Enumerate addresses in increasing length: empty address, 1,2,…,b, then 11,12,…,bb, and so on. For each address, reset tape 2 from the original input and follow at most that many choices. If an indicated child does not exist, discard the invalid address. If an accepting state appears, accept immediately. Resetting prevents mutations from one simulated branch contaminating the next.

An infinite branch cannot trap this procedure because each candidate address has finite length. The simulator examines a finite prefix and moves on. If no branch accepts and the tree is infinite, continuing forever is allowed for a recognizer. The construction promises discovery of every finite accepting branch, not a decision about absent acceptance in all cases.

A three-tape deterministic TM can perform these operations; the prior multitape theorem then converts it to one tape. Combining simulations is valid because each component has an explicit finite encoding and transition procedure.

Round 3 — “Every branch halts” needs one more argument · pages 8–9

An NTM decider halts on every branch for every input. To conclude that a deterministic breadth-first simulation halts too, we need its computation tree for each fixed input to be finite.

Here is the missing bridge. If a finitely branching rooted tree had infinitely many nodes, at least one child of the root would have infinitely many descendants; finitely many finite descendant sets cannot cover an infinite set. Choose such a child, then repeat the same argument below it. This constructs an infinite branch. Therefore, if no infinite branch exists and branching is finite, the tree must be finite. This is the relevant form of König's lemma.

The simulator should track the live frontier and reject when it becomes empty, after finding no acceptance. Blindly enumerating every imaginable address forever would not by itself detect that the real tree ended. Breadth-first frontier exhaustion supplies the terminating rejection procedure.

Thus deterministic and nondeterministic machines decide the same languages as well as recognize the same languages. The statement is about solvability. Exploring exponentially many branches may be far slower than following one branch, which is exactly why nondeterministic time becomes a separate topic later.

How the three-tape simulation organizes the work

One tape preserves the original input. Another simulates a candidate branch's working tape. A third records an address: a finite sequence of transition-choice numbers. If at most three choices are available, addresses begin 1,2,3,11,12,13,21,… in length order.

To inspect address 213, reset the work tape to the input, choose option 2 on the first step, option 1 on the second, and option 3 on the third. If a requested option doesn't exist, discard that candidate. If accept is reached along the replay, accept. Then move on to the next address. No single replay is allowed to run past the address's finite length.

These addresses describe choices, not tape cell positions. Replaying from the original input prevents edits from one branch contaminating another.

Why every accepting branch is eventually found

Suppose the NTM accepts in d steps along choices c₁…c_d. There are finitely many shorter addresses and finitely many addresses of length d before that one. Each replay takes finitely many steps. Eventually the simulator replays the successful sequence and accepts.

If the NTM never accepts, the simulator never invents acceptance: every replay uses actual legal transitions. It may search forever. That is acceptable when simulating a recognizer, whose no-instances need not halt.

What changes for a decider?

If every NTM branch halts on a fixed input, and branching is finite, the whole computation tree is finite. The reason is subtler than “each branch is finite, so there are finitely many branches.” If a finitely branching tree had nodes at arbitrarily large depths, one child of the root would have arbitrarily deep descendants; then one child of that child would too; continuing would construct an infinite branch. That contradicts the all-branches-halt assumption.

A breadth-first simulator can therefore maintain the live frontier and reject when no live configuration remains and none accepted. It must actually detect exhaustion; endlessly enumerating meaningless longer addresses without checking completion would not itself be a decider.

What the theorem does and doesn't establish

Deterministic and nondeterministic TMs recognize the same languages and decide the same languages. This is about eventual answerability. The deterministic search may explore exponentially many branches before finding a witness. The later complexity decks ask whether this cost can always be avoided efficiently—an entirely different question.

Hilbert's tenth problem asks for a method that takes an integer-coefficient polynomial and decides whether some integer assignment makes it zero. Because “effectively executable” began as an informal concept, this is not a theorem comparing two independently formalized mathematical definitions. The slide calls it a definition; thesis emphasizes the proposed identification supported by equivalent computational models. Round 2 — Search can recognize without deciding · pages 5–8

For one variable, try 0,1,−1,2,−2,… . If evaluation gives zero, accept. Every integer eventually gets tried, so a root will eventually be found. Without an additional stopping rule, a rootless polynomial makes this search continue forever.

A proven finite root bound changes the job. If every root lies in [−B,B], test only those finitely many integers and reject after they all fail. If degree is d, there are k nonzero terms, maximum coefficient magnitude c_max and leading magnitude |c_d|, then for |x|>max(1,k c_max/|c_d|), the leading magnitude exceeds the total lower-degree magnitude. This gives a sufficient finite radius, even if not the tightest one.

The general multivariable problem is undecidable. The obstacle: a grammar can keep expanding forever

Randomly trying grammar rewrites can get stuck in pointless delegation forever. CNF gives us a size budget for a successful derivation of a specified string length. Now the search has an actual fence around it. We can inspect every candidate inside that fence and justify both yes and no answers.

Round 1 — CNF finally pays rent · pages 1–2

Naively enumerating arbitrary grammar derivations is dangerous: A→B→A can repeat forever without printing anything. CNF removes those arbitrary unit/ε detours for nonempty derivations. If a generated string has n≥1 terminals, its parse tree has n terminal-producing nodes and n−1 binary-splitting nodes, totaling 2n−1 production applications.

Why n−1 splits? Start with one pending leaf. Each binary split increases the number of pending leaves by one. To end with n leaves requires n−1 increases. Each final leaf then prints one terminal. This is the structural reason for the bound, not an unexplained number to memorize.

Convert G to CNF, then enumerate leftmost derivations of exactly 2n−1 steps and compare outputs to w. Fixing leftmost expansion removes the additional choice of which variable occurrence to expand. If there are q productions, at most q choices per step gives a finite upper bound q^(2n−1); incompatible choices can be discarded. Handle w=ε separately by checking whether the start is nullable or has the allowed ε rule.

This algorithm may be wildly inefficient, but it always finishes. Its purpose here is decidability. The later dynamic-programming algorithm improves the runtime.

Round 2 — Productive means “can finish some terminal string” · pages 3–5

For grammar emptiness, mark terminals as already finished. Mark a variable A when some rule A→U₁…Uₖ has every right-side symbol marked. Then A can finish by following that rule and finishing each child. An ε rule has no unfinished children, so it marks its left variable immediately.

Repeat until no new variable is marked. The set only grows, and there are finitely many variables. A cycle A→B,B→A without any terminal-producing exit never gets marked: passing work around forever is not completing it.

If the start is unmarked, no complete output exists, so accept the emptiness question. If marked, reject emptiness. Soundness follows from the completed derivations behind marks. Completeness follows upward from any finite terminal parse tree: its leaves are marked, then their parents, eventually its root.

Round 3 — One failed method is not an impossibility proof · page 6

DFA equivalence used intersection and complement to build a disagreement language. CFLs are not closed under arbitrary intersection or complement, so the same construction is unavailable. That alone does not prove CFG equivalence undecidable; it only blocks this proof method. A separate reduction establishes the impossibility result in later theory.

Intersection with a regular language is a different statement and is closed for CFLs. “Not closed under intersection” means two arbitrary CFL operands can leave the family. Keep the operand conditions, or a memorized slogan will lead you into the wrong argument.

Round 4 — A PDA recognizer may loop even though its language is decidable · pages 7–10

A PDA can make infinitely many ε pushes without consuming the next symbol. Simulating it directly therefore may fail to give a halting decision algorithm. The language's decidability does not require every machine recognizing it to halt; it requires at least one decider.

Given a fixed CFL, choose a CFG for it and run the bounded membership procedure above on each input. This produces the needed decider. PDA→CFG conversion is finite, so a supplied PDA's membership can be decided by that route too.

The hierarchy is regular ⊊ context-free ⊊ decidable ⊊ Turing-recognizable. Each inclusion means every language in the inner family belongs to the outer; strictness means some outer languages are missing inside. Examples include equal blocks for the first separation and acceptance problems for the last. A language family classifies accepted sets, while a particular machine may have extra unnecessary loops or cumbersome implementation.

A binary split increases the number of pending leaves by one: replace one variable by two. Starting from one variable, it takes n−1 splits to create n final positions. Each position then uses one terminal rule, contributing n more applications. Total: (n−1)+n.

The resulting exhaustive algorithm may be slow. “Finite” establishes decidability, not polynomial efficiency. A later deck states the stronger fact that CFL membership has polynomial-time algorithms.

This also explains why a PDA with ε loops can recognize a decidable language. We need not use its possibly nonterminating branches as our deciding algorithm. Convert to a CFG and use a terminating membership procedure.

The question: could every language have a program?

A language is a set of finite strings. A TM is a finite description. Even before constructing a specific impossible problem, we can compare how many descriptions and how many languages there are. If there are more languages than programs, some languages have no recognizing program at all.

“Both collections are infinite” does not settle the comparison. Infinite sets can have different cardinalities—different sizes in the sense of whether their elements can be paired one-to-one.

“I have not seen it accept yet” could mean rejection, or a loop, or acceptance much later. That is the nasty part. The problem asks for a checker that handles every supplied program and input, always halts itself, and gets the answer right. We need to understand that promise before attacking it.

Round 1 — Acceptance and halting are related, but ain't identical · pages 1–2

A_TM asks whether M accepts w. HALT_TM asks whether M halts on w, either accepting or rejecting. The deck informally calls its A_TM discussion the halting problem; keep the displayed acceptance definition precise. A machine that immediately rejects halts, but does not accept.

A_TM is recognizable: simulate M on w and accept if it accepts. If M rejects, reject; if M loops, the simulation loops. The missing ability is a universally terminating no-answer for all nonaccepting computations. A long runtime is not evidence of an infinite loop, and a finite timeout cannot decide this for arbitrary programs.

Round 2 — Infinite size is measured by pairing, not by how crowded a list looks · pages 3–8

A function is injective, or one-to-one, when different inputs have different outputs. It is surjective, or onto, when every codomain element is hit. A bijection has both properties, pairing the sets without collisions or leftovers.

For f(x)=x² on real inputs, outputs never go below zero. With codomain all reals it is not onto; with codomain nonnegative reals it is onto. It is not one-to-one in either version because x and −x share a square. By contrast x³ is a bijection from reals to reals.

The map n→2n pairs positive integers with positive even integers. An infinite proper subset can therefore have the same cardinality as its parent. Cardinality means size in this pairing sense. The sets are not equal as collections—1 belongs to one but not the other—even though their cardinalities agree. The slide's wording “two sets are equal if paired” concerns size, not membership equality.

A set is countable if finite or bijective with the natural numbers. Informally, its members can be placed in a list where every member eventually appears. The list may never end, but no particular member is postponed forever.

Round 3 — Why row-by-row enumeration fails for fractions · pages 9–10

Put positive fractions m/n in a grid. Reading the first infinite row completely would never reach the second row. Instead traverse finite diagonals of increasing m+n. Every positive pair lies on some finite diagonal, so every fraction appears eventually. Skip repetitions such as 2/2 after 1/1 has appeared; reduced fractions give unique representatives.

To include all rational numbers rather than only the positive ones, add 0 and interleave positive and negative fractions. This illustrates the difference between an infinite search that is fair and one that starves later possibilities—the same issue as NTM branch simulation.

Round 4 — Construct a number that dodges every proposed row · pages 11–12

Assume a list r₁,r₂,… contains all reals in (0,1). Construct x one decimal place at a time. At position n, choose digit 1 if rₙ's nth digit is not 1, otherwise choose 2. Then x differs from rₙ at digit n for every n. Digits only 1 and 2 avoid the 0.999…=1.000… representation ambiguity.

Since x is a real in (0,1), the allegedly complete list must contain it at some row k. But its kth digit differs from row k. Contradiction. We did not need to locate a missing number before seeing the list; the construction works against any proposed complete list.

The diagonal uses one carefully chosen disagreement per row. It does not claim x differs from every row at every digit. That distinction is what makes the construction possible and sufficient.

Countable means listable, not finite

A set is countably infinite when its elements can be listed as first, second, third, and so on without missing any. All finite strings over a finite alphabet can be listed by increasing length, and within each length in a fixed order. Every particular string eventually appears.

TM descriptions are some of those finite strings. We can enumerate candidate encodings and discard malformed ones. Thus there are only countably many TMs. Program length has no fixed maximum, but every individual program is finite.

A bijection pairs each element on one side with exactly one on the other, using every element of both. Equal cardinality does not mean the sets contain the same objects. Integers and finite machine encodings are not literally the same set.

Diagonalization shows that some collections cannot be listed

Suppose someone lists infinite binary sequences as rows. Build a new sequence whose nth bit differs from the nth bit of row n. It differs from row 1 in position 1, row 2 in position 2, and so on. Therefore it is absent from the supposedly complete list.

The construction defeats every row for a specific reason, not by vaguely saying “there must be another one.” In the real-number version, choosing safe decimal digits avoids the ambiguity of two decimal representations such as a trailing sequence of 9s. The logical engine is the same: disagreement on the diagonal.

Connect the counting argument to languages

List all finite input strings as s₁,s₂,s₃,… . A language determines an infinite membership sequence: bit i is 1 if sᵢ belongs, 0 otherwise. Conversely, each such sequence defines a language. Since these infinite sequences cannot all be listed, neither can all languages.

Countably many programs cannot cover uncountably many languages. Some languages are not even recognizable. This is an existence result; it does not yet tell us a particular familiar language with no algorithm.

The next deck gives an explicit contradiction for A_TM, then uses recognizability and complement to sharpen the picture. Counting proves there are impossible tasks; diagonal self-reference identifies one.

Assume the impossible helper precisely

Suppose a decider H answers whether any encoded machine M accepts any input w. H always halts. On a yes-instance it says yes; on a no-instance it says no. “No” includes both M rejecting and M looping forever. H would have to settle both cases correctly.

We are assuming this helper exists to derive a contradiction. We are not claiming we can already implement it, and we are not waiting for a looping machine to finish.

Suppose a perfect predictor tells a program what it will do. Build the program to do the opposite of that prediction when inspecting its own description. Now follow both possible predictions. Each breaks the predictor’s promise. The contradiction needs that exact construction; self-reference alone is not some magic spell.

Round 1 — There are more languages than programs · pages 1–3

List finite binary strings by increasing length, then lexicographic order within a length: ε,0,1,00,01,… . Every finite string appears at a finite position. TM descriptions are finite strings, so there are only countably many machines, even though there are infinitely many.

A language is an arbitrary subset of that string list. Its characteristic sequence writes 1 at position i when string i belongs, otherwise 0. For the language of strings starting with 0, the opening bits are 010110011… under the slide's enumeration. This sequence is infinite because it answers membership for every possible finite input.

Infinite binary sequences are uncountable by diagonal bit-flipping. Each corresponds to one language, so there are uncountably many languages. Each machine recognizes one language, though several machines may recognize the same one. Countably many machines cannot cover the uncountable collection. Thus some languages are not even Turing-recognizable. This counting argument proves existence; it does not yet identify a specific example.

Round 2 — The hypothetical perfect checker gets asked about itself · pages 4–8

Assume H decides A_TM, so H always halts and answers whether a supplied M accepts its supplied input. Construct D on input ⟨M⟩: run H on ⟨M,⟨M⟩⟩, then output the opposite result. D can do this because machine descriptions are ordinary finite strings and H is assumed total.

Now feed D its own description. If H predicts D accepts ⟨D⟩, D rejects. If H predicts D does not accept ⟨D⟩, D accepts. Either answer contradicts H's promised correctness. Therefore H cannot exist.

The no-case for an arbitrary M is “M does not accept,” including rejection or looping. The slide sometimes writes “rejects” where that broader condition is needed. D itself always halts under the assumption that H is a decider, so its self-case has no third looping escape route.

In the diagonal table, row i records what Mᵢ does on each machine description. D differs from row i at its diagonal input ⟨Mᵢ⟩. If D appeared as a row, its own diagonal cell would have to disagree with itself. This is the program version of constructing a missing decimal, with total H supplying the hypothetical answers.

Round 3 — Why swapping accept and reject does not complement a recognizer · pages 9–12

A recognizer may loop on a nonmember. Swapping its two halting labels leaves that loop unchanged, but the input should now be accepted by a recognizer for the complement. So the swap works for deciders, where every run reaches a halt, but not for arbitrary recognizers.

Co-recognizable means the complement has a recognizer. The theorem is: A is decidable iff both A and its complement are recognizable. Forward: a decider recognizes A, and swapping its answers gives a decider—and therefore recognizer—for the complement.

Reverse: run the two recognizers with dovetailing, one step of the first, then one step of the second, repeatedly. If the A-recognizer accepts, accept. If the complement-recognizer accepts, reject. Every input belongs to exactly one side, so one of those accepting events eventually happens. A rejection by one recognizer is not needed as the decisive signal; its behavior on nonmembers may include looping.

Since A_TM is recognizable but undecidable, its complement cannot also be recognizable, or the theorem would produce a decider. This provides the explicit nonrecognizable language that the earlier counting proof did not name.

The direction is the whole game

To prove a new problem B undecidable, start with a known undecidable problem A. Show how a solver for B would let you decide A. In words: hard input in, translate it, call the supposed B solver, translate its answer back. If that worked, it would contradict A's known impossibility.

The arrow goes from the known hard problem toward the target problem. Showing that B can be solved using an A oracle says little about B's impossibility; easy problems can also wastefully call a hard oracle.

You are building an adapter: plug the old impossible question into the proposed new solver, then translate its answer back. If that adapter worked, the new solver would solve the old impossible job. So the new solver cannot exist. The damn direction matters; an adapter pointed backward proves something else.

Round 1 — Borrow a solver for B to solve A · pages 1–3

“A reduces to B” means a procedure for B would let us solve A through an effective construction and finite surrounding computation. The direction is easy to reverse by accident. To prove a new target B hard, start with an already hard problem A and show how a B-solver would solve it.

Think of a socket adapter: you already know the task requiring plug A is impossible to power with the available universal setup. If a purported B outlet plus a finite adapter would power A, that B outlet cannot exist under the assumptions either. The analogy represents dependency; the actual proof must specify the adapter algorithm and its answer correspondence.

The logical form is B decidable ⇒ A decidable. Its contrapositive is A undecidable ⇒ B undecidable. A reduction from an easy A to B proves no hardness for B. A reduction that itself calls an undecidable oracle without justification is not a valid finite adapter.

Round 2 — Turn one acceptance question into an emptiness question · pages 4–7

Given ⟨M,w⟩, construct the description of a new machine M₁. On its own input x, M₁ rejects if x≠w. If x=w, it simulates M on w and accepts if M accepts. The fixed w is stored in M₁'s program description.

We can write this description in finite time without discovering whether M will accept. That's crucial. Constructing a simulator is not the same as running the simulated computation to completion. The reduction creates code; the hypothetical emptiness decider must inspect its language behavior.

There are two language cases. If M accepts w, M₁ accepts exactly w, so L(M₁)={w}. If M does not accept w—whether it rejects or loops—M₁ accepts no input, so L(M₁)=∅. A looping run on x=w contributes no accepted member. This repairs the slide's occasional shorthand “rejects” in the no-case.

Assume R decides E_TM, the set of TM descriptions whose language is empty. Run R on ⟨M₁⟩. If R says empty, reject the original acceptance question. If R says nonempty, accept it. R always halts by assumption, and constructing M₁ is finite, so the resulting outer procedure would decide A_TM. Contradiction.

Round 3 — Audit the proof by asking what each machine receives

M is the original machine; w is its fixed test input. M₁ is the constructed machine; x is its arbitrary future input. R is the hypothetical emptiness decider; it receives the description ⟨M₁⟩, not x. S, the outer decider we derive for contradiction, receives ⟨M,w⟩.

These are different levels. If you silently replace x with w everywhere, you can lose the proof that all other inputs are rejected and therefore fail to characterize L(M₁). If you run M inside S before calling R, S may loop and the contradiction collapses.

The result also does not say every particular TM has an unknowable language. Many individual machines are trivially empty or nonempty. It rules out one algorithm that correctly decides emptiness for every encoded TM.

The construction maps acceptance to nonemptiness, so the final Boolean answer is flipped. When later distinguishing many-one reductions from more general decision-procedure reductions, preserve that polarity explicitly instead of claiming a yes-preserving mapping to E_TM without the flip.

  2. If x=w, simulate M on w.

The mental model: a behavioral switch

A reduction can construct a TM whose accepted language has one form if M accepts w and another form if M does not. Then a hypothetical property checker distinguishes the cases. The wrapper is fixed code; the language it ends up recognizing depends on the embedded simulation's behavior.

The target here is REGULARTMREGULAR_{TM}REGULARTM​: given a TM description, decide whether its accepted language is regular. The input is not a DFA with visibly finite-state behavior. It's an arbitrary TM, and the question is whether some DFA recognizes the same language.

Turn the unknown computation into a switch. In one case the constructed machine accepts a familiar regular language; in the other it accepts a known nonregular language. A perfect regularity checker would reveal which case happened. The construction must set up that switch without secretly solving the unknown computation first.

Round 1 — Make the unknown behavior control a visible language property · pages 1–4

REGULAR_TM asks whether the language accepted by a supplied TM is regular. It does not ask whether the TM's diagram looks like a DFA or whether it uses its tape. A cumbersome TM can recognize a simple regular language.

Given ⟨M,w⟩, build M₂ on input x. First decide whether x has form 0ⁿ1ⁿ. If so, accept immediately. Otherwise simulate M on the fixed w and accept if M accepts. The first branch is decidable because we already know a matching algorithm for equal ordered blocks.

If M accepts w, every x accepts: members of 0ⁿ1ⁿ use the first branch, all other binary strings eventually use the simulation branch. Therefore L(M₂)={0,1}*, which is regular. If M does not accept w, only the first branch contributes accepted strings, so L(M₂)={0ⁿ1ⁿ:n≥0}, which is nonregular. Again, “does not accept” includes looping; the proof must not assume M always halts.

A hypothetical regularity decider for ⟨M₂⟩ would therefore answer whether M accepts w. The outer reduction only constructs M₂ and calls that total decider. It never waits for M itself to finish. That gives the contradiction with A_TM's undecidability.

Round 2 — Why the order of the two branches matters

If M₂ first simulated M on w and only afterward checked x's equal-block form, then a looping M would prevent even valid 0ⁿ1ⁿ strings from being accepted. The baseline nonregular language would disappear, and the intended two-case analysis would be wrong.

The unconditional baseline branch must happen before the potentially nonterminating simulation, or be fairly interleaved with it. Here doing the easy decidable baseline test first is sufficient. The mechanism is a property switch: unknown acceptance toggles the language from a known nonregular set to a known regular set.

You need to prove both language identities, not merely exhibit one accepted string in each case. Regularity concerns the entire accepted set. The same reduction design pattern later works for many other nontrivial language properties, though each theorem has its own hypotheses.

Round 3 — Equivalence can hide emptiness as a special case · pages 5–6

EQ_TM asks whether two TMs accept exactly the same language. Choose a fixed machine Z that rejects every input, so L(Z)=∅. Then L(M)=L(Z) exactly when L(M)=∅.

If R decided EQ_TM, an emptiness decider could take ⟨M⟩, construct ⟨M,Z⟩, run R and return its answer. This construction preserves yes/no directly; no flip is needed. Since E_TM was just proved undecidable, EQ_TM is undecidable too.

Notice the economy: the second reduction starts from E_TM because equality with an empty-language reference makes the connection immediate. You do not have to reduce from A_TM every time. Choose a previously established hard problem whose question aligns cleanly with the target.

The number of rounds is O(log n), since each successful round roughly halves the live populations. But the old crossed-out cells still occupy physical tape positions. A pass may still travel across O(n) cells even when few live symbols remain. Therefore the time is O(n log n), not automatically O(n) from imagining the tape physically shrinks.

That distinction—logical population versus physical span—is exactly the kind of detail that separates a plausible story from a correct time analysis.

Multiple tapes can change the movement cost

With a second tape, copy the first block and compare it against the second in coordinated scans. Each relevant symbol needs only a constant amount of local work, so a linear-time method is possible on that model. This does not contradict the one-tape analysis: the storage layout and allowed head movements changed.

The language is the same, the yes/no condition is the same, and computability power is the same. The number of physical steps can differ. Complexity claims must name the model under which they are measured.

How to structure a time proof

Identify the input length n. Divide the algorithm into phases. For each phase, bound the number of repetitions and the cost per repetition, including resets and scans over marked cells. Sum the bounds, then simplify using Big O. If claiming little o, show the ratio or quantify over every positive multiplier; an ordinary upper bound is insufficient.

Keep: little o means vanishing relative growth. For algorithms, count physical work, not just useful-looking edits.

Revisit the one-tape encoding with a stopwatch

We already know one tape can represent k tapes using separated blocks and marked head positions. Now ask how much time that simulation takes. Suppose the multitape machine runs in t(n) steps on inputs of length n, with t(n)≥n and fixed k.

In t steps, each head can visit only O(t) cells, and the original input occupies at most t cells under the assumption. With a fixed number of tapes, the entire encoded configuration therefore has length O(t). This is a bound on how far the simulator may need to scan.

We already built an interpreter for several virtual tapes on one tape. Now audit its bill: how long is the encoded workspace, how many scans per simulated step, how many steps total? The theorem comes from multiplying those costs with the machine’s fixed number of tapes kept fixed.

Round 1 — The old simulation proves possibility; now price the work · pages 1–2

The theorem says a k-tape TM running in t(n)≥n time can be simulated by a one-tape TM in O(t(n)²) time. k is fixed for the source machine; it is not an extra parameter growing with the input. This is an upper bound on one general simulation, not a claim that every multitape computation inherently needs that much time on one tape.

The condition t(n)≥n ensures the input length is covered by the runtime bound. More generally the represented span is controlled by n+t(n); using t(n)≥n simplifies that to O(t(n)). Conditions written before a theorem usually pay for some later step like this.

Round 2 — How long can the encoded tapes get? · pages 3–4

In t steps, a head can move at most t cells from its initial position. Each step writes only one cell per tape. Including the original input, the used span of each tape is O(n+t), hence O(t). With fixed k tapes, the combined delimiter/head-marker encoding has length O(kt)=O(t).

One simulated step scans that encoding to find all marked head symbols, computes the source transition in finite control, and scans to update writes and head marks. If a region must grow, shifting the remaining encoding costs O(t) too. A fixed number of such scans and shifts remains O(t).

The simulator may carry a displaced symbol in its state during a shift, as explained in the earlier conversion. It does not need an unbounded state set because the source alphabet and number of tapes are fixed. The tape stores the growing data; finite control stores a fixed-sized local tuple.

Round 3 — Multiply the number of rounds by a valid per-round bound · page 5

There are at most t source transitions. Each costs at most C·t simulator transitions for some machine-dependent constant C, after accounting for initialization and encoding. Thus total ≤C·t² plus lower-order setup costs, giving O(t²).

We used the final upper bound t as a ceiling for every intermediate encoding length. That may overestimate early steps, but an upper-bound proof is allowed to overestimate consistently. It must not underestimate an operation, such as ignoring shifts or input copying.

If the multitape algorithm runs in n³ time, this simulation yields a one-tape n⁶ upper bound. The exponent changes, but the result remains polynomial. If it runs in 2ⁿ time, squaring gives 4ⁿ, still exponential. The theorem preserves the broad polynomial/exponential distinction while allowing substantial speed differences.

Round 4 — What this establishes about P

Because a one-tape machine is a special multitape machine and the reverse simulation has polynomial overhead, polynomial-time decidability is unchanged between these standard fixed-tape models. That is the relevant robustness of P.

It does not say hardware choices never matter in practice, or that all conceivable computational models have polynomially equivalent costs. The proof uses specific local tape operations and a fixed finite encoding. If you add an operation that solves an arbitrary hard problem in one step, this simulation theorem no longer justifies treating it as free.

When writing an exam proof, present the memory-span bound, the cost of one simulated step, and the number of simulated steps. “By equivalence of TMs” only proves language power; it omits the runtime accounting the question is asking for.

Name what “time” measures before counting

For a nondeterministic decider, time t(n) is the maximum number of steps along any branch on inputs of length n. It measures the longest branch, not the total number of nodes across the computation tree. Every branch must halt within that bound.

If each step has at most b choices, with b a constant determined by the machine, there can be roughly b^d paths of length d. A depth-t tree can therefore contain exponentially many candidates even though each individual branch is short.

A nondeterministic tree can have short branches and a shitload of branches. Those are different costs. The NTM time bound measures the longest branch; a deterministic search pays to explore alternatives. First count possible branches, then include what it costs to represent and inspect them.

Round 1 — Nondeterministic time measures one branch, not the whole tree · page 1

For an NTM decider, t(n) bounds the number of transitions on every branch for every input of length n. The maximum includes rejecting branches. A machine with one fast accepting branch and another infinite branch is not a polynomial-time NTM decider under this definition.

Let b be a fixed upper bound on the number of transition choices from any local situation. A computation tree of depth t has at most 1+b+…+bᵗ nodes. For b≥2, this is O(bᵗ). If b=1, the machine is deterministic and the tree is a single path; we can still use the looser exponential upper bound by taking max(2,b).

Nondeterministic “parallel” language is a way to describe existential branches, not a promise of exponentially many physical processors running for free. Deterministic simulation must account for exploring the choices.

Round 2 — Pay for each branch address you inspect · pages 2–4

Use the three-tape breadth-first simulator: original input, current branch simulation, branch address. Each address has length at most t. Resetting/copying the input costs O(n), which is O(t) because t≥n. Following that address costs O(t), and updating/enumerating its next address costs O(t).

Invalid addresses can stop early; they do not exceed the bound. Keeping the bound for all possible addresses is safe even if many do not correspond to real nodes. If an accepting configuration is found, accept. When every relevant branch is exhausted without acceptance, reject. The NTM's all-branches time bound makes this finite.

Thus a direct multitape simulation costs O(bᵗ·t). The factor t is real bookkeeping work; we do not omit it and hope the exponential hides the explanation.

Round 3 — Why that product becomes 2^{O(t)} · pages 5–6

Rewrite bᵗt as 2^{t log₂b+log₂t}. Since b is fixed, log₂b is a constant. For t≥1, log₂t≤t. Therefore the exponent is at most (log₂b+1)t, giving 2^{O(t)}.

Now convert the three-tape simulator into one tape using the previous quadratic-overhead theorem. If the multitape bound is at most 2^{ct}, its square is 2^{2ct}. Doubling a fixed constant in the exponent still fits 2^{O(t)}. This is why the final single-tape statement has the same broad exponential form.

Do not confuse 2^{O(t)} with O(2ᵗ). The former allows any fixed constant multiple of t in the exponent; the latter only allows a fixed multiplier outside 2ᵗ. That distinction was introduced in Big-O 1 and is doing useful work here.

Round 4 — What the theorem does and does not settle

For a polynomial-time NTM, this general simulation gives a deterministic exponential-time upper bound. It does not prove exponential time is necessary for that language. A clever deterministic algorithm might avoid enumerating the full tree.

That gap leads to P versus NP: can every polynomially bounded nondeterministic search be replaced by some polynomial deterministic method, perhaps one quite different from brute-force simulation? An expensive generic simulation cannot answer no. To establish a lower bound, we would have to rule out all faster algorithms, not merely analyze this particular one.

The transferable proof pattern is explicit: count candidates, bound work per candidate, multiply, and then account for model-conversion overhead. Each layer needs a bound before the final asymptotic shorthand is justified.

The definition is a growth guarantee, not a compliment

P is the class of languages decided by deterministic TMs in polynomial time: for some fixed exponent k, running time is O(nᵏ), where n is input length. The machine must halt on every input and answer correctly. “Polynomial” does not mean instantly practical; n¹⁰⁰ is polynomial and can be absurdly large.

The value of the class is robustness: standard deterministic model changes have polynomial overhead, and useful efficient algorithms often fall inside it. It gives a precise mathematical boundary to investigate, not a guarantee about your laptop's response time.

The good algorithms stop paying for the same work repeatedly. Reachability marks what is already discovered. Euclid preserves the common divisors while shrinking the numbers. Parsing saves answers for substrings. We will identify that reusable fact, show why the updates preserve it, and count the resulting work.

Round 1 — Polynomial is a mathematical class, not a stopwatch guarantee · pages 1–2

P contains languages decided by deterministic TMs in O(nᵏ) time for some fixed k. The union over k means the exponent may differ between languages/algorithms, but it cannot grow with n within one claimed polynomial bound. n³ is polynomial; nⁿ is not.

At n=1000, n³ is 10⁹ while 2ⁿ is about 10³⁰¹. That illustrates the growth gap. Nevertheless a polynomial with a huge exponent or constant can be impractical, and an exponential algorithm may work on small inputs. P captures a robust theoretical notion of efficient solvability, not a universal practical cutoff.

Round 2 — PATH avoids enumerating paths · pages 3–5

PATH asks whether a directed graph contains a route from s to t. A route with repeated vertices can have its cycles removed, so a reachable target has a simple path using at most m vertices. Brute-force enumeration of candidate vertex sequences is finite but exponential.

Instead mark s, repeatedly scan edges and mark b whenever an edge a→b has marked a, then stop when no new vertex is marked. At most m productive passes occur. A simple directed graph has at most m² edges, and each marking/check can be implemented in polynomial time in the graph encoding. Thus total time is polynomial.

Correctness uses the reachability invariant from earlier decks: every mark has a path justification, and at a fixed point no reachable vertex can remain unmarked. Complexity adds a new obligation: bound passes and cost per pass. A correct decider without that accounting has not yet proved membership in P.

Round 3 — Euclid preserves the common divisors · pages 6–11

The greatest common divisor gcd(x,y) is the largest positive integer dividing both. Two positive integers are relatively prime iff their gcd is 1. The update is (x,y)→(y,x mod y), continuing until y=0, then returning x.

Why preserve gcd? Write x=qy+r. Any common divisor of x and y divides r=x−qy. Conversely, any common divisor of y and r divides x=qy+r. The common-divisor sets are identical, hence their largest member is identical. At y=0, every divisor of x also divides 0, so gcd(x,0)=x.

Trace (24,18)→(18,6)→(6,0), returning 6. If x<y initially, the first remainder is x and the swap fixes their order. For x>y>0, x mod y<x/2 or at most x/2 by splitting into y≤x/2 and y>x/2. Across successive iterations the positive operands shrink rapidly, giving O(log x+log y) iterations.

Those logarithms are proportional to binary input length. Long division/remainder on n-bit numbers uses polynomially many bit operations; swapping stored values is polynomial too. Therefore the whole algorithm is polynomial in encoded length, not merely in the enormous numeric values.

Round 4 — The omitted CFL-in-P proof: reuse solved substrings · page 12

For a fixed CNF grammar and input w of length n, let T[i,j] be the set of variables that generate substring wᵢ…wⱼ. Initialize length-one intervals from rules A→wᵢ. For longer intervals, consider each split k and each rule A→BC; put A in T[i,j] when B∈T[i,k] and C∈T[k+1,j]. Process shorter intervals before longer ones. Accept iff the start variable belongs to T[1,n]; handle ε separately.

There are O(n²) intervals and O(n) splits per interval, with finitely many grammar rules to check. This gives O(|R|n³) rule checks. The invariant follows the binary root split of a CNF parse tree. Dynamic programming means storing answers to repeated smaller subproblems so they are not recomputed exponentially. This is a supplementary proof of the theorem the slide states without proof.

PATH: search the graph without enumerating all paths

Given a directed graph G and vertices s,t, ask whether a path from s to t exists. Mark s. Repeatedly inspect outgoing edges from marked vertices and mark their destinations. Stop when t is marked or no new vertex can be marked.

On a graph s→u→t with an extra cycle u→s, marking still progresses safely: revisiting s doesn't create an endless search. A vertex needs to be newly marked only once. At most the number of vertices can be added, and each pass inspects finitely many encoded edges, giving a polynomial bound.

Correctness comes from two directions: each marked vertex has a path from s; every reachable vertex is eventually marked by following a path's edges. Termination comes from finitely many new marks. Enumerating every possible path would waste work on repetitions and cycles.

Euclid: use a preserved relation and a decreasing quantity

To compute gcd(a,b), repeatedly replace (a,b) by (b, a mod b) until b=0. The greatest common divisor stays the same because a divisor divides both a and b exactly when it divides both b and the remainder a−qb.

For 18 and 24: (18,24)→(24,18)→(18,6)→(6,0), so the gcd is 6. The remainder is smaller than the divisor, ensuring progress. More sharply, the relevant magnitude shrinks by at least a factor of two within a bounded number of iterations, giving logarithmically many rounds in the numerical magnitude.

The numbers are binary encoded. Their bit length is logarithmic in their value, so a rigorous polynomial-time claim also counts the bit cost of division/remainder operations. Treating arbitrary-size arithmetic as one free step would hide work.

A familiar language class returns

The deck states that every context-free language is in P. Earlier, CNF gave a finite exhaustive membership algorithm via 2n−1 derivation steps. That particular enumeration can be exponential; it established decidability, not the stronger polynomial result. Polynomial parsing uses shared subproblems instead of separately trying every tree.

This distinction is useful everywhere: a language may admit a slow algorithm and also a fast one. Complexity classes assert the existence of a suitably bounded algorithm, not that every algorithm for the problem is efficient.

Start with checking, not with a mysterious acronym

Suppose someone hands you a proposed Hamiltonian path in a graph: an ordered list of vertices. You can check that it starts and ends where required, visits every vertex exactly once, and uses an actual graph edge between each adjacent pair. The list may have been hard to find, but checking a supplied list is a concrete finite job.

A certificate is that extra proposed evidence. A verifier is a deterministic algorithm that checks the original input together with the certificate. NP consists of decision languages where yes-instances have certificates of polynomially bounded length that can be verified in polynomial time.

For no-instances, every permitted certificate must fail. A verifier that accepts some bogus witness would certify the wrong language.

Think “show me the route and I'll check it.” The certificate supplies the route; the verifier checks the graph's actual edges and the once-per-vertex requirement. It doesn't trust the person who supplied it. A pretty-looking list gets no free pass. This is the concrete meaning of verification before the acronym starts sounding like wizard shit.

A certificate is somebody handing you a proposed reason for yes: “here, this route visits every vertex once.” You still inspect the whole claim. A plausible-looking route with a repeated vertex is bullshit evidence. Fast checking means every required condition is checked within the time bound, not that we trust the suggestion.

Round 1 — A proposed solution can be easier to check than to discover · pages 1–3

A Hamiltonian path visits every graph vertex exactly once. HAMPATH additionally specifies start s and end t. It differs from ordinary PATH, which only asks for some route and need not visit every vertex.

Given a candidate list p₁,…,pₘ, check it contains exactly the graph's m vertices, with no duplicates; starts at s and ends at t; and every consecutive pair is a directed edge. A claimed route that skips one vertex is not a Hamiltonian witness. A list of m distinct valid vertices already covers all m vertices, but validity of each listed identifier must be checked too.

Verification is like checking a supplied route itinerary against a map. The itinerary saves you the search for which route to try; it does not let you skip checking the actual constraints. An invalid certificate must never convince the verifier of a false yes-answer.

Round 2 — The certificate is extra input, with a bounded size · pages 6–9

A verifier V checks an instance w together with a proposed certificate c. The language satisfies w∈A iff there exists a c making V accept ⟨w,c⟩. For yes-instances, at least one valid certificate exists. For no-instances, every certificate must fail. The verifier does not need to accept all certificates for a yes-instance.

For NP, certificate length is bounded by a polynomial in |w| and verification takes polynomial time in |w| under that bound. Making the bound explicit prevents smuggling an exponentially long search transcript into “easy verification.” An arbitrary useless suffix can be ignored in some machine conventions; the clean definition restricts the certificate actually used to polynomial length.

NP stands for nondeterministic polynomial time, not “non-polynomial.” P⊆NP: a polynomial decider can serve as a verifier that ignores the certificate. Membership in NP does not establish that a problem is hard or outside P.

NTIME(t(n)) bounds the longest branch of a nondeterministic decider by O(t(n)). The equality NP=∪ₖNTIME(nᵏ) is proved in the next deck; here the verifier definition gives the first mental model.

Round 3 — Do not overclaim from the compositeness example · pages 4–5

For integer x, a certificate p can be a nontrivial divisor: check 1<p<x and x mod p=0. Or provide p,q≥2 and check pq=x. These are polynomial-time arithmetic checks in bit length.

For the complement of HAMPATH, one failed proposed route is not a certificate that no Hamiltonian route exists. That explains why the obvious yes-certificate does not automatically work for no-instances. It does not prove that no polynomial no-certificate system exists; making that stronger claim would run into unresolved complexity questions.

Round 4 — Guess finitely, then verify every condition · page 10

An NTM guesses a list of m vertex identifiers, with bounded encoding length, then runs the checks above. Guessing is a sequence of branching choices, each branch selecting one candidate list. Every branch halts after polynomial work, accepting exactly when its list is valid.

If a Hamiltonian path exists, one branch guesses it. If none exists, every guessed list fails at least one check. The number of branches may be huge, but nondeterministic time measures the longest branch. Deterministic enumeration would have to pay for exploring the list space unless another algorithm avoids that search. The distinction is a definition, not a claim that real hardware gets those branches for free.

The bound matters: unlimited guessing can wander forever and wreck the time promise. We will connect the two descriptions one direction at a time.

Round 1 — A certificate and an accepting branch encode the same witness · pages 1–3

Suppose V verifies a language in polynomial time with polynomially bounded certificates. An NTM guesses a certificate of at most that bounded length, then runs V. Every branch terminates in polynomial time. If w belongs, some certificate makes a branch accept; if not, every branch rejects.

The length bound must be enforced during guessing. “Guess any finite string, then verify” would allow arbitrarily long branches and would not establish a polynomial bound. Include a counter or a fixed polynomial-sized guessing workspace.

Conversely, suppose an NTM decides the language in p(n) time on every branch. A certificate can list the branch choices for a proposed accepting run. The branching factor is fixed, so each choice uses only a constant number of bits and the certificate has O(p(n)) length. A deterministic verifier simulates those choices, rejects nonexistent transitions or malformed certificates, and accepts only if the recorded branch legally reaches acceptance within the bound.

This proves both directions. The certificate need not magically contain the correct answer; it contains a checkable reason. “Some accepting branch” corresponds exactly to “some accepted certificate.”

Round 2 — A subset chooses occurrences, not unlimited copies · pages 4–6

SUBSET-SUM gives numbers x₁,…,xₖ and target t, asking whether some selection sums to t. The slide permits repeated values in the input, such as two occurrences of 11. Treat the input as an indexed list or multiset: each occurrence can be chosen at most once.

A safe certificate is a k-bit mask. Bit i=1 means include occurrence xᵢ; bit i=0 means omit it. For {4,11,16,21,27} and target 25, mask 10010 chooses 4 and 21. Verify mask length and bits, sum selected values using binary arithmetic, and compare with t.

The slide's bare check “each cᵢ belongs to s” is not sufficient when the certificate lists values. With input list [4,11] and target 8, certificate [4,4] passes value-membership and sum checks but illegally reuses the only 4. A mask or distinct valid indices enforces multiplicity. If the input really contained [4,4,11], selecting both 4 occurrences would be legal.

The certificate size is at most polynomial in the input length; it need not be strictly shorter than the input, contrary to a loose slide inequality. Summing k binary integers increases bit length by at most a logarithmic factor in k, so verification remains polynomial. Guess-and-verify proves membership in NP, not by itself NP-completeness.

Round 3 — The open question is whether finding can always be as efficient as checking · pages 7–8

P has polynomial deterministic decision algorithms. NP has polynomially checkable, polynomial-sized yes-certificates. We know P⊆NP; whether equality holds remains open. “Most people believe unequal” is an opinion about the conjecture, not evidence you may use as a theorem.

A language B is NP-hard when every language in NP reduces to B by a polynomial-time many-one reduction: a polynomially computed transformation f with x∈A iff f(x)∈B. It is NP-complete when it is NP-hard and also belongs to NP. These are two separate requirements.

If one NP-complete problem had a polynomial algorithm, compose that algorithm with each polynomial reduction and every NP language would be in P. If one NP-complete problem were proved outside P, then P≠NP. A failed search for a fast algorithm, a slow brute-force method or a list of difficult instances does not prove that lower bound.

Reductions now have a polynomial-time requirement, stronger than the merely computable reductions used for undecidability. Same dependency idea, stricter cost constraint. That's the connection between the earlier impossibility proofs and this final complexity story.

Reconnect the pieces in the worked model

Now put the mechanism back together. The worked model below revisits the key example and compresses the reasoning into something you can reconstruct.

Reverse the construction

If an NTM decides a language in polynomial time, an accepting branch has polynomially many steps. Record its transition choices as a certificate. A deterministic verifier follows those choices, checks that each is legal, and confirms an accepting halt within the bound.

Because the fixed machine has only finitely many choices per step, each choice needs only a constant number of bits. A polynomial number of choices gives a polynomial-size certificate. The verifier doesn't search all branches; the certificate identifies one candidate branch to check.

That proves the equivalence: polynomial nondeterministic time and polynomially verifiable certificates describe the same class NP.

SUBSET-SUM: make the witness concrete

The deck uses numbers such as {4,11,16,21,27} and a target. For target 25, selecting 4 and 21 works. A certificate can be a bit vector 10010, with one bit per listed entry: 1 means select that occurrence, 0 means skip it. Add the selected numbers and compare with the target.

The input is a list of entries; repeated equal values, if present, are distinct positions. You may use each occurrence at most once in ordinary SUBSET-SUM. A certificate that reuses one index repeatedly would be solving a different problem. Check certificate length, valid entries, and the sum.

Binary arithmetic takes time proportional to bit lengths, but summing at most the listed number of integers of bounded input size remains polynomial. Exhaustively trying every subset has 2ᵐ candidates for m entries. A fast verification procedure does not by itself provide a fast search over all candidates.

Where P versus NP actually stands

P asks for a deterministic polynomial-time decision algorithm. NP asks for polynomially checkable yes-certificates, equivalently polynomial-time nondeterministic decision. P⊆NP. Whether P=NP remains unresolved; the Clay Mathematics Institute lists P versus NP as unsolved (checked November 1, 2026).

NP-complete means a problem is in NP and every NP problem can be transformed into it by a polynomial-time reduction. It is a special kind of completeness, not a synonym for NP. If one NP-complete problem had a polynomial-time algorithm, all NP problems would. No known polynomial algorithm is not the same as a proof that none exists.

The course's final connection

We began by asking what a machine must remember. We moved to what it can compute at all, then what it can compute within a time budget. The same habits keep paying off: specify the object, preserve its meaning through a construction, prove both directions, and account for termination or cost separately.

Keep: bounded guesses are certificates; checking one branch differs from searching the whole tree; the major separation questions remain open.
