Start with the one job underneath the entire course

Alright. Before another Greek letter lands on your screen, fix the job in your head: someone gives us a finite input, and we want to determine whether it follows a rule.

Take 0011. A rule might say: “zeros first, then exactly the same number of ones.” This input passes. 001 fails because one zero has no matching one. 0101 fails the order requirement even though the counts match. The rule has two conditions. Forget either and you solve a different problem.

A string is one input sequence. An alphabet is the set of symbols allowed in it. A language is the set of all strings satisfying the rule. The language is the target; a machine is our proposed checker. A machine can be designed incorrectly. Calling a circle “accept” doesn't make its decisions match the target by magic.

The course keeps changing one resource: what can the checker remember?

Imagine reading 000… and then receiving the first 1. The earlier zeros are behind you. To decide whether enough ones follow, something must preserve the number of unmatched zeros. That's the actual problem. The circles and arrows are our way of specifying the solution—or proving a proposed kind of solution cannot exist.

Model What survives from earlier input? What that buys us
DFA One of finitely many state labels A finite summary: odd/even, the last symbol, remainder modulo 3
NFA Several possible finite-state runs Convenient guesses; a DFA can track the set of possibilities
PDA A finite state and an arbitrarily growing stack Store one marker per unmatched obligation; discharge the newest one first
Turing machine A finite state, a writable tape, and a movable head Write down information, revisit it, change it and compare separated pieces

A stack is a pile whose top is the only accessible end. A tape is a row of cells you can revisit by moving a head. Those access rules matter as much as the amount of storage. “More memory” is too vague; ask what can be written, inspected, and retrieved next?

For 0011, a PDA pushes two markers while reading the zeros, then pops one per 1. State labels enforce “no zeros after ones.” The stack handles the count; the state handles the phase. That's how the parts cooperate.

Grammars approach the same target from the other direction

A checker receives a finished string. A grammar starts with an unfinished job and constructs a string using replacement rules.

Consider S → 0S1 | ε. S is the unfinished job. → means “may be replaced by.” The vertical bar separates choices. ε means produce no symbols.

S
0S1       add one zero before the unfinished job and one one after it
00S11     repeat that same wrapping move
0011      replace the remaining S by ε

Every wrapping adds a matched pair, and every zero is placed before the unfinished middle while every one is placed after it. The rule builds equality and order into the structure. The PDA's stored markers are another way to manage those unfinished obligations. Grammar ↔ PDA conversions make that connection exact.

CNF then changes the grammar's internal building blocks while preserving its finished strings. It is like reorganizing a recipe into smaller instructions: the meal must remain the same. We will explain exactly what corresponds, so the analogy doesn't have to carry the proof.

A proof is the explanation that survives every input

Watching 0011 work tells us about 0011. To justify the whole PDA, we need a statement that remains true throughout every run: during the matching phase, the stack has one marker for each earlier zero not yet matched by a one. That statement connects the changing machine to the fixed language rule.

To use it, check three things: it starts true; each allowed move preserves it; the final acceptance condition means the rule is satisfied. We also show every valid string has a successful run. This is the bridge from “I can follow the diagram” to “I can prove the diagram works.”

The pumping lemma goes the other way: finite memory forces some long runs to repeat a state, creating a reusable loop. If reusing that loop necessarily breaks the target language, no DFA could have been its correct checker. The loop is forced by the resource limit; the contradiction is between the checker's behavior and the target rule.

Where the later chapters go

Once a tape gives us a general model of an algorithm, we ask a bigger question: does any algorithm solve this problem and always finish? Decidability studies that. Reductions show that a solver for one problem would give a solver for another. Complexity then asks how the number of steps grows with input length. “A solution exists,” “it eventually finishes,” and “it finishes quickly” are three different claims.

Chapter 0 — Know what kind of thing you are talking about

Original chap0.pdf · PDF pages 1–15 · Prerequisites

The whole idea

This deck gives us the grammar for talking precisely about computers. Before proving anything, ask: what objects are involved, and what exactly am I claiming about them? A bunch of notation becomes much less cursed once every symbol has a job. Pages 1–9 introduce objects and logic; pages 10–15 show how definitions become reasons in a proof.

Build the objects from scratch

A set is a collection where membership matters. {0,1} and {1,0,1} name the same set. A sequence preserves order and repetitions: 01 differs from 10, and 11 differs from 1. A tuple is a fixed-length sequence of entries. A machine's five-tuple is therefore a record with five different fields, not five arbitrary decorations.

A function gives exactly one output for every allowed input. Its output may itself be a set. That is how an NFA transition can be a perfectly valid function even though the machine has several possible next states. A relation records which pairs satisfy a condition; it need not select a single partner.

The Cartesian product lists ordered choices from two sets. If A={1,2} and B={x,y}, then A×B contains (1,x), (1,y), (2,x), (2,y). Later, “state × symbol” simply means “give me those two pieces of information together.”

Watch a definition do useful work

Pages 3–4 use “same remainder modulo 7.” Two integers are related when their difference is a multiple of 7. Why is this an equivalence relation—a way of grouping genuinely interchangeable cases?

An integer differs from itself by zero, so it relates to itself (reflexive). If i−j=7a, then j−i=7(−a), so reversing the pair preserves the relation (symmetric). If i−j=7a and j−k=7b, adding gives i−k=7(a+b), so the relationship passes through the middle number (transitive). Each fancy word has just become a checkable property.

How a proof grows out of the picture

Page 11 asks why an undirected graph's total degree is even. A vertex is a node; an edge joins endpoints; a vertex's degree counts incident edge-ends. Look at one edge. It contributes one end at each endpoint, so two contributions overall. Repeat that accounting for every edge: total degree = twice the number of edges. Twice an integer is even. Done. We counted a generic contribution, so the argument covers every finite graph, not just the drawn example. A self-loop, if allowed, contributes two to its vertex's degree.

An implication “P implies Q” says there cannot be a case with P true and Q false. It does not say Q happens only because of P. “Rain implies wet ground” allows wet ground from a sprinkler. To disprove a universal implication, find one case satisfying P but violating Q.

Source wording to separate: page 10 writes the contrapositive ¬Q→¬P under a contradiction heading. Contraposition proves that equivalent implication. Contradiction assumes the original claim fails and derives an impossibility. Pages 13–15 use contradiction: write √2=m/n in lowest terms; its square forces m even, then n even, contradicting lowest terms. Those methods are related but their opening assumptions differ.

Carry this into the next deck

A state diagram will use sets, functions and a graph to define a checker. Proofs will connect its behavior to a claim about all inputs. Your job is to track object, condition, reason before worrying about polished wording.

DFA 1 — A state is the information you keep

Original chap1_DFA1.pdf · PDF pages 1–10 · Prerequisites

The whole idea

The automatic door on pages 1–3 is the cleanest starting point: the same sensor reading can require different behavior depending on whether the door is already open or closed. A state stores the relevant situation from before this instant. The circle is the drawing of that stored situation. It is not the memory concept itself.

Build the machine before the notation

A door controller receives a sensor category such as front, rear, both or neither. Its current state plus that reading determines the next state. You do not need the entire history of everyone who walked past. You need the small summary that makes the next decision possible.

A DFA applies the same idea to a string: read one symbol, update the summary, repeat. “Deterministic” means a current state and symbol specify exactly one next state. “Finite” means the list of available summaries is fixed and finite. It cannot invent a new state every time the input gets longer.

Acceptance is checked after all input is read. An accepting state may have outgoing arrows because the current prefix might be valid while a longer string is not. Walking through an accepting state halfway through is not an early victory lap.

Follow the actual slide example

Pages 9–10 ask for strings ending in 1. What must survive from the past? Only whether the most recently read symbol is 1. Use q₁ for “no last 1” and q₂ for “last symbol was 1.” Initially q₁: no symbol has been read, and the empty string does not end in 1.

Current summary      Read 0       Read 1
q₁: not ending in 1   q₁           q₂
q₂: ending in 1       q₁           q₂

For 1010, start q₁. Read 1→q₂, 0→q₁, 1→q₂, 0→q₁. End in q₁, so reject. Notice why both rows agree: whatever happened before, a new final 0 makes the current prefix end in zero. The update rule follows from the state's meaning.

Now decode the five pieces

The tuple (Q,Σ,δ,q₀,F) names the same machine in five fields. Q is the finite set of states; Σ is the input alphabet; δ is the update function; q₀ is the chosen starting state; F is the set of accepting states. In this example Q={q₁,q₂}, Σ={0,1}, q₀=q₁ and F={q₂}. The subscript 0 in q₀ means “designated start,” so its actual label can be q₁. Annoying notation, yes; no mathematical conflict.

δ(q₁,1)=q₂ reads “from q₁, on input 1, go to q₂.” Its type Q×Σ→Q means it consumes a pair and returns one state. It says nothing about how many accepting states are permitted. F may contain several states or none.

Why this works

After every nonempty prefix, the machine is at q₂ exactly when that prefix ends in 1. Check the first symbol, then notice each update preserves the statement. At the end, F selects exactly the required strings. This statement is the machine's invariant: its maintained meaning.

Pages 4–8 use a different three-state language: at least one 1, with an even number of zeros after the last 1. Do not silently reuse the two-state interpretation there. Different target, different information to remember.

DFA 2 — Compress the past without losing the decision

Original chap1_DFA2.pdf · PDF pages 1–14 · Prerequisites

The whole idea

The design question is: which differences between input histories can safely be forgotten? If two histories require the same behavior for every possible continuation, one state may represent both. If some continuation must distinguish them, merging them loses information. This is the reason to design state meanings before drawing arrows.

Build the picture from the slide examples

Pages 1–4 recognize nonempty strings whose first and last symbols agree. You need the first symbol permanently, and you update the current last symbol. A separate initial situation handles “nothing read yet.” One symbol such as a already has matching first and last symbols; the empty string needs its own decision.

Pages 6–8 keep the sum since the last reset, modulo 3. Modulo 3 means the remainder after division by 3: 0, 1 or 2. You can throw away the actual sum because adding the next digit affects the final remainder using only the current remainder. A reset overwrites the summary with remainder zero. This is deliberate forgetting, not random loss of memory.

One complete construction: odd many ones

Pages 11–13 ask for binary strings with an odd number of 1s. “Odd” means 1,3,5,…; “even” means 0,2,4,…. You do not need to distinguish one 1 from a thousand and one. Both require the same future toggles.

Let qₑ mean “even many ones so far,” and qₒ mean “odd many.” Start qₑ because the initial count is zero. Accept at qₒ. Reading 0 changes no count, so each state loops on 0. Reading 1 changes parity, so it switches states.

For 010101, the summaries after each symbol are even, odd, odd, even, even, odd. Accept. If you append another 1, the answer flips. That is exactly what the rule demands.

The formal computation page is a run log

On page 9, w=w₁…wₙ names the input symbols. The r₀,…,rₙ names the visited states. w entries are what we read; r entries are what we remember afterward. There are n symbols but n+1 recorded states because r₀ records the situation before reading anything.

r₀=q₀ says start correctly. δ(rᵢ,wᵢ₊₁)=rᵢ₊₁ says each adjacent row follows the update rule. rₙ∈F says the final recorded state belongs to the accepting set. “∈” means membership. It is an acceptance test, not a claim that every run must accept.

A language is regular if some finite automaton recognizes exactly its strings. That is an existence claim about a checker. A language does not become regular because its English description sounds simple.

Why this method generalizes

The odd/even invariant holds at the start and survives each symbol. That gives a proof for arbitrarily long inputs. The “contains 001” machine on page 14 uses another summary: how much of the useful suffix 001 has been matched, or whether it was already found. After 000, the useful suffix is still 00; an extra zero should not erase both zeros from memory.

The reset, parity and substring examples share one mental move: keep exactly the information needed for later decisions. Their arrows differ because their meanings differ.

DFA 3 — Combine rules by remembering both summaries

Original chap1_DFA3.pdf · PDF pages 1–10 · Prerequisites

The whole idea

You already have two working checkers. Can you combine their languages without reinventing everything? Pages 1–4 define the language operations; pages 5–10 prove one combination works. Closure means an operation never takes you outside the class when you start inside it. It is a statement about all suitable languages, not a “closed” state in a diagram.

First distinguish the three jobs

Union A∪B means the whole input belongs to A or B, possibly both. Concatenation A◦B means the input can be split into a first piece from A and a second piece from B, in that order. Star A* means concatenate zero or more pieces from A. Zero pieces produce ε, the empty string.

The slide's A={good,bad}, B={boy,girl} makes the roles visible. goodgirl is in A◦B; girlgood is not. goodbadgood is in A*, because each piece belongs to A. You may choose the sequence of pieces, but you do not shuffle characters inside a chosen piece. The star counts repetitions of whole members, not necessarily single symbols.

Build the union machine from first principles

The slide combines “odd many 1s” with “odd many 0s.” After a prefix, the first machine knows one parity and the second knows the other. Store the ordered pair of their states. Four combinations are possible: (even,even), (even,odd), (odd,even), (odd,odd).

Start (even,even). Reading 1 flips the first coordinate and leaves the second alone. Reading 0 flips the second and leaves the first alone. For 10, the run is (even,even)→(odd,even)→(odd,odd). Union accepts because at least one coordinate is odd. Input 11 ends (even,even) and rejects: it has two ones and zero zeros, both even.

Each pair is one state of the new DFA, with two pieces of information in its label. No branching is happening. It still has one next state per symbol.

Read the formula as a sentence

Q₁×Q₂ is the set of all state pairs. The new update is

δ((r1,r2),a)=(δ1(r1,a),δ2(r2,a)).\delta((r_1,r_2),a)=(\delta_1(r_1,a),\delta_2(r_2,a)).δ((r1​,r2​),a)=(δ1​(r1​,a),δ2​(r2​,a)).

“Feed the same input symbol a to both old machines and store both new answers.” Subscripts identify which component's update function is used. For union, the new pair accepts when its first coordinate belongs to F₁ or its second belongs to F₂. For intersection, use and instead; the transitions stay the same.

Why the construction proves closure

At the start, both coordinates are the component start states. If a pair correctly records both runs after a prefix, the formula makes it record both runs after one more symbol. Therefore it is correct after every finite input. The final or-test matches union membership exactly. This is induction: start true, preserve it one step at a time, conclude it for every length.

Concatenation exposes a new difficulty: a streaming checker may not know when the first piece finishes. Running both machines from the beginning does not solve that cut-position problem. That's why the next deck introduces nondeterminism.

NFA 1 — Keep several guesses alive

Original chap1_NFA1.pdf · PDF pages 1–13 · Prerequisites

The whole idea

A DFA commits to one next state. An NFA may have several legal moves. The useful picture is a collection of candidate runs: one candidate can die while another succeeds. The definition says accept if at least one complete run consumes the whole input and ends accepting. It is not a probability, a majority vote, or a machine that magically knows the future.

Why guessing helps

Pages 6–7 ask whether the third symbol from the end is 1. While reading left to right, you do not yet know where the end will be. An NFA can continue scanning and, whenever it sees a 1, also start a candidate that says, “maybe this is the third-last position.” That candidate must then consume exactly two further symbols and finish.

The diagram has q₁ looping on 0 and 1; q₁ also goes to q₂ on 1; q₂→q₃ and q₃→q₄ each consume either symbol. Only q₄ accepts, with no outgoing moves. Those missing moves are part of the design: if more input remains, that candidate guessed too early and must die.

Follow the candidates all the way

Use the slide's accepted input 0100. Begin with candidate set {q₁}. After 0: {q₁}. After 1: {q₁,q₂}, because the run can keep scanning or start its guess. After the next 0: {q₁,q₃}. After the final 0: {q₁,q₄}. One candidate finishes at q₄, so accept.

Now 0010: after 0,0,1 the set is {q₁,q₂}; after the last 0 it is {q₁,q₃}. No accepting candidate remains. Reject. The 1 was second-last, not third-last. Reaching q₂ was only a hypothesis, not success.

What ε adds

Pages 2–5 also use ε-arrows. ε means move without consuming an input symbol. If a candidate can follow an ε-arrow, include that possibility while retaining the possibility of taking zero ε-moves. The ε-closure collects everything reachable that way. After consuming the next real symbol, take closure again. Old states do not stay merely because you remember seeing them; they stay only if a legal continuation reaches them at the current input position.

The tree is a record of possible paths. A row can collect possibilities at a common input position, including free ε movement. Actual hardware need not create infinitely many parallel workers; this is a mathematical definition of accepted strings.

Why the DFA can still do this

Pages 8–10 show eight DFA states remembering the latest three bits. That DFA stores enough history to answer at the end without guessing. Leading zeros in the initial q₀₀₀ do not create a false accepting third-last 1 for a short input. Nondeterminism made the design compact; it did not enlarge the regular-language class. Subset construction will prove the general equivalence.

The modified ε version on pages 12–13 asks a different question: is some one among the last three symbols a 1? Zero, one or two remaining symbols may finish the guessed path. Changing arrows changes the permitted completion lengths, hence the language.

NFA 2 — A transition returns a collection of options

Original chap1_NFA2.pdf · PDF pages 1–10 · Prerequisites

The whole idea

We need a precise way to write “zero, one, or several possible next states.” The output of an NFA transition is a set. The function still gives one answer for each request; that answer is the entire option set. This repairs the informal “δ isn't a function anymore” wording in NFA1.

Build the types before reading the formula

For a DFA, asking “from q on 1?” returns one state, say r. For an NFA it may return {r,s}, {r}, or ∅. Braces say “a set containing these states.” ∅ says “there are no options.” The accepting set F is a separate object listing states where a fully consumed run may finish.

The power set 𝒫(Q) is the collection of all subsets of Q. If Q={a,b}, its possible output sets are ∅, {a}, {b}, {a,b}. Each state has an in/out choice, hence 2×2=4 subsets. With three states there are 2³=8. The power set is where the function's answers live; it is not a new kind of accepting state.

Σ names actual input symbols. Σε means Σ∪{ε}, allowing the table to ask about a no-input move as well. Thus δ:Q×Σε→𝒫(Q) reads: state plus a symbol-or-ε request goes in; a set of possible destinations comes out.

Work the slide's actual table

Pages 8–9 have four states. From q₁ on 1 the answer is {q₁,q₂}. From q₂ on ε it is {q₃}. From q₃ on 1 it is {q₄}, and q₄ accepts.

Trace 11. Start {q₁}. The first 1 reaches q₁ and q₂; the free q₂→q₃ move adds q₃. Current possibilities are {q₁,q₂,q₃}. On the second 1, q₁ contributes {q₁,q₂}; q₂ contributes ∅; q₃ contributes {q₄}. Combine those destinations, then close under ε: {q₁,q₂,q₃,q₄}. Accept because q₄ is possible after the whole string.

Notice the empty contribution from q₂. Union with ∅ adds nothing. We do not insert an object called ∅ into the set of NFA states. “No candidate from this branch” is different from “a candidate at a state named empty set.” The latter becomes a useful name only in the converted DFA.

Why the formal run can be longer than the string

Page 10 allows w=y₁…yₘ with each yᵢ either a real symbol or ε. For input 11, one accepting path can be labeled 1,ε,1. Concatenating those labels still gives 11: the ε contributes zero characters. The state sequence has a step for every move, so m need not equal the number of input characters.

The condition rᵢ₊₁∈δ(rᵢ,yᵢ₊₁) says the chosen next state must be one of the legal options. A run chooses one option each time; the acceptance definition asks whether any suitable run exists.

NFA 3 — One DFA state can store the entire candidate set

Original chap1_NFA3.pdf · PDF pages 1–13 · Prerequisites

The whole idea

The NFA branches, but its set of states is finite. So we can ask a deterministic machine to keep a checklist: which NFA states are still possible after the input read so far? Every possible checklist gets one DFA state. That is subset construction. The braces label the contents of one memory record; they do not turn the new DFA into a branching machine.

Here's the mental switch: the DFA is the clerk holding the whole checklist, not one of the candidates on it. {q₁,q₂} is one clerk's current record. Reading a symbol deterministically produces the next record. That's why a circle with braces can still be one ordinary DFA state.

Build the update rule

Suppose the current checklist is R and the next input symbol is a. Look at every state r in R, follow its a-arrows, collect the destinations, then include every state reachable from those destinations by ε moves. That creates one uniquely determined next checklist.

The start checklist is E({q₀}), where E means ε-closure: include q₀ and all states reachable by zero or more ε-arrows. A checklist accepts when it contains at least one NFA accepting state. Nothing more complicated is hidden in the formula R∩F≠∅: intersection keeps members shared by R and F; “not empty” says at least one accepting possibility survives.

Trace the exact slide example

The three-state NFA on page 3 starts at q₁, which has an ε move to q₃; q₁ is accepting. Therefore the converted start is {q₁,q₃}, already accepting because ε has an accepting run at q₁.

Pages 10–11 give baa:

before input       {q₁,q₃}
after b            {q₂}
after ba           {q₂,q₃}
after baa          {q₁,q₂,q₃}

The final set contains q₁, so accept. To see one union explicitly, page 6 starts with {q₁,q₂} and reads a: q₁ contributes no destination; q₂ contributes q₂ and q₃. The result is {q₂,q₃}. ∅∪{q₂,q₃}={q₂,q₃}. An empty contribution doesn't create an extra candidate.

What the empty DFA state means

If the checklist becomes ∅, every NFA candidate has died. Another symbol cannot restart a nonexistent run. Thus ∅→∅ on every symbol in the DFA. This is a real state whose remembered fact is “no candidates remain.” In the old NFA, a missing arrow meant a branch died. Same behavior, different representation.

With three original states there are eight possible subsets. The textbook construction includes all of them; some are unreachable from the start. Here any subset containing q₁ but omitting q₃ is unreachable because closure would immediately include q₃. Remove unreachable states only after satisfying any exam requirement to display the complete prescribed construction.

Why the proof works for every input

At zero symbols, closure records exactly the possible starts. Assume the checklist is exact after a prefix. Every legal next run must consume the next symbol from one of those states, followed by any ε moves; the update lists exactly those possibilities. No legal run is omitted and no impossible run is invented. Induction gives the exact checklist after every prefix. The final “contains an accepting state” test then agrees with NFA acceptance.

In the formula δ′(R,a)=⋃ᵣ∈ᴿ E(δ(r,a)), the prime marks the new transition function and ⋃ means collect the members from all the listed sets. It is the table procedure written compactly.

The whole idea

Union, concatenation and star are instructions about whole accepted pieces. We want machine wiring that respects those instructions. ε-arrows let us hand control from one component to another without secretly adding an extra character. That is their job here. They are not decorative buffers.

Derive the three constructions

For union, the complete input may belong to either language. Add a fresh start with ε-arrows to both old starts. Preserve both components' accepting states. One successful component is enough.

For concatenation, the input must be a valid first piece followed by a valid second piece. Add ε-arrows from each first-component accept to the second start. Keep only second-component accepts as final accepts. A candidate may guess a boundary at any successful first-piece endpoint; another candidate may keep reading in the first component. A successful run must eventually finish both obligations.

For star, the input is zero or more complete pieces from one language. Add a fresh accepting start to handle zero pieces, with an ε-arrow into the old start. From old accepting states, add ε-arrows back to the old start so another piece may begin. Keep the old accepting states accepting too: you may finish after a complete positive number of pieces.

Follow one stable example

Use A={01} throughout this example. Its NFA has S→T on 0 and T→U on 1, with S starting and U accepting. Other symbol moves are absent. For A*, add accepting start Z, Z→S on ε, and U→S on ε.

The input 0101 has a successful run:

Z --ε--> S --0--> T --1--> U --ε--> S --0--> T --1--> U

All four symbols are consumed and U accepts. The empty string accepts at Z. Input 001 fails: after its first zero the candidate is at T, which has no zero move. “Repeat pieces” does not mean you may repeat arbitrary fragments of a piece. 001 cannot be cut into complete 01 blocks.

Why the extra start matters

The slides' pages 13–14 warn against simply making the old start accepting. A different original machine might return to its start after a nonempty string that it previously rejected. Changing that state's status would newly accept the string, even if it is not a concatenation of valid old pieces.

Here is a separate counterexample, with its changed target stated explicitly: an NFA for 01 has old start S looping on 0, then S→T on 1, with T accepting. Making S accepting would accept 0. But (01)* contains no nonempty all-zero string, since every nonempty piece ends in 1. A fresh accepting start avoids that bug. It provides exactly the zero-piece option without changing the meaning of visits to old S.

Read the case definition as “whose state is this?”

The piecewise δ table preserves an old state's old moves except at the handoff points. Set union adds the new ε destination without deleting existing ε destinations. The fresh start has no ordinary input moves; its ε moves enter components. Q is the combined state set; F separately specifies where a completed input may accept. Rename overlapping component state labels first so they really are distinct states.

A correctness argument cuts an accepting run at the handoffs to recover valid pieces. In reverse, join accepting runs for valid pieces using those handoffs. That's why the construction recognizes exactly the combined language.

The mental model: each arrow is a summary of hidden paths

At the beginning, most labels are single symbols. After states are removed, an arrow summarizes all the ways to travel between its endpoints through the already-removed states. That sentence is the invariant: the fact we maintain after every step. It is what makes the final expression trustworthy.

A regular expression on an arrow describes a set of strings, not one action like a DFA's single-symbol move. Traversing an ε-labeled arrow consumes nothing; an ∅ label permits no traversal. A run can split its input into chunks matching its arrow labels.

First put the graph in the required shape

Add a fresh start s with an ε arrow to the old start. Add a fresh sole accept f; put ε arrows from each old accepting state to f. Old accepting states become ordinary states. Now no arrow needs to enter s, and no arrow needs to leave f. The fresh endpoints prevent us from accidentally deleting the boundary of an accepting computation.

If two arrows share endpoints, combine labels by union. Fill missing permitted connections with ∅. This gives a label for every ordered pair whose source is not f and whose destination is not s.

The formal line

δ:(Q−{f})×(Q−{s})→R\delta:(Q-\{f\})\times(Q-\{s\})\to\mathcal Rδ:(Q−{f})×(Q−{s})→R

says: choose a source state other than f and a destination other than s; receive a regular expression. Here Q is the state set; − removes the named element; × forms ordered pairs; R\mathcal RR means the collection of regular expressions. Unlike a DFA transition table, the second input to this δ is a destination state, not an alphabet symbol.

DFA and NFA use the same preparation

A DFA already has single-symbol labels. An NFA may have parallel arrows and ε arrows. Both can be put into the GNFA shape directly. NFA→GNFA does not require subset construction first: the GNFA still allows alternative paths. Subset construction solves a different job—making a deterministic one-symbol-at-a-time machine.

For example, if an NFA has both 0 and ε arrows from p to q, the GNFA label is 0 ∪ ε. It means either consume one zero or consume nothing on that connection. It does not mean consume both.

Why one elimination is valid

Remove k. Any old path between surviving states can be split at its encounters with surviving states. A segment through k consists of entry, zero or more k-loops, and exit. The replacement expression records exactly those segments. Conversely, any string chosen from a replacement label can be expanded back into an old path. Both directions matter: preserving old paths alone would still permit accidentally adding new ones.

Each step removes one state. Since the graph began finite, eventually just s and f remain. Their edge describes exactly the original accepting paths. That proves termination and correctness for different reasons: fewer states gives termination; preserved path language gives correctness.

Original chap1_pumpinglemma1.pdf · PDF pages 1–9 · Midterm 2 preparation

The question: when is a finite number of states not enough?

A DFA can remember parity with two states. Could it remember the exact number of leading zeros so it can demand that many ones afterward? For {0n1n:n≥0}\{0^n1^n:n\ge0\}{0n1n:n≥0}, the number may be arbitrarily large. “It needs to count” is a useful suspicion, but not yet a proof: plenty of counting tasks only need a remainder. We need a consequence that every DFA must obey.

Suppose a DFA has p states. Read p symbols. The computation has visited p+1 state positions: the initial state plus one after each symbol. With only p different states, some state was visited twice. That's the pigeonhole principle: more visits than available distinct places forces a repeat.

A repeat turns a path into a reusable loop

Split the input into three consecutive pieces. x gets us to the repeated state the first time. y takes us around the loop back to that same state. z finishes the original accepting journey.

Because the state after y is exactly the state before y, the rest of the machine cannot tell whether we took that loop zero times, once, twice, or a hundred times. Following z afterward still reaches accept. The DFA has no secret memory outside its current state. That's the whole damn mechanism.

The notation xyizxy^izxyiz means x, then i copies of y, then z. With i=0, y disappears; with i=1, it is the original string; with i=2, y is duplicated. We are editing a substring, not moving letters around.

Decode the theorem in its actual order

If L is regular, there exists a pumping length p such that every s in L with length at least p can be split as s=xyz satisfying:

  1. ∣y∣>0|y|>0∣y∣>0: the loop consumes at least one symbol.
  2. ∣xy∣≤p|xy|\le p∣xy∣≤p: the loop fits within the first p symbols.
  3. xyiz∈Lxy^iz\in Lxyiz∈L for every integer i≥0: every repetition count still works.

∣y∣|y|∣y∣ is the number of symbols in y. ∈\in∈ means “is a member of.” The theorem promises at least one suitable split, not every split. p belongs to the assumed machine; we don't get to declare p=3 because that makes an example convenient.

Why this helps prove impossibility

To show a language is not regular, assume a DFA exists and receive its unknown p. Choose a legal long string. Then show that no allowed split can keep all repetitions in the language. That contradicts the required loop property.

Be careful with the deck's counting examples. Equal numbers of 0 and 1 is not the same requirement as equal numbers of adjacent 01 and 10. The latter can be tracked using boundary information: in a binary string, changes from 0 to 1 and back alternate. Similar-looking counts can need radically different memory.

Why the hell are we rewriting the grammar?

A rule can currently do several things at once: print terminals, create three pending jobs, hand off to one other variable, or produce nothing. That flexibility is convenient for writing a grammar, but awkward for algorithms that must reason about every derivation.

Chomsky normal form, CNF, limits a rule to one of two ordinary shapes:

A→BCorA→a.A\to BC\qquad\text{or}\qquad A\to a.A→BCorA→a.

The first splits one pending job into two pending jobs. The second finishes one job by printing one terminal. Capital letters here stand for variables, lowercase a for a terminal. They are shape examples, not the only letters allowed.

If ε belongs to the language, the new start may also have a rule to ε; that start must not appear on a right-hand side. CNF is a format for a grammar. It does not mean the language becomes regular, deterministic, or unambiguous.

Picture a job ticket. “Print a” completes it. “Do B, then C” tears it into two ordered subtickets. A variable is the ticket's label, not output printed on the page. This analogy maps only the pending-work structure: it does not introduce a real worker, time cost, or a rule that jobs must take equal time. CNF makes every ticket use one of those two shapes.

First understand what “can disappear” means

Use the slide grammar:

Nullable does not mean “delete this variable everywhere.” B can also produce b. Removing that possibility would mutilate the language. Nullable means we must preserve both choices: it may contribute something, or contribute nothing.

The mental model: change the wiring, keep the possible outputs

Every conversion stage should answer the same question: “How can I reconstruct an old derivation from this new one, and a new derivation from an old one?” If you only check that the final grammar looks like CNF, you can still have the wrong language. Format and equivalence are separate obligations.

We need an order because one repair can create the next kind of unwanted rule. Removing ε rules can create unit rules, so doing unit removal first would leave new handoffs behind.

Step 1: protect the start and find all nullable variables

Create S₀→S, with fresh S₀ appearing on no right-hand side. If the original grammar can generate ε, only this protected start will keep that ability in the final CNF.

Find nullable variables by repeated marking. First mark variables with a direct ε rule. Then mark A whenever it has a rule whose entire right-hand side consists of already-nullable variables. A terminal blocks this: a printed a cannot disappear. Repeat until a full pass adds nothing. This is a fixed point: further application changes nothing.

Why repeat? In A→B, B→C, C→ε, A is nullable indirectly. One left-to-right scan could miss it depending on rule order. With finitely many variables, each productive pass adds a mark and the process eventually stops.

Step 2: replace disappearing subtrees with explicit choices

For each rule, choose independently which nullable occurrences to omit. Keep the original rule too. For X→ABA with A nullable and B not nullable, the possibilities are ABA, AB, BA, B. The two As share a variable name but represent separate positions in a derivation.

Do not retain an ordinary empty right-hand side after this stage. Preserve S₀→ε exactly when the original start was nullable. Then remove the original ε rules from other variables.

Cycles need no special magic. With S→B|ε and B→S|ε, both variables are nullable; the language is just {ε}. The protected start may generate ε, but there is no terminal-producing work to invent. A conversion that manufactures a from this grammar is obviously wrong.

Here's the bit that makes the omission rule click. In an old derivation, a nullable variable might spend five steps becoming ε. In the new grammar, its parent can choose an alternative that leaves that position out immediately. Same finished word; fewer internal moves. We preserve the possible output, not the exact history of how it got printed.

Step 3: follow unit reachability, then copy real work

A unit rule has exactly one variable on its right, such as A→B. For each A, find every B reachable by zero or more unit rules. Copy every nonunit B-production onto A. Then remove unit rules.

Example: A→B, B→C, C→a|DE. A needs A→a|DE, and B needs B→a|DE. C keeps its original alternatives. The slides' CNF2 page 3 wording about removing B→u should not be read as deleting the nonunit production being copied; doing that can destroy valid outputs. Retain the useful nonunit rules.

A rule X→a is already valid. Do not replace it by X→U unless you also remove the new unit rule afterward. The goal is standard shape, not maximum helper count.

Check every right-hand side's shape; ensure only the protected start may produce ε; ensure that start never occurs on a right-hand side; inspect repeated nullable positions; inspect unit chains and cycles; compare a few boundary strings to catch errors. Original chap2_PDA5.pdf · PDF pages 1–11 · Midterm 2 preparation

The hidden issue: accepting state does not mean the stack is empty

Our general PDA accepts when a run consumes all input and finishes in an accepting state. It may still have stack contents. But the PDA→CFG construction summarizes balanced empty-to-empty runs. We therefore need an equivalent PDA that finishes with an empty stack at one designated accepting state.

This is a change of representation, not permission to change which strings accept. A cleanup gadget is correct only if it cannot help the original machine do extra input processing that used to be impossible.

Why “just add pop loops” is broken

Suppose an old accepting state has stack ba$, top first, and a future input transition needs to pop a. In the original machine that transition is blocked by the top b. If we add arbitrary ε-pop loops directly to this state, it can discard b, expose a, and resume the original transition. We have handed the machine a new way to process unread input. Shit—that changes behavior before completion, not just afterward.

The deck illustrates precisely this danger: cleanup mixed into the old control can accept a string the original PDA rejects. A final-state label is not a magical barrier against later transitions.

The safe gadget is a one-way exit

Add a fresh bottom marker under the original stack contents. Add a fresh drain state. From each old accepting state, allow an ε handoff into this drain. There, pop original stack symbols using ε transitions. When the fresh bottom marker appears, pop it and enter the sole new accepting state.

There is no way back to the old machine and no input-consuming transition in the drain. If a branch guesses completion too early, unread input remains forever, so it cannot accept. If an old accepting run has actually consumed the whole input, it can safely drain and finish. Those two observations establish the language-preserving role of the gadget.

The marker must be fresh: an old computation must not confuse it with one of its legitimate stack symbols. It marks the baseline that the old machine cannot cross.

Normalize individual transitions too

The grammar construction wants each transition to perform exactly one push or one pop. For a transition that both pops b and pushes c, use a fresh intermediate state: first perform the pop (and any input consumption), then perform an ε push of c. The intermediate state has only the intended continuation, so no other old transition can interrupt the halfway state.

For a transition that changes state but neither pushes nor pops, insert a push of a fresh temporary symbol followed by its pop. This creates a balanced two-step version of the same action. Consume the input only once across the two steps.

Fresh states and symbols are not decoration. Reusing an old state could create extra exits; reusing a marker carelessly could allow a wrong pop to match.

How this closes the CFG/PDA connection

CFG→PDA stores pending derivation work. Normalized PDA→CFG summarizes balanced runs. Together they show that context-free languages are exactly the languages recognized by PDAs. A DFA can be simulated by a PDA that ignores its stack, so every regular language is context-free. The reverse inclusion fails: the stack can handle 0n1n0^n1^n0n1n, which the pumping argument ruled out for DFAs.

Keep: cleanup must be an irreversible commitment to stop reading. Normalize safely, then apply the balanced-run grammar recipe.

One table cell isn't the whole decision

For a DFA, the current state and next input symbol select exactly one move. For a PDA, a move may read input or ε, and may pop the top or ε. Several differently labeled transitions can therefore be enabled at the same situation. Determinism must rule out those competing actions, not merely forbid two answers in one cell.

Suppose the machine is in q, the next input is 0, and the stack top is X. It could potentially use any of these:

Transition lookup What it would do
δ(q,0,X) read the zero and pop X
δ(q,0,ε) read the zero without popping
δ(q,ε,X) pop X without reading
δ(q,ε,ε) move without reading or popping

If two are available, the machine has a choice right now. Different labels do not make that choice disappear.

Read the course definition precisely

This course's DPDA definition requires exactly one of those four entries to be nonempty, for every state q, input symbol a, and stack symbol x. Each nonempty entry returns one pair (next state, symbol to push) rather than a set of alternative pairs.

Some treatments use “at most one” and permit partial transitions. For these slides and exam questions, use the stated exactly-one convention. The next deck completes missing cases with rejecting behavior.

An entry equal to ∅ means there is no transition. A pair such as (r,ε) is an actual transition to r that pushes nothing. Those are very different: no action versus a legal action with no push.

Work one collision

Suppose δ(q,0,ε)=(r,X): read 0, push X. Also suppose δ(q,ε,X)=(s,ε): pop X without reading. When the next input is 0 and the current top is X, both can run. One consumes input and increases the stack; the other consumes nothing and decreases it. Each individual entry has one output, but the machine is nondeterministic.

To repair the design, the state must distinguish the phases in which those actions are allowed, or one of the conflicting moves must be removed while preserving the intended language. Writing the arrows farther apart on the page doesn't fix the collision.

Deterministic does not mean “will accept or reject quickly”

An ε cycle may keep running without consuming the next input symbol. A configuration may become stuck when the input or stack is empty and its required action is unavailable. The four-way condition is stated over actual alphabet symbols; ε is the no-consumption option, not a real member of the input alphabet.

Acceptance is still about a computation that has consumed the whole input and is in an accepting state. Visiting an accepting state while unread input remains isn't enough. This is unlike a Turing machine's accepting halt state, which will be introduced later.

The broader connection

Nondeterminism adds no language-recognition power to DFAs versus NFAs, but deterministic PDAs are more restricted than general PDAs. A stack does not make every midpoint guess deterministic. The absence of a visible separator can matter because the machine may not know when to stop pushing and start popping.

Turing machines: a finite program with a rewritable workspace

Original chap3_TM1.pdf · PDF pages 1–8 · Midterm 2 preparation

What changes when the stack isn't enough?

A PDA can only inspect the top of its stack. A Turing machine, or TM, has a tape and a head that moves left or right. It can read a cell, overwrite it, move, and come back later. The finite state still stores the current phase of the program; the tape stores the growing work.

The tape has no fixed upper bound on usable cells. That does not mean infinitely many cells are processed in one move. At every finite point in a computation, only finitely much work has happened. “Unbounded workspace” and “infinite work for free” are completely different claims.

One transition does three specific things

δ(q,a)=(r,b,R)\delta(q,a)=(r,b,R)δ(q,a)=(r,b,R) means: in state q reading tape symbol a, write b in this cell, move the head one cell right, and enter r. With L, move left instead. At the tape's left boundary, the course model keeps the head there when it attempts to move farther left.

A blank is an actual tape symbol. ε is a zero-length string or no-consumption notation in other models. A blank cell is not “no cell,” and writing a blank is a real write operation. Tape symbols may include marks such as x that never appear in the original input alphabet.

Build the slide's matching idea: w#w

The separator # tells us where the first copy ends. On input 01#01, mark the first unprocessed left symbol, remember whether it was 0 or 1 in the finite control, cross the separator, and compare it with the first unprocessed right symbol. Mark that symbol too. Return to the left portion and repeat.

After the first round, marks stand where the two zeros were. After the second, both ones are marked too. Finally verify that no extra unmatched symbol remains on the right. Accept only then.

For 01#00, the second comparison fails. For 01#010, the first two comparisons succeed but the final leftover check fails. For malformed input with a missing or extra separator, the machine must reject through its format checks. Matching the examples isn't enough; each clause of the language needs a reason in the program.

What belongs in the seven-part definition?

(Q,Σ,Γ,δ,q0,qaccept,qreject)(Q,\Sigma,\Gamma,\delta,q_0,q_{accept},q_{reject})(Q,Σ,Γ,δ,q0​,qaccept​,qreject​): states; input alphabet; tape alphabet; transition rule; start; accepting halt state; rejecting halt state. Γ includes the blank and all input symbols. Σ excludes the blank. The accepting and rejecting states are distinct and halt immediately when entered.

This differs from a finite automaton or PDA: visiting their accepting state does not necessarily end the run, and acceptance is evaluated after the input is consumed. A TM's program must arrange its checks before entering accept.

The proof has two separate jobs

Correctness says successful comparisons and the final leftover check establish exactly two equal blocks. Halting says the procedure finishes: each round marks another left input symbol; each sweep crosses a finite occupied region; there are only finitely many unmarked left symbols. A convincing trace of 01#01 proves neither claim for every input, but it makes the invariant visible.

Repeated halving: encode a numerical test as marking passes

Original chap3_TM2.pdf · PDF pages 1–8 · Midterm 2 preparation

Read the language before reading the arrows

The deck's language is {02n:n≥0}\{0^{2^n}:n\ge0\}{02n:n≥0}. The number of zeros must be a power of two: 1, 2, 4, 8, 16, … . This is not 02n0^{2n}02n, which describes even lengths. 000000 has even length six, but six is not a power of two. ε has length zero and is also excluded.

The numerical idea is simple: one is a power of two; a larger odd count isn't; a larger even count is a power of two exactly when its half is. So repeatedly halve an even count until either one remains or an odd count greater than one appears.

The tape is doing the counting for us. The finite controller only needs to remember “keep this one” versus “cross this one out.” So the trick isn't stuffing the number eight or eight billion into a state label; it's leaving the work distributed across the tape and shrinking it by a rule we can justify.

How a tape implements “halve the count”

Scan the live zeros and mark every other one. States alternate between “keep the next live zero” and “cross out the next live zero.” Marks are ignored on later passes; they are old work, not new zeros. The head returns to the left boundary to start another pass.

The state alternation records parity during one sweep. It does not store the whole count. The surviving unmarked cells carry the reduced count between sweeps. This is a recurring theme: use finite control for a small phase distinction, external memory for an unbounded amount.

Follow numbers first, then align with the actual diagram

For eight zeros, the conceptual counts go 8→4→2→1, so accept. For six, they go 6→3, so reject on the odd count greater than one. For one zero, accept without demanding an even count. That last exception matters: “reject all odd counts” would reject the successful stopping condition too.

The slide machine has a representation detail: it erases the first zero to make a left marker and treats that reserved contribution as part of the represented count. Consequently, the remaining visible live zeros represent the current count minus one. Don't stare at a row with three visible live zeros and conclude the represented count must be three; it may represent four under this convention.

In the diagram, q₂ begins a pass by marking the first remaining live zero, q₃ and q₄ alternate through subsequent live zeros, and q₅ returns left. The one-zero case is detected when the reserved initial zero has no remaining live partner. The conceptual halving test and the diagram are the same algorithm with different bookkeeping.

Here is the physical bookkeeping for input 0000, at successive pass boundaries:

Tape's used portion Live zeros after the left marker Represented count
⊔000 after initialization 3 4
⊔x0x after one halving pass 1 2
⊔xxx after the next pass 0 1

⊔ is the blank used as the left marker, and x means crossed out. On the final scan q₂ finds no remaining live zero and reaches accept. This table is the bridge between the arithmetic 4→2→1 and the marks actually visible in the slide trace.

Why rejection and halting follow

If an odd represented count greater than one appears, repeated exact division by two cannot lead to one without a fractional step. Reject. If an even represented count appears, halving preserves the property of being a power of two. Every successful nonfinal round strictly decreases a positive integer count, so it cannot continue forever. Each tape pass itself traverses only a finite used region.

That is the proof skeleton: a property preserved by a transformation, a failed condition causing rejection, and a decreasing measure causing termination. These are reusable tools, not facts unique to this TM.

How to read a dense transition diagram

Annotate each state with its phase before tracing. Record state, head position, and full changed tape—not just the input symbols consumed, because this machine revisits cells. When a trace seems to contradict the high-level plan, check the encoding convention before changing the mathematics.

A state name alone no longer describes the situation

For a DFA with fixed input position, the state was enough memory. For a TM, two visits to q can have different tape contents and head positions. A configuration must record all three: control state, tape, and head location. Otherwise a trace can silently lose the information that determines the next move.

The notation uqvu q vuqv writes the tape prefix u to the left of the head, inserts state q at the head position, and writes the scanned symbol as the first symbol of v. q is not a tape symbol; it is an annotation in the snapshot.

Decode one transition completely

Suppose a configuration is a q bc: the tape contains abc, the head reads b, and the state is q. If δ(q,b)=(r,x,R), the new configuration is ax r c. The b was overwritten by x; the head moved to c; the state became r.

If instead δ(q,b)=(r,x,L), the result is r axc: the head now reads the a to the left. The entire tape is still axc; only the placement of the state annotation differs. At the left boundary there is no earlier cell to move into, so that case follows the boundary rule separately.

This is why copying only the state sequence is not a full TM trace. You need the tape edits and head movement too.

Three possible outcomes, not two

A TM may accept, reject, or keep running forever. A recognizer for L must accept every member and must never accept a nonmember. On a nonmember it may reject or loop. A decider must halt on every input, accepting members and rejecting nonmembers.

Every decider is a recognizer. Calling a recognizer “an algorithm that answers yes or no” overstates its guarantee: on some no-instances it may never answer. You cannot turn it into a decider by getting impatient after a million steps; a genuine accepting run might take a million and one.

Read the deck's constructions as phase programs

The w#w machine alternates marking, crossing, comparing, and returning. Its return states need different jobs on the two sides of #; reaching a marked symbol on the right is not the same as reaching the last processed symbol on the left. State meanings explain why several apparently similar left-moving states exist.

The slide language is aibjcka^ib^jc^kaibjck with ij=k and i,j,k≥1: all three blocks must be nonempty. Check that format first, then use repeated matching: for each a, traverse the b-block and account for j c-symbols. Restore temporary b-marks before the next a, while keeping track of c-symbols already spent. The a-count controls the number of repetitions, and the b-count controls each repetition's cost. A final check rejects unused or insufficient c's. The slide's positivity condition rejects zero-size blocks at the format check. A variation allowing zero would need different boundary handling; don't silently change the supplied language.

Reuse the comparison routine on a whole list

Pages 13–14 ask that the binary blocks in #x₁#x₂…#xₗ all differ. Compare every pair, not only neighbors. For #0#1#0, the first and second differ, and the second and third differ, but the first and third are equal. Mark the two selected separators, copy or compare their blocks using the earlier matching routine, then advance to the next pair. With l blocks there are l(l−1)/2 pairs, so a systematic finite pair schedule terminates. The subscripts identify positions in the list, not bits inside one block.

A high-level solution still owes a proof

For any construction, state the invariant tying the marks to completed work. Then show why acceptance implies the required relation and why a valid input can complete the procedure. Finally show termination using finite scans and a finite number of progressing rounds. “It keeps trying until it works” is not a halting argument.

Multiple tapes: give each part of the job its own workspace

Original chap3_multitapeTM1.pdf · PDF pages 1–9 · Midterm 2 preparation

The mental model: several work surfaces, one finite controller

A multitape TM has several tapes, each with its own head. It can keep the input on one tape and scratch work on another. This can make a program much easier to describe. It does not mean separate independent machines are voting on an answer: one control state selects a joint transition from the symbols currently under all heads.

For k tapes, a transition reads a k-tuple of symbols and returns a new state, k replacement symbols, and k movement choices. A tuple is ordered. The first entry belongs to tape 1, the second to tape 2, and so on. Swapping the entries can change the computation.

One step uses one shared snapshot

Suppose two heads currently read (0, blank). A transition may write (x,0) and move (R,R). Both decisions are based on the original pair. Do not write x on tape 1 and then use some half-updated situation to choose tape 2's action. The transition is one joint instruction.

A stay-put movement S is a convenient extension. It can be simulated in a left/right-only model using a right move followed by a left move, with an intermediate state preserving the required control information. The order matters at the left boundary: left then right would not restore the original position there.

The slide example: even positive unary input

The deck works with input 02n0^{2n}02n, n≥1, and constructs a machine that doubles it. This is an even-positive-length requirement, not the earlier powers-of-two language 02n0^{2^n}02n. 000000 meets the input pattern here even though its length is not a power of two.

The machine uses the second tape as stored work, a boundary marker to find the beginning again, and control states to check parity while returning across the stored copy after copying. Once this check verifies the required form, the stored copy can be used in producing the doubled output. For four input zeros, the required result is eight zeros. A correct trace must show where each head sits during copying, resetting, and extending the output, not just write “4 becomes 8.”

The useful separation is: tape contents store the actual block; a small state distinction tracks odd/even position; a marker gives a reliable return point. Each part solves a different bookkeeping problem.

What an exam trace should record

Write one row per joint step: current state, each tape's contents with its head marked, and the transition used. Preserve unchanged cells. A blank symbol in the read tuple is a condition on that tape's scanned cell; it isn't permission to ignore that tape.

When designing rather than tracing, first assign a purpose to each tape and each phase. Only then translate phases into transitions. Otherwise you end up memorizing a pile of arrows with no way to reconstruct them under exam pressure.

The next question is about power

Extra workspace organization might look like a stronger model. The next deck shows how one tape can encode all the tapes and head positions, then simulate their joint steps. That establishes equal computability. It does not promise equal running time; organizing work differently can save a lot of movement.

One tape simulates many: encode the whole situation, then update it

Original chap3_multitapeTM2.pdf · PDF pages 1–5 · Midterm 2 preparation

The job: replace convenient hardware with an encoding

A multitape machine has k tapes and k head positions. A single tape can store their finite used contents as separated blocks, for example #block₁#block₂#…#blockₖ#. Use a marked version of a symbol to indicate each simulated head's position. The delimiter and marked symbols are extra members of the simulator's finite tape alphabet.

The representation must retain both the data and the head locations. Merely joining the tape contents loses which cell each simulated head reads next. That's the same lesson as configurations: an encoding has to preserve everything needed to determine the next step.

Simulate one joint step in phases

First sweep across the encoded blocks and read each marked symbol. Remember the k-symbol tuple in the simulator's finite control. This is possible because k and the simulated tape alphabet are fixed for this machine, so there are only finitely many possible tuples.

Use the simulated transition function to determine the new state, writes, and movements. Make another sweep to update each marked cell and move the head marker to its neighbor. Different blocks may move their heads in different directions, but all updates come from the same old snapshot.

For example, if the simulated heads read (0,1) and the rule writes (x,0) with movements (R,L), the simulator must find those two marked cells, replace their contents, and move the two markers appropriately. It must not let the new x influence the choice of the second write.

What if a simulated tape needs more room?

If a head moves past its block's currently represented end, insert a blank cell into that block. Shift later encoded cells right to make space. A finite-control carry can move symbols one by one; this is tedious but implementable. The block remains a faithful representation of a tape with additional blank cells available.

The simulation is allowed to use many real steps for one simulated step. Computability asks whether the same answers can be produced at all, not whether the hardware has identical speed.

The invariant is the proof

At the beginning of each simulated step, the single-tape encoding represents exactly the multitape machine's complete configuration. Initialization establishes this. Reading the stored head tuple and applying the same transition preserves it. Therefore each finite accepting or rejecting computation is reproduced, and an endless simulated computation continues rather than being falsely turned into a halt.

Conversely, a multitape machine can ignore extra tapes and behave like a one-tape machine. The two simulations establish equal recognition and decision power.

Why this matters later

We can design algorithms using convenient multiple tapes, then know a standard TM can implement them. In complexity theory we revisit this exact construction and count its cost: scanning and shifting a growing representation can turn t simulated steps into roughly quadratic work. Same computability is compatible with different efficiency.

Nondeterministic TMs: a tree of possible complete computations

Original chap3_NTM1.pdf · PDF pages 1–7 · Midterm 2 preparation

What branches now?

An NTM can have several legal actions for the same state and scanned symbol. Each action creates a possible next configuration: state, tape contents, and head position. As choices accumulate, the computation forms a tree. Branches are alternative histories, not multiple heads sharing one mutable tape.

A string accepts if at least one branch reaches accept after finitely many steps. A rejecting branch alone doesn't settle the input. A branch that loops also doesn't accept. The whole existential claim is: is there a finite successful computation somewhere in the tree?

A pattern example makes the guessing concrete

To recognize strings containing aab, one branch can keep scanning while another guesses “the occurrence starts here.” The checking branch then demands a, a, b in sequence. A wrong guess fails locally; a correct occurrence supplies a successful branch. This is the NFA idea with TM configurations behind it.

The word “guess” is mathematical shorthand for allowing all permitted choices as branches. It is not a probability claim and not a promise that a real computer luckily picks the right one.

A more useful guess: a factorization witness

For unary compositeness, input 0ⁿ represents the integer n. Guess integers p and q with 2≤p,q≤n−1, then verify pq=n. For n=6, the branch choosing p=2,q=3 succeeds. Guesses such as 2 and 2 fail their multiplication check. For a prime input, no legal pair succeeds.

The range bound matters. If the machine generates arbitrarily long guesses with no stopping bound, some branches may guess forever. For an NTM decider, every branch must halt. Bounding the guesses and using terminating arithmetic checks gives that guarantee. Acceptance can be existential while termination is required branch by branch.

Why tracing just the states is especially wrong here

Two branches may reach the same control state with different guessed factors on tape. Their later verification differs. You cannot merge them merely because both circles are named q. An NFA's finite state-set method does not directly apply to TMs: tape configurations can be arbitrarily large and there can be infinitely many of them.

A trace tree should show enough of each configuration to distinguish the guesses or edits. When proving correctness, identify what an accepting branch certifies: here, two nontrivial integer factors whose product is exactly the input number.

The obvious simulation idea has a trap

A deterministic simulator might try the first branch to completion, then the second. But the first can loop forever while the second accepts in ten steps. Waiting for completion would miss an available yes-answer. We need a fair schedule that never lets one infinite branch hog all the attention. That's why the next deck uses breadth-first exploration.

Fair simulation: don't let one endless branch hide a short success

Original chap3_NTM2.pdf · PDF pages 1–9 · Midterm 2 preparation

The problem is scheduling, not lucky guessing

To simulate an NTM deterministically, we must eventually inspect every finite candidate computation. A depth-first strategy can get trapped following an infinite branch. Breadth-first search explores all branches to depth 0, then 1, then 2, and so on. A successful branch of depth d is eventually inspected because only finitely many nodes occur at each earlier depth.

The finite branching condition matters: the transition table supplies finitely many choices per step. Without it, “finish this level before the next” might itself require infinite work.

How the three-tape simulation organizes the work

One tape preserves the original input. Another simulates a candidate branch's working tape. A third records an address: a finite sequence of transition-choice numbers. If at most three choices are available, addresses begin 1,2,3,11,12,13,21,… in length order.

To inspect address 213, reset the work tape to the input, choose option 2 on the first step, option 1 on the second, and option 3 on the third. If a requested option doesn't exist, discard that candidate. If accept is reached along the replay, accept. Then move on to the next address. No single replay is allowed to run past the address's finite length.

These addresses describe choices, not tape cell positions. Replaying from the original input prevents edits from one branch contaminating another.

Why every accepting branch is eventually found

Suppose the NTM accepts in d steps along choices c₁…c_d. There are finitely many shorter addresses and finitely many addresses of length d before that one. Each replay takes finitely many steps. Eventually the simulator replays the successful sequence and accepts.

If the NTM never accepts, the simulator never invents acceptance: every replay uses actual legal transitions. It may search forever. That is acceptable when simulating a recognizer, whose no-instances need not halt.

What changes for a decider?

If every NTM branch halts on a fixed input, and branching is finite, the whole computation tree is finite. The reason is subtler than “each branch is finite, so there are finitely many branches.” If a finitely branching tree had nodes at arbitrarily large depths, one child of the root would have arbitrarily deep descendants; then one child of that child would too; continuing would construct an infinite branch. That contradicts the all-branches-halt assumption.

A breadth-first simulator can therefore maintain the live frontier and reject when no live configuration remains and none accepted. It must actually detect exhaustion; endlessly enumerating meaningless longer addresses without checking completion would not itself be a decider.

What the theorem does and doesn't establish

Deterministic and nondeterministic TMs recognize the same languages and decide the same languages. This is about eventual answerability. The deterministic search may explore exponentially many branches before finding a witness. The later complexity decks ask whether this cost can always be avoided efficiently—an entirely different question.

Keep: bounded-depth replay gives every finite branch a turn. Fairness preserves recognition; finite-tree exhaustion supplies rejection for deciders.

The obstacle: a grammar can keep expanding forever

Work the size argument rather than memorize 2n−1

A binary split increases the number of pending leaves by one: replace one variable by two. Starting from one variable, it takes n−1 splits to create n final positions. Each position then uses one terminal rule, contributing n more applications. Total: (n−1)+n.

For a three-symbol word, the tree uses two binary splits and three terminal productions: five applications. The shape can vary, and there may be many candidate trees, but none needs an arbitrarily long chain of unit or ε productions because CNF removed those ordinary rules.

The question: could every language have a program?

A language is a set of finite strings. A TM is a finite description. Even before constructing a specific impossible problem, we can compare how many descriptions and how many languages there are. If there are more languages than programs, some languages have no recognizing program at all.

“Both collections are infinite” does not settle the comparison. Infinite sets can have different cardinalities—different sizes in the sense of whether their elements can be paired one-to-one.

Countable means listable, not finite

A set is countably infinite when its elements can be listed as first, second, third, and so on without missing any. All finite strings over a finite alphabet can be listed by increasing length, and within each length in a fixed order. Every particular string eventually appears.

TM descriptions are some of those finite strings. We can enumerate candidate encodings and discard malformed ones. Thus there are only countably many TMs. Program length has no fixed maximum, but every individual program is finite.

A bijection pairs each element on one side with exactly one on the other, using every element of both. Equal cardinality does not mean the sets contain the same objects. Integers and finite machine encodings are not literally the same set.

Diagonalization shows that some collections cannot be listed

Suppose someone lists infinite binary sequences as rows. Build a new sequence whose nth bit differs from the nth bit of row n. It differs from row 1 in position 1, row 2 in position 2, and so on. Therefore it is absent from the supposedly complete list.

The construction defeats every row for a specific reason, not by vaguely saying “there must be another one.” In the real-number version, choosing safe decimal digits avoids the ambiguity of two decimal representations such as a trailing sequence of 9s. The logical engine is the same: disagreement on the diagonal.

Connect the counting argument to languages

List all finite input strings as s₁,s₂,s₃,… . A language determines an infinite membership sequence: bit i is 1 if sᵢ belongs, 0 otherwise. Conversely, each such sequence defines a language. Since these infinite sequences cannot all be listed, neither can all languages.

Countably many programs cannot cover uncountably many languages. Some languages are not even recognizable. This is an existence result; it does not yet tell us a particular familiar language with no algorithm.

ATMA_{TM}ATM​ consists of pairs ⟨M,w⟩ where M accepts w. HALTTMHALT_{TM}HALTTM​ asks whether M halts on w, either accepting or rejecting. These are different languages, although both are undecidable. If M rejects w, that is a no-instance of acceptance and a yes-instance of halting.

For sequential phases, add costs. If one is at most c₁g(n) after n₁ and another at most c₂g(n) after n₂, their sum is at most (c₁+c₂)g(n) after max(n₁,n₂). The maximum threshold ensures both bounds are valid at once.

For a nested loop, count how often the inner work runs and its cost each time. n passes each taking O(n) steps give O(n²). But check whether the pass length shrinks; mindlessly multiplying every visible loop by n can miss a stronger bound.

Input representation is part of the problem

An integer N written in binary takes about log₂N bits; unary 0ᴺ takes N symbols. An algorithm using N iterations is linear in unary length but exponential in the binary length. Saying “linear in the number” without specifying encoding can hide the entire difficulty.

“At most a constant multiple” versus “eventually a tiny fraction”

Big O allows comparable growth: 6n³ is O(n³). Little o is stronger. f(n)=o(g(n))f(n)=o(g(n))f(n)=o(g(n)) means that for every positive constant c, f(n)≤c g(n) eventually. The threshold may depend on c. When the ratio is defined appropriately, this is equivalent to f(n)/g(n)→0.

For √n versus n, the ratio is 1/√n, which tends to zero. Thus √n=o(n). For 6n³ versus n³, the ratio is always 6, so it is not little o. It cannot eventually fit below 0.01 times n³. The difference is the order of the quantifiers: some fixed multiplier versus every arbitrarily small multiplier.

Return to a familiar language and count actual work

To decide {0k1k:k≥0}\{0^k1^k:k\ge0\}{0k1k:k≥0} on a single tape, first check block order. A straightforward machine crosses off one zero and one one per round, repeatedly traveling across a region of length O(n). There are O(n) rounds, so the time is O(n²).

The reason isn't just “two loops.” It is the combination of how many obligations are discharged per round and how far the head travels to discharge them. Tape movement is part of the cost.

Why repeated halving can improve the bound

Instead of matching one pair at a time, compare the parity of the two remaining counts, then retain roughly half of each for another round. Equal counts have equal low-order binary bits; after removing that bit by halving, their quotients must still match. If parities differ in some round, reject. Boundary cases with no surviving symbols must be handled explicitly.

The number of rounds is O(log n), since each successful round roughly halves the live populations. But the old crossed-out cells still occupy physical tape positions. A pass may still travel across O(n) cells even when few live symbols remain. Therefore the time is O(n log n), not automatically O(n) from imagining the tape physically shrinks.

That distinction—logical population versus physical span—is exactly the kind of detail that separates a plausible story from a correct time analysis.

Multiple tapes can change the movement cost

With a second tape, copy the first block and compare it against the second in coordinated scans. Each relevant symbol needs only a constant amount of local work, so a linear-time method is possible on that model. This does not contradict the one-tape analysis: the storage layout and allowed head movements changed.

The language is the same, the yes/no condition is the same, and computability power is the same. The number of physical steps can differ. Complexity claims must name the model under which they are measured.

How to structure a time proof

Identify the input length n. Divide the algorithm into phases. For each phase, bound the number of repetitions and the cost per repetition, including resets and scans over marked cells. Sum the bounds, then simplify using Big O. If claiming little o, show the ratio or quantify over every positive multiplier; an ordinary upper bound is insufficient.

Simulation cost: equal computability can come with a quadratic bill

Revisit the one-tape encoding with a stopwatch

We already know one tape can represent k tapes using separated blocks and marked head positions. Now ask how much time that simulation takes. Suppose the multitape machine runs in t(n) steps on inputs of length n, with t(n)≥n and fixed k.

In t steps, each head can visit only O(t) cells, and the original input occupies at most t cells under the assumption. With a fixed number of tapes, the entire encoded configuration therefore has length O(t). This is a bound on how far the simulator may need to scan.

One simulated step is not one real step

The simulator must sweep to find the marked symbols, remember their tuple, apply the joint transition, move markers, and sometimes insert a blank cell by shifting later data. Each such phase costs O(t) on a representation of length O(t). A fixed number of phases still costs O(t).

There are at most t simulated steps. Multiply: O(t)×t=O(t2)O(t)\times t=O(t^2)O(t)×t=O(t2). Initialization is absorbed under t≥n. The constants may depend on the fixed simulated machine and number of tapes, not on the input length.

What the theorem actually promises

Every such multitape computation has a one-tape simulation with at most quadratic overhead under this construction. It does not say every one-tape algorithm for the same language must be quadratically slower. A different direct algorithm might do better. An upper-bound construction isn't a lower-bound impossibility proof.

For example, simulating a linear-time multitape method gives an O(n²) one-tape method. That demonstrates existence of a quadratic method; it does not establish that O(n²) is optimal.

Why polynomial time survives

If t(n)=nᵈ for a fixed constant d, squaring produces n^{2d}, still a polynomial. This is one reason polynomial time is a robust category across these standard deterministic tape models. A constant number of extra tapes may alter the exponent or practical speed without turning a polynomial computation into an exponential one under this simulation.

By contrast, nondeterministic simulation will involve a tree of alternative configurations, not merely one encoded configuration. The next deck counts how many branches must be explored. Different source of overhead, different bound.

Nondeterministic time: depth is cheap to define, the whole tree is costly to search

Original chap7_TMcomplexity2.pdf · PDF pages 1–6 · Later published material; cutoff unconfirmed

Name what “time” measures before counting

For a nondeterministic decider, time t(n) is the maximum number of steps along any branch on inputs of length n. It measures the longest branch, not the total number of nodes across the computation tree. Every branch must halt within that bound.

If each step has at most b choices, with b a constant determined by the machine, there can be roughly b^d paths of length d. A depth-t tree can therefore contain exponentially many candidates even though each individual branch is short.

See the difference on a small tree

With two choices per step and depth three, there can be eight length-three choice sequences: 111,112,121,122,211,212,221,222. Each branch takes three steps. A deterministic simulator that explores all choices may need to inspect all eight branches before concluding that none accepts.

Growing depth from three to thirty doesn't merely multiply the candidate count by ten. It can multiply it from 2³ to 2³⁰. That's the source of the exponential cost; no individual transition became expensive.

Derive the simulation bound

Enumerate candidate choice sequences up to length t, replay each for at most O(t) steps on a multitape simulator, and check whether any accepts. The number of candidates is bounded by a constant-base exponential in t. Multiplying by a polynomial factor such as t still gives 2O(t)2^{O(t)}2O(t).

If b=1 there is no branching and the search is much cheaper, but the exponential expression remains a valid general upper bound. Converting the resulting deterministic multitape simulation to one tape squares its running time. Squaring 2ct2^{ct}2ct gives 22ct2^{2ct}22ct, still 2O(t)2^{O(t)}2O(t). The constant in the exponent changes; the broad form does not.

What this says about power and efficiency

Nondeterministic and deterministic TMs decide the same languages because the finite tree can be searched. But the straightforward deterministic simulation may be exponentially slower than the longest nondeterministic branch. Whether every polynomial-time nondeterministic decision problem has some polynomial-time deterministic method is the P versus NP question—not settled by this expensive simulation.

An exponential simulation proves an upper bound that is sufficient for decidability. It does not prove that an exponential slowdown is unavoidable. Again: “our method costs this much” and “every possible method must cost this much” are different claims.

Connect this to a guessed solution

A nondeterministic branch can guess a short candidate and verify it. The branch length includes both guessing and checking. A deterministic exhaustive search may try every candidate. Later, the certificate definition of NP packages exactly this distinction: a supplied candidate can be easy to check even when finding one efficiently is not known.

Keep: nondeterministic time measures branch depth; deterministic search may pay for the whole tree. Do not silently substitute one quantity for the other.

P: algorithms whose work is polynomial in the encoded input length

Original chap7_Pexample.pdf · PDF pages 1–12 · Later published material; cutoff unconfirmed

The definition is a growth guarantee, not a compliment

P is the class of languages decided by deterministic TMs in polynomial time: for some fixed exponent k, running time is O(nᵏ), where n is input length. The machine must halt on every input and answer correctly. “Polynomial” does not mean instantly practical; n¹⁰⁰ is polynomial and can be absurdly large.

The value of the class is robustness: standard deterministic model changes have polynomial overhead, and useful efficient algorithms often fall inside it. It gives a precise mathematical boundary to investigate, not a guarantee about your laptop's response time.

PATH: search the graph without enumerating all paths

Given a directed graph G and vertices s,t, ask whether a path from s to t exists. Mark s. Repeatedly inspect outgoing edges from marked vertices and mark their destinations. Stop when t is marked or no new vertex can be marked.

On a graph s→u→t with an extra cycle u→s, marking still progresses safely: revisiting s doesn't create an endless search. A vertex needs to be newly marked only once. At most the number of vertices can be added, and each pass inspects finitely many encoded edges, giving a polynomial bound.

Correctness comes from two directions: each marked vertex has a path from s; every reachable vertex is eventually marked by following a path's edges. Termination comes from finitely many new marks. Enumerating every possible path would waste work on repetitions and cycles.

Euclid: use a preserved relation and a decreasing quantity

To compute gcd(a,b), repeatedly replace (a,b) by (b, a mod b) until b=0. The greatest common divisor stays the same because a divisor divides both a and b exactly when it divides both b and the remainder a−qb.

For 18 and 24: (18,24)→(24,18)→(18,6)→(6,0), so the gcd is 6. The remainder is smaller than the divisor, ensuring progress. More sharply, the relevant magnitude shrinks by at least a factor of two within a bounded number of iterations, giving logarithmically many rounds in the numerical magnitude.

The numbers are binary encoded. Their bit length is logarithmic in their value, so a rigorous polynomial-time claim also counts the bit cost of division/remainder operations. Treating arbitrary-size arithmetic as one free step would hide work.

A familiar language class returns

The deck states that every context-free language is in P. Earlier, CNF gave a finite exhaustive membership algorithm via 2n−1 derivation steps. That particular enumeration can be exponential; it established decidability, not the stronger polynomial result. Polynomial parsing uses shared subproblems instead of separately trying every tree.

This distinction is useful everywhere: a language may admit a slow algorithm and also a fast one. Complexity classes assert the existence of a suitably bounded algorithm, not that every algorithm for the problem is efficient.

NP: a yes-answer has a short certificate that can be checked quickly

Original chap7_NPexample1.pdf · PDF pages 1–10 · Later published material; cutoff unconfirmed

Start with checking, not with a mysterious acronym

Suppose someone hands you a proposed Hamiltonian path in a graph: an ordered list of vertices. You can check that it starts and ends where required, visits every vertex exactly once, and uses an actual graph edge between each adjacent pair. The list may have been hard to find, but checking a supplied list is a concrete finite job.

A certificate is that extra proposed evidence. A verifier is a deterministic algorithm that checks the original input together with the certificate. NP consists of decision languages where yes-instances have certificates of polynomially bounded length that can be verified in polynomial time.

For no-instances, every permitted certificate must fail. A verifier that accepts some bogus witness would certify the wrong language.

Think “show me the route and I'll check it.” The certificate supplies the route; the verifier checks the graph's actual edges and the once-per-vertex requirement. It doesn't trust the person who supplied it. A pretty-looking list gets no free pass. This is the concrete meaning of verification before the acronym starts sounding like wizard shit.

Work the HAMPATH certificate

For a graph with vertices {s,a,b,t}, a candidate [s,b,a,t] claims a path using all four exactly once. Check its endpoints, count and uniqueness of vertices, and edges s→b, b→a, a→t. If any edge is missing, reject this certificate. That does not by itself prove the graph has no Hamiltonian path; another ordering may work.

The certificate length grows with the graph encoding size. Trying all vertex orderings may take huge time, but the verifier processes one supplied ordering. Keep the quantifiers straight: some certificate for a yes-instance; no certificate for a no-instance.

NP does not mean “non-polynomial”

The name refers to nondeterministic polynomial time, which the next deck connects to certificates. Problems already in P are also in NP: a verifier can simply run the polynomial decider and ignore the certificate. Therefore membership in NP does not establish hardness or rule out an efficient deterministic algorithm.

The deck uses compositeness as a verification example. A nontrivial factor certifies that an integer is composite: check the factor bounds and divisibility. But compositeness is also in P, because primality has an unconditional deterministic polynomial-time algorithm. The Agrawal–Kayal–Saxena paper establishes that prime/composite decision result. Finding a full factorization is a different task; don't slide from one claim to the other.

What about certifying a no-answer?

A Hamiltonian path is a compact witness that a path exists. The absence of one particular candidate is not a witness that no candidate exists. The complement class coNP concerns languages whose no-answers, viewed as yes-answers to the complement, have polynomial certificates.

It is not established that NP and coNP differ. So say “we have this yes-certificate” rather than “there can never be a short no-certificate.” A lack of a known method is not an impossibility theorem.

Connect to earlier proof practice

An ambiguity witness gave one string and two derivations. A computation history gave a finite run. A counterexample refuted a universal claim. These are all evidence objects, but NP adds quantitative requirements: certificate length and verification time must be polynomial in the original input length.

Keep: NP is about polynomially checkable yes-evidence. It includes easy problems and does not itself mean NP-complete.

Verifiers and guessing machines: two descriptions of the same resource

Original chap7_NPexample2.pdf · PDF pages 1–8 · Later published material; cutoff unconfirmed

Turn a certificate verifier into a nondeterministic machine

If a language has polynomially bounded certificates and a polynomial-time verifier, an NTM can guess a certificate of the allowed length, then run the verifier. A yes-instance has at least one successful guessed certificate, so at least one branch accepts. A no-instance has none, so every branch rejects.

The guess must be bounded. “Guess any finite string” with no length limit could produce arbitrarily long or nonterminating branches, destroying the polynomial-time guarantee. Guessing itself consumes time; it isn't free magic.

Reverse the construction

If an NTM decides a language in polynomial time, an accepting branch has polynomially many steps. Record its transition choices as a certificate. A deterministic verifier follows those choices, checks that each is legal, and confirms an accepting halt within the bound.

Because the fixed machine has only finitely many choices per step, each choice needs only a constant number of bits. A polynomial number of choices gives a polynomial-size certificate. The verifier doesn't search all branches; the certificate identifies one candidate branch to check.

That proves the equivalence: polynomial nondeterministic time and polynomially verifiable certificates describe the same class NP.

SUBSET-SUM: make the witness concrete

The deck uses numbers such as {4,11,16,21,27} and a target. For target 25, selecting 4 and 21 works. A certificate can be a bit vector 10010, with one bit per listed entry: 1 means select that occurrence, 0 means skip it. Add the selected numbers and compare with the target.

The input is a list of entries; repeated equal values, if present, are distinct positions. You may use each occurrence at most once in ordinary SUBSET-SUM. A certificate that reuses one index repeatedly would be solving a different problem. Check certificate length, valid entries, and the sum.

Binary arithmetic takes time proportional to bit lengths, but summing at most the listed number of integers of bounded input size remains polynomial. Exhaustively trying every subset has 2ᵐ candidates for m entries. A fast verification procedure does not by itself provide a fast search over all candidates.

Where P versus NP actually stands

P asks for a deterministic polynomial-time decision algorithm. NP asks for polynomially checkable yes-certificates, equivalently polynomial-time nondeterministic decision. P⊆NP. Whether P=NP remains unresolved; the Clay Mathematics Institute lists P versus NP as unsolved (checked November 1, 2026).

NP-complete means a problem is in NP and every NP problem can be transformed into it by a polynomial-time reduction. It is a special kind of completeness, not a synonym for NP. If one NP-complete problem had a polynomial-time algorithm, all NP problems would. No known polynomial algorithm is not the same as a proof that none exists.

The course's final connection

We began by asking what a machine must remember. We moved to what it can compute at all, then what it can compute within a time budget. The same habits keep paying off: specify the object, preserve its meaning through a construction, prove both directions, and account for termination or cost separately.

Keep: bounded guesses are certificates; checking one branch differs from searching the whole tree; the major separation questions remain open.
